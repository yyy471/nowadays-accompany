## 1. 目标与范围

把现有 P0～P4 后端整理为可运行、可配置、可重复验收的源码原型。业务范围保持单角色、本机 CLI／HTTP API／SSE、完整事件记忆与 Agent 回复、本地 Skill／stdio MCP、自主活动和持久恢复。P0 独立小样仅作历史证据，当前运行入口为 backend。

P5 不提前实现远程 MCP、桌面 UI／安装包、浏览器／视频／电脑控制或 QQ。后续先按 DL-115 实施 Streamable HTTP MCP，再讨论桌面前端。没有实测的厂商、平台、安装环境及并发能力仍列为未验证。

## 3. 验收入口约定

统一命令只运行固定白名单中的离线脚本，不包含真实服务脚本，不读取用户历史提供的密钥。全部业务数据和临时文件位于 backend/test-results/ 下新建的独立目录，不复用用户运行目录，不删除旧验收记录。

按顺序执行工程类型检查、验收脚本类型检查、交付脚本回归、正式测试、真实进程／CLI 冒烟、P2 离线 20 项、P3 的 7＋2＋2 项、P4 的 8＋6＋14 项。每个步骤单独保存日志、退出码和验收报告，汇总检查用例数、唯一编号及通过字段，不只依赖进程退出码。

输出 summary.json、source-manifest.json、各步骤日志及业务报告。实际运行的 Node 版本、Git HEAD／工作树状态、锁文件与源码哈希参与证据归属；运行期间源码发生变化则不通过。本地报告属于 Git 忽略的运行产物，可通过统一入口重建，稳定结论与证据索引写入 194。
