# 账号模型配置与会话角色修订

日期：2026-10-22。状态：当前设计依据，尚未实施业务改造。覆盖 13/14 和旧图集中与本文件冲突的条目；历史架构文档不代表当前页面要求。

## 1. 本轮确认

- 删除“会话”页面，不提供历史聊天浏览和人工发送入口。
- 删除独立“任务与媒体”页面；用户已进一步确认只保留配置与测试，不将历史任务和媒体列表移到其他页面。后端异步任务、取消、归属与审计机制仍按业务需要保留。
- “账号策略”改为“模型配置”，按 QQ 账号配置对话、识图、视频识别、生图、语音生成五类能力。不再按群聊/私聊/具体会话配置模型。
- 全局服务在“应用设置 → 模型服务”中维护；账号模型配置页只快速选择服务及模型，并提供与能力相符的测试。
- 不设账号默认角色卡。每个群聊、私聊必须单独指定角色卡；允许多个会话显式选择同一张卡，但不自动继承。
- 展示主页的 QQ 名称、图像与签名不决定运行角色，不随会话角色切换而修改。

## 3. 全局服务与账号配置

全局模型服务定义包含：稳定 serviceId、显示名称、云端/本地、适配器、地址、凭据状态、模型列表、每个模型支持的能力、超时/并发等服务限制。允许同一服务提供多项能力，也允许五项能力分别选择不同服务。地址和密钥不在每个账号重复填写。

账号模型配置页顶部始终显示当前 QQ 账号。主体采用五行配置表，列为能力、启用状态、服务、模型、测试；右侧只放当前能力参数与可用原因。服务选择仅列支持该能力且当前账号获准使用的选项；无可用项提供“前往设置添加服务”。保存显式作用于当前账号。

| 能力 | 目标能力标识 | 测试与特殊参数 |
| --- | --- | --- |
| 对话 | chat | 测试文本、可配置输出长度等模型参数 |
| 识图 | image.understand | 上传一张测试图片，返回文字结果 |
| 视频识别 | video.understand | 上传测试视频，返回理解结果；不是视频生成 |
| 生图 | image.generate | 输入提示词、选择受支持尺寸，临时显示测试图片 |
| 语音生成 | audio.generate（待实现） | 输入文本、选择服务支持的音色/格式，临时播放测试音频 |

语音生成按文本转语音理解，不隐含语音识别、音色克隆或视频配音。不要把所有 OpenAI-compatible 服务都假设为支持生图或语音；测试必须走相应适配器能力。

每项能力可为“未配置 / 已禁用 / 已配置但不可用 / 就绪 / 测试中 / 测试失败”。缺少对话服务时不能启动自动对话；其余能力未配置时显示能力不可用，不影响纯文字聊天。测试是显式操作，不因选中或保存自动调用收费服务。测试只显示本次反馈与临时结果，不建立历史媒体浏览页；临时文件仍受后端清理规则约束。

全局服务修改需显示引用账号；移除被引用服务要阻止或先显式解除引用，不能静默替换。账号保存稳定 serviceId/modelId，不能保存下拉序号或服务显示名称。全局服务可共用连接池与凭据，但账号上下文、用量归属、会话、角色与输出不共用。

模型选择不设会话级覆盖；账号授权和云端媒体授权仍在服务端校验。既有会话级插件/Skill 可用性属于扩展策略，不等于模型服务覆盖，此轮不自动删除该能力。

## 4. 群聊与私聊分别绑定角色

“资料与角色”分为账号展示、会话角色两个标签。会话角色页提供群聊/私聊筛选、目标搜索、已绑定/未绑定筛选，行内显示目标名称、类型、群号/QQ号、所选角色卡、版本与绑定状态。详情区选择公用或账号私有角色卡，预览内容后保存。

绑定键为 accountId + kind(group/private) + peerId。accountId、kind、peerId 缺一不可：相同数字的群号与好友 QQ 号不共用配置，相同目标出现在两个 QQ 账号下也不共用配置。

同一张角色卡可被多条绑定显式引用；选择公用角色卡共享定义，不共享历史、记忆、情绪或会话运行状态。不提供“应用为账号默认角色”。批量设置如果后续增加，必须明确列出目标并为每个目标创建独立绑定，不能作为隐藏继承规则。

未绑定、角色卡缺失或版本不可解析时，保留消息接收与诊断，默认不触发自动 AI 回复、工具或付费生成。状态显示“未绑定角色卡”，不自动用第一个资源、账号旧角色卡或通用助手兜底；不向对方连续发送配置错误通知。首次目标如何发现需由会话目录/接收事件提供，允许手动按类型和ID添加，不能依赖已经删除的聊天页面。

一个群绑定一张角色卡，是该账号在该群对所有成员采用的身份；参与者 ID 保留在消息与上下文里。群内按成员设置不同人设不属于本轮。

切换角色只影响该绑定，其他群/私聊保持原状。新轮次按新的角色执行；已有运行中请求携带 bindingRevision，交付前校验。角色变化时取消/阻止旧角色结果自动交付，避免旧角色回话落在新绑定下。

会话上下文、未来长期记忆至少按 accountId + kind + peerId 隔离。建议再按 bindingId/contextEpoch 区分换角色前后的上下文；保留旧记录，不删除或自动混入新角色。世界书、情绪和遗忘曲线后续沿绑定的实际角色扩展，不只存一份账号级记忆。具体恢复旧角色上下文策略后续另定，此轮默认新角色开启新上下文。

## 5. 实际消息链路的目标调整

```text
用户手动注入并监听 QQ
→ 校验账号身份、构造 accountId + kind + peerId
→ 查询该目标的显式角色绑定
  → 无绑定：记录未配置，结束自动处理
  → 有绑定：解析指定角色卡与版本，建立会话上下文
→ 读取该账号的五类模型配置
→ 根据消息类型调用对话/识图/视频识别，按扩展与权限提供生图/语音工具
→ 保存任务内部状态；交付前复核账号、目标、绑定修订与授权
→ 通过原目标发送回复或媒体，记录脱敏诊断
```

不同会话可并行，同一会话的顺序与上下文继续受会话调度约束；账号模型并发上限和服务并发上限同时生效。删除页面不改变运行调度与数据隔离。

## 6. 当前实现的必要改造

本次只确认设计，不宣称以下能力已存在：

1. 当前 CapabilityId 枚举只有四项，需增加语音生成对应 schema、服务/模型声明、适配器方法、账号配置、校验、调用、输出媒体和测试链路；仅加一个下拉框不算完成。
2. 当前档案模型解析单个 roleCard，Agent 使用 profile.roleCard.content 构造上下文。需改为在每条消息所属会话上解析角色绑定，不能只改前端展示。
3. 增加会话角色绑定 CRUD、目标目录与实际生效状态，执行器和缓存携带完整绑定键及修订；具体端点待实现，不假定现有 profile API 已支持。
4. 账号模型配置需独立的账号级读取/写入与能力测试契约，五项配置原子校验并返回实际生效结果。复用现有 policy/providers 时明确边界，不通过会话覆盖暗中改模型。
5. 对现有会话级模型覆盖做迁移检查：列出受影响条目，由用户明确选择账号级结果；不静默沿用旧覆盖，确保所有会话最终使用同一账号配置。
6. 现有账号 roleCard 迁移为“可供选择的资源”，不自动视为所有群/私聊的默认卡。已有可确认目标的显式绑定可保留；没有绑定的目标标为待配置，不能迁移后悄悄继续自动回复。
7. 后端 job/media/audit 仍保留内部职责；界面移除历史浏览不等于删除文件、取消清理或失去账号归属。
8. TTS 能力与 QQ 发送语音能力分别验收：模型生成成功不等于 QQ 端支持语音消息。后端支持音频编码、时长与语音发送前，明确显示“已生成，当前渠道暂不支持语音交付”，不把文件发送冒充语音消息成功。
