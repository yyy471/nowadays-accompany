# 268 模型配置、首次启动与对话演出修复计划

范围包括设置、角色配置、角色初始活动状态和桌面对话。以下代码现状来自 `d63887f` 及当前工作区。修复与验收待执行。

实施进展：第 4 节（首次启动与角色初始状态）与外观导入预览不显示立绘的修复见 [269](269-268-progress-first-launch-import-preview.md)；第 1、2、3、5 节与第 6 节的核对见 [270](270-268-progress-dialogue-model-picker.md)。第 6 节的生图草稿探测与 MCP／Skill 探测仍待实施。

## 1. 优先排查对话差分

外观导入把 `standees` 登记为主页立绘，把 `expressions` 登记为差分。导入服务只创建衣柜记录和素材，角色穿着由 Agent 通过 `state_update` 提交。现在句段标注在正文落库后执行，服饰为空或对应服饰没有差分时直接跳过。舞台也要求句段有服饰标识才应用差分。因此已导入图片时仍有多条路径只显示立绘，实际会话需继续定位到具体一条。见 [外观服务](../backend/src/application/appearance-service.ts#L76)、[穿搭与回复](../backend/src/application/conversation-service.ts#L2456)、[句段标注](../backend/src/application/segment-annotation-service.ts)、[对话舞台](../desktop/desk-preview/renderer/src/conversation/ConversationStage.tsx#L81)。

1. 在临时数据根导入千叶的实际目录，用可控模型跑真实 HTTP、SSE 和桌面。核对角色状态的 `outfitId`、对应衣柜的差分、每个句段保存的服饰和立绘、标注调用和 `spriteAssetId`、素材请求状态及左侧实际显示的图。用 `02_classic`、`06_white_knit_barelegs` 验证两套有差分的服饰，再用只有主页立绘的 `01_white_knit_stockings` 验证缺图分支。
2. 核对首次穿搭和换装的提交时机。角色有衣柜时沿用 DL-136 的每日首次活动或对话选衣，确保本轮 Agent 提交的新穿着进入句段服饰快照和标注候选。若当前服饰为空或已失效，在既有穿搭流程中请 Agent 选择有效服饰。若 Agent 仍未提交、服饰没有差分或标注失败，文字照常展示。衣柜可提示「当前未选择服饰」或「这套服饰没有对话表情」，用于定位素材问题。
3. 核对并补齐标注写回、窗口快照和 SSE 合并。已经显示的句段收到对应标注后更新左侧，未展示句段的标注在推进到它时生效。晚到旧轮标注只更新相应记录。快照、终态句段、重连或历史分页均保留已收到的有效标注。标注继续按素材 ID 匹配，任意已登记的文件名都可成为候选。记录跳过、无匹配和失败的不同原因，便于区分衣柜、模型、事件与图片加载问题。
4. 对话舞台按正在展示的句段使用差分。同轮同服饰的无标注句段延续前一个有效表情。没有可用差分时使用该句段的立绘快照，实时演出缺快照时回退到当前服饰立绘、再回退到主题图。历史使用该轮保存的素材引用，读取失败时显示安全的缺图回退。纯背景过场只替换背景，整幅过场收起后恢复当前句段的角色图。

## 2. 设置页填写后即可读取列表和测试

新建模型服务表单目前只有保存。编辑表单按 `modelDirty` 禁用列表和测试，列表只交给 `datalist`。后端已有草稿 `POST /v1/model-services/models`、`POST /v1/model-services/test` 和按资源探测接口。见 [设置页](../desktop/desk-preview/renderer/src/pages/Settings.tsx#L500)、[模型路由](../backend/src/http/routes.ts#L840)、[模型服务](../backend/src/application/model-service.ts#L61)。

- 新建、编辑使用同一套模型名称控件与探测逻辑。填写有效的协议、服务地址及所需密钥后即可读取列表。选择或输入模型后即可发简短测试请求。列表读取与测试由按钮主动触发，保存独立执行。显示加载、成功、空列表、失败和重试。手填模型名称始终可用，读取失败保留当前值。
- 字段统一显示「选择或输入模型名称」。列表有内容时点击字段打开可筛选的下拉框，选项显示服务返回的模型名称，保留手填入口。请求仍发送服务识别的模型标识。设置页选择的名称用来测试，可作为再次打开供应商时的测试选项。角色绑定独立填写。
- 新建和使用新密钥时复用现有草稿路由。已保存服务的未修改配置走按资源接口。编辑时若保留已保存密钥又修改地址路径，需要服务端以资源为基准解析密钥，核对协议与 origin 一致后才复用。换协议、主机或端口时可用当前填入的新密钥，或按用户选择清除密钥后探测。沿用统一凭据解析，响应和日志只返回状态。草稿测试可显示本次结果，已保存服务的最近测试只接受对应配置的结果。
- 模型列表与测试结果按供应商、协议、完整地址、凭据版本隔离，测试结果还绑定模型名。表单更改或切换供应商后，迟到结果只归属原请求。候选列表可在同一供应商的设置页和角色页共享。草稿列表在对应配置实际保存后才可成为共享列表，重进应用可按供应商手动刷新。列表失败或缺少原有模型时允许继续手填，已经保存的角色选择仍可读。

## 3. 角色配置先选供应商，再选模型

后端绑定已经保存 `resourceId` 和 `modelName`，对话与记忆按各角色绑定解析。角色页目前只提供供应商下拉和模型 ID 输入，另有「新建模型服务」跳转并预填资源草稿。见 [角色绑定表单](../desktop/desk-preview/renderer/src/pages/Settings.tsx#L377)、[绑定解析](../backend/src/application/model-binding-resolver.ts#L180)。

- 对话模型和记忆整理模型共用模型名称选择控件。先选设置中已保存的供应商，再用该供应商列表选择模型，或手填。切换供应商时清空该项的待保存模型名和旧列表，重新载入当前供应商的候选。角色 A、角色 B 和设置页的测试都可以对同一供应商使用不同模型。
- 删除角色页的「新建模型服务」按钮和创建后预填草稿的逻辑。保留「在设置中查看模型」，添加供应商统一从设置进入。保存角色选择继续走角色绑定的 revision 校验。
- 未配置的对话模型显示「未选择」。记忆整理的空绑定显示「跟随对话模型」，按 DL-124 在运行时继承已绑定的对话模型。全局服务的创建、测试、列模型或选中目录项都与角色绑定写入独立。生图和语音依各自协议与资源结构展示。

## 4. 首次启动与角色初始状态

当前创建角色索引时没有初始化活动记录，`RoleActivityStore` 将无记录解释为 `active`。全局配置写入要求所有角色已停止，因此新数据根只要建立一个角色就可能挡住首轮配置。当前代码查到的模型资源创建只写全局资源，角色表单从绑定接口读已有选择。预置角色若显示已绑定，需要继续检查首启数据包、安装入口和配置页草稿，区分实际落库与仅显示了选中项。见 [角色索引](../backend/src/storage/app-store.ts#L152)、[角色活动存储](../backend/src/storage/role-activity-store.ts#L15)。

- 新数据根无预置角色时保持空列表，直接允许配置全局模型。预置角色和首次配置中新建的角色以 `stopped` 写入活动记录。建议把后续新建角色也统一设为 `stopped`，便于先配置再开始活动。覆盖 API、CLI、安装预置和初始化重试，确保停止状态在后端可查询。用户明确开始活动后才进入活动调度。
- 初始化角色的模型绑定为空。设置页创建供应商后角色仍为空，直到用户在角色配置中保存。验证预置的默认角色与其他角色走同一规则。
- 升级已有库保留现有活动和用户保存的绑定。若历史版本缺少活动行且按旧契约等同活动，按迁移前语义处理。把新建默认值落在创建边界，配置写入保护继续按 DL-148 在后端判断。

## 5. 对话等待动效与点击推进

当前底部 `dialogue-turn-controls` 负责等待文本和「下一句」按钮，页面已经能区分等待、可推进与本轮结束。保留会话状态机，改动交互入口。见 [对话面板](../desktop/desk-preview/renderer/src/conversation/ChatPane.tsx#L229)、[推进函数](../desktop/desk-preview/renderer/src/conversation/use-window-session.ts#L734)。

- 发送后在角色消息位置显示「正在组织回复…」和轻量点状动效。首句自动出现后移除首句等待提示。已展示到当前可用句段、服务仍在生成时，在消息区继续显示等待下一句。失败、中断、重连和切换窗口依实际会话状态更新提示，减少动效偏好下显示静态提示。
- 移除消息下方的等待与「下一句」整条控制栏。右侧消息区的正文、动作文字或空白处可点击推进，每次展示一段。使用语音、过场图、历史和翻页控件，或滚动、拖选文字时维持各自操作。可推进时提供键盘操作与可访问提示。翻看历史时保留阅读位置。
- 继续遵循 DL-141。首句自动出现，直到真正末句出现才自动恢复输入框。单句回复一出现即恢复。推进到动作时已播放的语音继续，直到播完或另一句实际开始播放。

## 7. 实施与验收顺序

先复现对话差分全链路并修正已定位断点。并行补齐模型草稿探测和初始活动状态，然后接通两个页面的模型选择与对话交互。最后用同一套首次配置流程联验。

| 场景 | 可核对结果 |
| --- | --- |
| 空数据目录启动，含预置和无预置两种 | 全局可配置。预置和新建角色显示已停止，模型绑定为空。显式启用后活动写入保护生效。已有库升级前后的活动与绑定可对照。 |
| 新建及编辑模型服务 | 保存前可列模型和测试。验证新密钥、同源保留、跨源换密钥、清除、空列表、失败、手填和迟到响应。通过服务桩记录实际接收的模型名与凭据来源。 |
| 一个供应商、两个角色 | 设置页测试模型 A，角色甲用 A、角色乙用 B，记忆整理可另选或继承。重启后配置各自正确，角色运行请求使用保存的绑定。 |
| 语音与生图测试 | 草稿测试接收当前值，切换角色或服务时旧结果不会串入。探测和测试可重复执行，保存时后端继续检查活动状态。 |
| 对话点击和等待 | 慢首句、有句间停顿、多句、单句、失败及中断分别验收。鼠标和键盘逐句推进，点击喇叭或历史控件不会推进，末句显示即恢复输入。 |
| 千叶外观 | 验证无穿着、只有立绘、两套有差分的服饰、换装、延迟标注、SSE 重连、历史回看、过场图和素材加载失败。分别核对数据库字段、SSE 和舞台显示。 |

后端运行类型检查和 `npm run accept:offline`。桌面运行测试、渲染端类型检查和构建，再用临时后端做桌面联调。千叶用真实素材验证，自动化中的模型、语音和生图服务使用本地替身，真实服务结果另记。实施与独立复核分别留证。
