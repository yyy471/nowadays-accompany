# 第一阶段优化方案：多实例隔离与模型能力底座

日期：2026-10-22

用途：开发分配与实现依据。本文根据已有讨论制定本阶段推荐决策；尚未实际实现的能力均为目标，不代表当前代码已有支持。若与 01、02 文档冲突，本阶段实施以本文及配套验收标准为准。

配套：`04-phase-1-acceptance.md`、`05-phase-1-work-packages.md`。

## 1. 阶段结论

需要局部结构调整，不需要推倒重写。保留 Core、Supervisor、RuntimeRegistry、OneBotChannel、账号存储、控制 API 和 Electron/React 桌面技术栈。

本阶段目标：一个桌面程序分别管理多个已有 QQ 运行时连接；账号、会话和扩展作用域明确隔离；建立独立的对话、图片理解、视频理解、图片生成服务配置与路由，并通过最小对话闭环验证。

新增需求没有形成必须等待用户决策才能开工的阻塞项。本阶段采用下述默认决策。真实供应商及本地服务的具体接口，需要在对应适配器任务中列明协议和样例；不能把任意 URL 配置能力宣传为任意 API 兼容。

### 推荐默认决策

| 问题 | 本阶段决策 |
| --- | --- |
| 视频专属 API 的含义 | 先指视频理解/分析；视频生成不在本阶段范围内 |
| 云端和本地 | 均作为服务端点配置；本地服务不要求 Key，但可配置鉴权 |
| 本地模型安装/启动 | 用户提供已运行服务，本阶段不负责下载模型或启动推理引擎 |
| 图片生成 | 独立能力、独立配置；由明确的生图动作调用，不与识图混用 |
| 无视觉对话模型 | 图片先经授权的识图服务生成结构化观察，再交给对话模型 |
| 无视频服务 | 反馈能力未配置；抽帧/转写方案仅在用户显式配置后启用 |
| 无需某种媒体能力 | 可以不配置，不阻止文字对话和其他能力运行 |
| 跨实例通信 | 默认关闭；本阶段不实现通用通信管道 |
| 插件信任边界 | 本阶段面向可信插件，逻辑隔离；不声称具备恶意代码安全沙箱 |

## 2. 范围与交付边界

### 本阶段必须交付

1. 多账号 attach 管理、数据/身份隔离、槽位重新绑定规则与诊断。
2. 同会话有序、跨会话有界并发；共享状态、资源和服务配额的协调。
3. 私聊、群聊、具体会话的扩展与能力作用域策略。
4. 公用制品定义复用、私有覆盖、账号运行状态分离。
5. 模型服务注册、独立能力绑定、授权、凭据保护、路由与错误模型。
6. 媒体引用/处理产物、有限异步任务、超时取消、结果归属与统一发送出口。
7. 内置最小 AgentEngine：文字对话、图片理解后对话、视频理解后对话、显式生图并发送图片。
8. 设置页面、账号覆盖页面及可复现的验收证据。
9. 角色卡继续实际生效；为世界书、记忆模块保留明确的作用域和上下文接口。

### 后续阶段交付

- 从零拉起 QQ、执行注入及安装运行时：独立 launch 阶段。本阶段真实测试要求预先存在可连接运行时。
- 完整酒馆角色卡/世界书格式兼容、关键词递归、复杂触发与完整编辑器。
- 自动长期记忆、情绪系统、遗忘曲线、复杂人格生活模拟。
- 开放插件市场、不可信代码沙箱、远端仓库、签名与自动更新。
- 通用自主浏览、空间互动、长周期工作流、跨实例 Agent 协作。
- Core 迁出 Electron 主进程、完整跨进程账号租约。

媒体异步任务是本阶段的有限执行机制，不等于已经实现可恢复任意网页工作流。

## 3. 对象与归属

```text
DesktopApp
  └─ Core（一个 dataRoot 一个写者）
      ├─ 公用资源库：插件、Skill、角色卡、世界书的定义与版本
      ├─ 服务注册表与凭据库
      └─ Slot（运行槽位）
          └─ AccountSession（已校验的 QQ 身份）
              ├─ 账号档案与覆盖配置
              ├─ 会话：private/peerId 或 group/groupId
              ├─ 插件与 Skill 的账号启用集
              ├─ 历史、私有制品、状态、媒体、任务
              └─ AgentEngine → Policy → CapabilityRouter → Adapter
```

- 长期数据属于 accountId；Slot 是可重用运行槽位。
- 重绑定必须取消旧会话、撤销调用授权、释放运行资源，然后加载新账号数据。
- 每个运行会话有 sessionEpoch；每个宿主有 hostEpoch。旧代际结果不得写入或发送到新会话。
- 一份公用代码可以被多个账号引用，但各账号的配置、状态、媒体、任务、记忆分别存储。
- 公用资源库不是共享记忆区，也不是实例消息总线。
- 同一账号不允许在同一 Core 中重复占用；不同 dataRoot 的跨进程重复账号检测暂不承诺。

## 4. 分层调整与建议目录

```text
src/agent/           最小内置对话引擎、上下文构建接口
src/policy/          作用域、授权与有效能力计算
src/providers/       服务配置、适配器、能力路由、配额
src/media/           媒体引用、下载/上传、观察结果、清理
src/jobs/            有限异步媒体任务、取消、持久记录
src/secrets/         凭据引用、Windows 桌面凭据实现
src/extensions/      工具、Hook、Skill 与能力注册契约
```

目录为职责建议，可在实现时合并小模块。禁止把上述业务逻辑继续塞入 QqInstance、HTTP 路由或一个超大 Agent 文件。

现有 AgentHost 保留作为兼容入口，内置 AgentEngine 通过 hostFactory 接入。默认对话不再依赖用户安装一个聊天插件。旧插件产生 reply 的行为走明确兼容模式，不能与内置引擎竞争回复或静默覆盖。

## 5. 并发、状态与取消

### 消息调度

- 同会话 turn 按顺序运行，不同会话可并发；同一群视作一个会话，保留各发送者身份。
- 初始建议：每账号对话并发 2；全局对话并发 4；每账号媒体任务并发 1。均可配置，属于初始策略而非性能承诺。
- 服务端点还需独立并发/排队上限；多个账号共用同一服务必须共用端点限额。
- 对话和媒体使用独立队列，等待视频任务不能占住全部文字对话资源。
- 媒体任务创建后结束当前发起 turn；完成事件重新进入原会话队列。若期间有新消息，结果要标明原请求，不作为最新问题的答案。
- 每个异步结果保存 originMessageId、turnId、accountId、conversationId、sessionEpoch。

### 插件兼容

现有 v1 插件暴露可变状态，并按账号串行。本阶段不能仅删除 turnChain 后并发执行所有旧插件。

- v1 保持串行兼容通道，明确限制和诊断信息。
- 新 SDK 使用按会话上下文及显式状态操作；共享状态通过事务、CAS 或串行资源执行器修改。
- v1 回调不能位于所有现代对话请求必经的账号串行链上；同一会话仍需遵循已声明的流水线顺序。
- 队列有硬上限；排队、执行分别有超时；接近上限可观测，拒绝有明确错误。

### 取消

会话停止、重绑定、用户取消、调用超时均应传播至适配器和媒体任务。HTTP 取消不等于服务端已停止计费/计算；适配器声明 cancelMode=remote|localOnly|none。

无法远端取消时，本地不再轮询或提交后续步骤，晚到结果不得发送或改写记忆。保留任务记录和未知副作用说明。UI 不得虚报“远端已取消”。

## 6. 私聊/群聊与扩展策略

沿用现有 global → account → kind → account:kind → conversation 合并顺序。新增字段必须文档化数组替换、继承、显式清空的语义。

有效调用同时满足：

```text
已安装且版本兼容
AND 账号启用
AND 当前会话作用域启用
AND 账号获得服务/能力授权
AND 实际服务支持该能力
AND 当前调用未被取消、未超预算
```

配置继承允许在细范围覆盖普通开关；账号服务授权/硬限制不允许由会话、插件或提示词覆盖。关闭能力后，Hook 分发、工具列表、实际调用三处一致。

私聊数据、媒体观察、摘要不自动用于群聊。跨范围传播需要未来独立授权机制。

Skill 不是任意 JS 的别名。本阶段定义受支持的 Skill 内容：说明文本、工具引用、依赖能力、作用域与配置；经筛选后进入 Agent 上下文。可执行实现仍由插件/适配器提供。不宣称支持任意来源 SKILL.md 的全部运行语义。

公用和私有同名资源必须使用 source + kind + id 唯一定位，插件状态不能只按裸 id 混用。制品版本不可原地覆盖；升级前校验兼容与状态迁移。

## 7. 模型服务与能力路由

### 独立配置四项能力

| 能力 ID | 含义 | 输入/输出 |
| --- | --- | --- |
| chat | 对话 | 规范化上下文 → 文本或受支持工具请求 |
| image.understand | 图片理解 | 图片引用 + 问题 → 观察文本/结构化结果 |
| video.understand | 视频理解 | 视频引用 + 问题 → 摘要、时间片等受支持结果 |
| image.generate | 图片生成 | 提示词、受支持参数 → 一个或多个图片制品 |

同一服务可提供多项能力，也可以每项使用不同服务。服务提供者与模型分开标识；不要假定同一 baseUrl 的全部模型都支持相同媒体和工具能力。

Provider 配置包含：id、adapterId、baseUrl、credentialRef（可选）、location、模型列表、能力与支持参数、超时、并发/队列上限、允许的媒体传输方式、重试规则。

路由绑定包含：账号/会话作用域、能力、providerId、modelId、fallback 列表、可选参数。显式允许跨端点回退，默认关闭，防止本地数据未经配置转发云端。

location=local|cloud 是 UI 与策略声明，不能代替地址验证。自定义本机或局域网地址允许；媒体下载地址与模型服务地址使用不同网络策略，不能把媒体 URL 当模型端点随意访问。

### 适配器边界

- 第一批实现明确版本/行为范围的 OpenAI-compatible 文本/图片输入适配器，以及可注册的媒体适配器接口；“compatible”仅指实现支持的字段。
- 视频服务和本地生图工作流通过独立适配器表达提交、轮询、取消、上传和结果解析；不能复用一个修改路径的万能 HTTP 客户端。
- 开发集成阶段必须为四项能力各选至少一个真实可用端点/模型，记录请求响应样例和限制。可由同一个供应商覆盖多项能力。
- 本地和云端分别至少有一个实际端点通过人工验证；不要求每项能力都同时交付本地、云端两种供应商适配器。
- 没有实际服务时可完成模拟验收，但对应真实接入项保持未验收，不能标记完成。

### 路由行为

1. 纯文字直接走 chat。
2. 对话模型不支持图片：先按 image.understand 绑定解析，再把带来源的观察交给 chat。
3. 对话模型支持图片：可通过显式 direct 模式直接输入；默认 external 模式便于独立替换。禁用识图必须阻止图片直接输入和外部识图两条路径。
4. 视频优先走 video.understand；只有显式绑定 frame-summary 后才抽帧/转写，不能默认静默降级。记录观察覆盖范围，不宣称理解未处理的音画。
5. 生图通过内置明确命令/动作启动；支持工具调用的模型可调用同一工具。文本模型不支持工具调用仍可用显式生图动作。
6. 返回的图片 URL、base64 或服务资产 ID 统一转换为账号媒体制品，再经统一发送出口发送。远端服务的本地路径不能直接作为本机文件读取。
7. 缺少能力只反馈该能力未配置；文字聊天继续可用。故障回退必须受能力兼容、账号授权、媒体外发策略共同约束。

### 凭据与配额

- 设置页展示服务和模型，Key 为写入/替换操作，读取仅返回 configured 和掩码，不回传完整密钥。
- 配置文件只保存 credentialRef；桌面凭据使用可用的系统保护机制，保护不可用时明确报错，不静默降级为明文。
- 凭据不传给普通插件、模型上下文、SSE、日志、导出配置。错误体和带鉴权的 URL 同样脱敏。
- 公用服务可显式授权多个账号使用；共用凭据不代表共用上下文、缓存或历史。
- 本地可设置无凭据；连接测试要实际验证所选能力，费用型探测由用户触发，不能后台反复发起生图测试。
- 服务限流与账号预算同时生效；费用统计若无可靠价格来源，仅显示 token/次数，不伪报精确金额。

## 8. 媒体与有限任务

MediaRef 至少包含 mediaId、accountId、来源会话、来源消息、类型、大小、校验摘要、保留策略；本机路径仅由媒体服务解析。按账号鉴权，即使内容摘要相同也不能跨账号直接复用私有观察。

- 入站验证大小、类型、下载时限和重定向；无权限/失效媒体返回明确错误。
- 提交外部服务前检查账号绑定和媒体传输方式；本地文件转为受限上传/内联，禁止把整个数据目录暴露成静态目录。
- 工具观察携带来源和覆盖范围，作为不可信数据进入上下文，不得执行其中的指令或开启权限。
- 输出有数量、大小、有效期上限；清理跳过正在使用的资源，删除会话/账号时有明确清理行为。
- 有限任务状态：queued、running、waiting_remote、succeeded、failed、cancelled、interrupted。
- 任务持久记录可使用 SQLite repository，保持单写者。进程重启后可查询的远端任务按任务 ID 恢复查询；不可查询的任务标 interrupted/unknown，不盲目重发付费生成请求。
- 同一生图动作重复提交使用稳定 actionId；本地去重不等于供应商恰好一次。远端提交结果未知需展示，不自动重复扣费。
- QQ 发送结果未知也需要区分；本阶段不宣称实现全链路 exactly-once 或完整持久 outbox。

## 9. 人格、世界书、记忆预留

本阶段角色卡使用现有解析能力并注入最小 AgentEngine。历史按 token/条数预算加载，避免重复包含当前入站消息。

上下文构建接口划分：稳定人格、世界书条目、记忆条目、会话摘要、近期消息、媒体观察。预留来源、作用域和 token 预算字段，允许世界书/记忆实现为空，不要求本阶段交付长期记忆质量。

世界书定义与经历记忆分离；公用世界书只读复用，自动记忆不改写角色卡或公用定义。若 UI 暂不支持世界书/记忆编辑，应明确标记后续能力，不给出可保存但不生效的配置入口。

## 10. 配置与界面交付

设置页增加“模型与媒体服务”：服务列表、地址、适配器、模型、凭据状态、能力、连接测试与默认绑定。

账号页增加：继承/覆盖 chat、image.understand、video.understand、image.generate；私聊/群聊/具体会话启用规则；显示当前生效来源。

能力详情展示：已配置服务、是否被授权、作用域是否启用、服务能力是否满足、降级策略和禁用原因。不要把局部识图失败显示为 QQ 离线。

任务页或现有 Activity 扩展：任务来源、能力、服务、状态、取消、错误原因与输出。错误信息不包含密钥。

配置语义样例（目标格式示意，不能直接传入当前 config v1）：

```json
{
  "schemaVersion": 2,
  "providers": [
    {
      "id": "local-chat",

      "location": "local",

    },
    {

      "adapterId": "example-media-adapter-v1",
      "location": "cloud",
      "baseUrl": "https://media.example.invalid/api",
      "credentialRef": "provider/cloud-media",
      "models": [
        { "id": "vision-model", "capabilities": ["image.understand"] },
        { "id": "video-model", "capabilities": ["video.understand"] },
        { "id": "image-model", "capabilities": ["image.generate"] }
      ]
    }
  ],
  "accountPolicies": {
    "10001": {
      "allowedProviders": ["local-chat", "cloud-media"],
      "bindings": {
        "chat": { "providerId": "local-chat", "modelId": "text-model" },
        "image.understand": { "providerId": "cloud-media", "modelId": "vision-model" },
```

## 11. 迁移与可观测性

- 现有 v1 档案和槽位可读取；新功能采用显式配置版本与迁移，不能把旧用户自动绑定未知模型服务。
- 迁移前备份，先校验后原子写；失败不覆盖旧文件；新版本创建的数据与旧版本回退兼容范围应写清。
- 分开 artifactRevision、profileFingerprint、hostEpoch。配置修改应使指纹变化；旧宿主不能写新代际状态。
- 使用 requestId、turnId、jobId、actionId 关联消息、调用、任务、发送，记录账号/会话/能力/服务与耗时，不默认记录完整敏感提示词。
- 统计对话/媒体队列长度、服务并发、超时、取消、能力拒绝；诊断区分 QQ 连接、Agent 就绪、媒体服务状态。

## 12. 阶段完成定义

04 文档中的自动化与集成必选项全部通过，人工真实接入项有实际证据；不能用模拟成功替代真实 QQ 或真实模型接入。未具备服务/账号条件时清楚列为未验收，不宣称阶段完成。

先完成契约与骨架，再完成最小纵向闭环，最后交付界面和真实集成。完整世界书、长期记忆与自主行为进入下一阶段，不在此阶段隐式扩张。
