日期：2026-10-26。状态：待执行。2026-10-26 更新：W01～W10 已实现并有自动/浏览器证据，W11 视觉缩放与 W12 原生选择器待人工，逐项结果见[55 执行记录](55-worldbook-editor-and-source-execution.md)。配套[53 实现计划](53-remaining-development-implementation-plan.md)。世界书细项继续按[47 验收标准](47-independent-worldbook-acceptance.md)执行；本文件覆盖剩余全阶段，不替代历史执行报告。

## 1. 验收方式

自动测试使用隔离临时dataRoot、FakeChannel/FakeProvider与固定样例，不读真实用户数据。浏览器使用独立服务与测试账号。Electron原生、真实QQ和真实服务分别记录；未提供环境的项目明确待验收，不能用构建通过或截图推断。

P0：跨账号/群私聊/角色数据泄漏、越权外部操作、覆盖/丢数据、关闭后仍执行、失效回复发送。P1：主流程、恢复或一致性错误。P2：文案、布局与可访问性等；导致主要操作不可达的P2也阻止放行。

所有P0/P1必须通过；其他延期项写明影响和处理计划。当前基线726通过/1既有跳过仅供对照，后续以实际命令输出为准，不要求固定测试数量，也不接受新增相关skip绕过。

## 7. 每阶段统一命令与证据

```powershell
npm test
npm run typecheck
npm run desktop:build
git diff --check
```

阶段修改后运行必要定向测试；结束再执行统一命令，记录实际退出码、通过/跳过数与原因。新增测试验证边界与真实行为，不为凑数量重复实现细节。阶段P0/P1失败必须修复再验，不得仅更新报告为通过。

截图、日志、服务矩阵和测试产物放本地test-results；文档保存步骤、摘要、测试名称及可重现条件。浏览器截图证明视觉，API/Store/Agent测试证明数据和行为，两类证据互不替代。

## 8. 结果模板与完成定义

每阶段新增执行报告，更新README。推荐表格：

| 验收ID | 通过/失败/待执行 | 测试名或操作步骤 | 证据路径 | 问题/修复/剩余影响 |
| --- | --- | --- | --- | --- |
| 示例：W09 | 待执行 | 固定r1→保存r2→显式切换 | 待填写 | 不预填通过 |

报告另附：实施包完成情况、方案差异、Git/工作区状态、自动命令结果、浏览器视口、原生/真实服务条件、跳过原因、迁移/回退结果，以及是否提交/打包/发布。

完成定义：目标范围可实际使用、权限与隔离成立、错误可恢复、相关P0/P1通过、公共模块无重复实现、文档与真实行为一致。人工项未执行时限定结论；不能将“后端已接通”“测试通过”“页面可点击”“已打包”混写成整个产品已验收。
