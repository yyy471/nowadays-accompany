# 前端用户操作体验修复方案

日期：2026-10-23。输入：[32 前端用户操作体验分析](32-frontend-ux-review.md)。本文给出按用户任务排序的修复工作包、关键设计取舍、依赖与验收标准；不修改代码，不改变现有产品约束。

## 1. 修复原则

1. **先修状态，再修文案**：加载失败显示成“没有数据”会让用户做错决定，优先级高于视觉和措辞。
2. **主链路优先**：首次连接 → 绑定角色 → 配置模型 → 查看状态，四处断点优先于低频的部署与诊断页面。
3. **保留安全边界**：手动注入、账号隔离、角色卡门禁、凭据只写不回显、卸载保留数据等规则不改；优化的是解释和入口，不是放松限制。
4. **能用现有 API 的不新增后端**：模型服务管理复用已存在的 `/providers` 删除与凭据接口；只有资源导入和“打开资源目录”需要 Electron/后端配合。
5. **小步可回退**：纯前端改动按页面提交；涉及路由合并的改动保留旧 hash 重定向；不改变账号数据 schema。

## 2. 目标状态

修复完成后，用户应该能形成下面这条直线：

```
首次打开
  → 主页空态直接告诉我“去实例与监听”
  → 连接页看到 SnowLuma 状态与不可用原因
  → 注入并监听
  → 资料页看到“去资源库添加角色卡”并完成绑定
  → 模型服务可用模板或已有服务，保存后一键去账号模型配置
  → 日常在总览看状态，在实例与监听做操作
```

同时，任何请求失败都应显示“哪里失败 + 重试”，而不是显示空态；任何未保存修改在切换账号、切换页面或关闭设置时都不应无声丢失。

## 3. 工作包

### U0：共享状态与文案基础（前置）

**目标**：让所有页面用同一套方式表达加载、失败、空态、旧数据和禁用原因，避免逐页临时修补。

**改动**

- 在 `desktop/renderer/src/ui/` 增加统一的异步状态组件：`AsyncSection`（loading / error / empty / stale / content）或等价的组合组件。
- `usePoll` 增加“是否完成首次加载”和“错误时是否仍有旧数据”的明确字段；页面不再用 `list.length === 0` 推断空态。
- 新增 `desktop/renderer/src/labels.ts`：
  - `ReplyMode`、`VisionMode`、`CancelMode`、`ArtifactKind`、部署动作等枚举的中文标签。
  - `capabilityId` → 中文名称的唯一映射。
  - 统一动作词：注入并监听、开始监听、停止监听、卸载注入、重新读取、应用到运行实例。
- 新增纯函数 `connectionBlockers(status)`：返回“为什么不能连接”的用户可读原因和下一步动作。连接页、SnowLuma 设置页共用。
- 新增文案守卫测试：扫描非诊断页面中的内部术语（`profile.json`、`catalog`、`worker`、`last-known-good`、`槽位`、`租约`、`Runtime`、`backend`、`熔断` 等），诊断页、manifest 展开区和设置诊断区列入白名单。
- 增加 `useDirtyGuard`（或 App 级未保存注册表）的接口定义，供 U1 使用。

**验收**

- 用延迟响应、500 响应、空数组三种 mock 情况验证：页面先显示加载态，失败显示错误与重试，只有成功且为空才显示空态。
- 连接页在任一 `ready` 条件不满足时都能看到对应原因，而不是只有灰按钮。
- 文案守卫测试通过；内部术语只出现在诊断、manifest 和高级说明中。

### U1：主链路与数据安全（P0/P1）

**目标**：把“首次连接 → 角色 → 模型”的断点补上，并阻止无提示的数据丢失。

#### U1.1 主页

- `App.tsx` 把 `accounts.loading`、`accounts.error` 传给 `HomePage`。
- 主页三态：加载骨架；失败错误 + 重试；真空态显示“还没有账号”并给出“去实例与监听”按钮。
- 有账号时增加“编辑展示资料”入口（跳到“资料与角色”，并定位到展示资料卡）。
- dock 显示账号在线状态；账号多时横向滚动，昵称截断；去掉不完整的 tab ARIA 或改成按钮组 + 方向键。

**验收**：首次加载无“还没有账号”闪烁；断网时显示错误；无账号时能一次点击进入实例页；12 个账号时 dock 不溢出。

#### U1.2 连接页与 SnowLuma

- 连接页顶部增加紧凑状态条：管理服务、版本、密码、自动注入、协议。
- 主按钮下方始终显示禁用原因；`aria-describedby` 关联。
- 文案统一：介绍写“点击右侧按钮”，按钮只用“注入并监听／开始监听”。
- 把“刷新状态”改为“同步连接”（或“重连”），与只读的“刷新”区分。
- 进程卡片统一用“停止监听”；连接详情里的“停止 / 释放”改成同一动作的说明或移除重复按钮。
- “可连接的 QQ”改为“QQ 进程”。

**验收**：未保存密码、版本不兼容、自动注入状态未知三种情况都能在连接页直接看到原因与“去连接设置”；停止动作只有一套名称。

#### U1.3 资料与角色

- 先渲染“会话角色绑定”，把“账号展示资料”折叠为次级卡或放到绑定卡之后。
- 账号下拉显示“昵称（QQ 号）”，带 `AccountAvatar`。
- 角色卡无选项时提供“去资源库添加角色卡”按钮；资源库返回后保留账号上下文。
- 角色卡选择：默认“跟随当前版本”；固定版本收进“选择特定版本”二级选择，避免长列表和重复项。
- 空态文案改为“注入并开始监听后账号会出现在这里”，按钮改为“去实例与监听”。
- 绑定读取失败时在卡片内显示错误和重试，不再一直显示“正在读取…”。
- 切换账号或离开页面前，如果绑定表单有输入，使用 U0 的 dirty guard。
- 解除绑定加一次确认。

**验收**：无角色卡时两次点击内可到达资源库；绑定读取失败不会停在加载态；角色卡下拉默认只显示一组“跟随当前”；切换账号不静默丢失输入。

#### U1.4 插件与 Skill

- 页面先改名为“账号插件”（或类似），副标题只承诺插件；Skill 状态继续留在模型配置的生效结果中。若产品要求独立 Skill 管理，另开工作包，不在此页伪装入口。
- 编辑插件时读取完整的 `account.file.plugins`：
  - 公用插件可勾选启用／停用；
  - 私有插件作为只读条目展示并原样保留；
  - 停用条目保留 `enabled: false`，不要因为未勾选就从文件里删除；
  - `config` 字段原样保留。
- 保存时按“保留未展示条目 + 更新公用插件启用状态”合并，不重建整个列表。
- 目录路径和槽位移入折叠详情；“重新加载”改为“应用到运行实例”。
- 删除“会话绑定数”这一错误文案；插件页不展示会话绑定。

**验收**：带私有插件、停用插件和 `config` 的账号保存一次后，原条目仍在；标题不再出现无法使用的 Skill 承诺。

#### U1.5 模型配置

- 切换账号前检查 `dirty`：提示“有未保存修改，放弃并切换？”；取消则留在当前账号。先保存再切换由用户手动完成，避免把保存失败和切换耦合。
- 在 App 路由层注册页面级 dirty guard：侧栏、顶栏切换和设置关闭都能感知。
- 保存栏固定在卡片底部或页面底部，滚动时保持可见；撤销修改同栏。
- 测试与保存解耦：有未保存修改时禁用测试并提示“先保存”，或把按钮明确改为“保存并测试”；不要保留隐式保存。
- “生效结果”里的 `auto`／`external`／`cancel` 使用 `labels.ts` 的中文标签；费用确认使用能力中文名。
- 读取失败时在卡片内显示错误和重试，不再显示“正在读取账号配置…”。
- 服务授权复选框显示服务 id／名称，不只显示模型和 Base URL。

**验收**：切换账号时草稿不丢失；测试按钮不会在用户不知情时保存；失败时不出现永久加载；页面内所有枚举均为中文。

#### U1.6 资源库状态

- `ArtifactsPage` 增加 `data === undefined` 的加载态和错误态；部署记录同样区分加载与空。
- 空态先提供“打开资源目录”按钮（见 U2），再展示格式说明。
- 回滚目录移入“更多”菜单或页面次级区域，减少误触。

**验收**：请求失败时页面显示错误，不显示“还没有制品”；空态可以直接打开资源目录。

### U2：资源导入闭环（P1，需要 Electron/后端）

**目标**：让用户不离开应用就能把角色卡或插件放入公用资源库。

**分两步**

1. **短期**：在 Electron 主进程增加 `nowadays:open-public-artifacts-directory` IPC，根据 `diagnostics.artifacts.publicRoot` 用 `shell.openPath` 打开目录。主进程沿用现有来源校验（窗口、主 frame、origin 与 `apiUrl` 一致）。资源库空态和路径卡各放一个“打开目录”按钮。角色页的“去资源库”落到资源库并突出“打开目录”。
2. **完整方案**：增加“导入资源”：
   - Electron `showOpenDialog({ properties: ['openDirectory'] })` 选择包含 `manifest.json` 的目录。
   - 后端增加受 token 保护的导入用例与路由；校验 `kind`、`id`、`revision`、manifest schema、文件路径，拒绝路径穿越和符号链接；先复制到临时目录，再原子替换目标 revision。
   - 导入对话框展示“角色卡／插件、名称、版本、文件数、目标路径”；同 revision 已存在时要求明确覆盖或改用新 revision。
   - 导入不自动部署；导入后仍由用户在版本列表点击部署。这样保持现有“catalog 变更需要显式操作”的语义。
   - 角色卡导入后，资料页的角色下拉刷新即可看到。

**验收**：有效目录可以导入并出现在列表；无 manifest、kind 不符、非法 id、路径穿越、重复 revision 都有明确错误；导入不会自动切换当前版本；打开目录在打包版可用。

### U3：信息架构与导航（P1）

**目标**：减少重复入口，让一级／二级导航的行为符合预期。

**推荐方案**

- **总览与实例与监听差异化**：总览只保留“SnowLuma 状态摘要 + 在线账号摘要 + 去实例与监听 + 账号准备快捷入口”，不再渲染完整进程卡片；实例与监听成为唯一的完整操作页。保留两个路由，避免书签失效。
- **工作台一级导航**：点击“工作台”始终回到总览；如果当前已在总览，滚动到顶部。侧栏切换保持当前子页面。
- **插件页改名**：把“插件与Skill”改为“账号插件”，等真正有 Skill 管理能力后再改回或新增页面。
- **设置拆分**：设置标签改为“模型服务 / 连接 / 外观 / 诊断”。SnowLuma 标签只保留连接状态、连接表单和恢复监听；运行信息、容量限制、账号租约、期望状态、Runtime、指标、路线图、诊断快照全部移到“诊断”标签（或事件诊断页的“系统”区）。两处只能保留一处，不复制。
- **设置入口语义**：全局“设置”按钮记住上次使用的标签；连接页的“连接设置”仍定向到“连接”；模型配置的空态定向到“模型服务”。
- **交叉链接**：模型服务保存后提供“去账号模型配置”；模型配置空态提供“去模型服务”；资料页无角色卡提供“去资源库”；主页提供“去实例与监听”和“编辑展示资料”。

**验收**：从任意工作台页面点击“工作台”都会回到总览；总览不再出现完整的进程操作卡；设置页首屏能看到连接表单，不再需要穿过 8 张运行信息卡；所有跨页面任务都有一次点击的入口。

### U4：模型服务管理（P1，复用现有 API）

**目标**：用户能看见、修改和清理已有服务，而不是只能通过能力行间接操作。

**改动**

- 在“设置 → 模型服务”增加渐进展开的“全部服务”列表：服务 id、Base URL、支持的模型、密钥是否已保存。不增加本地／云端强制选择或凭据引用字段，保留三类固定配置与扩展模型的简化入口。
- 每行操作：编辑、清除密钥、删除服务。删除前调用只读 `GET /providers/:id/impact` 展示受影响账号，并说明服务授权、绑定或回退引用将被清理；用户确认后才调用 `DELETE /providers/:id`，取消或预览失败不得删除。预览是当时快照，删除后展示实际影响结果。
- 编辑复用现有 `/providers/:id` 更新接口；变更 origin 时仍要求重新输入密钥（现有规则保留）。
- 服务来源下拉显示“服务 id · 模型”，不再只显示 Base URL。
- 模型服务保存后增加“去账号模型配置”按钮。
- 可选 P2：增加常见服务的 Base URL 模板（OpenAI 兼容、DeepSeek 等），但不预置密钥、不替用户填写。

**验收**：能删除错误服务并看到受影响账号提示；能清除已保存密钥；两个同地址服务在下拉中可区分；保存后可一步进入账号授权。

### U5：布局、可读性与可访问性（P1/P2）

**目标**：让长页面、窄窗口和键盘操作都可完成。

**改动**

- 固定设置按钮：给 `.content` 增加底部安全区（例如 76px，窄窗口同样生效）；或把按钮移入顶栏。保留“左下角设置”的产品选择时，必须保证不遮挡内容。
- 主页签名区去掉固定 168px 最小高度，改为随内容自适应；dock 增加横向滚动、昵称省略、键盘方向键切换。
- 字号与对比度：
  - 先修正低对比说明文字和占位符（目标 4.5:1），把关键提示提升到 12px；
  - 再评估是否把根字号从 13px 提到 14px。建议分两步，避免一次改动造成全站密度变化。
- 卡片层级：页面标题、卡片标题、正文之间拉开字号或字重；模型配置和设置诊断页优先。
- 首次连接 stepper 改为两列或 `auto-fit`，不再固定三列。
- 资源库网格在 1240px 以下是否单列需要复核；如桌面窗口常见 1280×800，可把最小列宽调到 360px 以保留两列。
- 成功提示增加自动消失（如 3–5 秒）或在相关数据刷新时清除；错误保留到用户处理或重试。
- 事件诊断：暂停时显示“已暂停接收显示”；列表底部标注“仅显示最近 300 条”；清空加确认。
- 可访问性：禁用原因用 `aria-describedby` 关联；加载／暂停使用 `role="status"`；主页 dock 使用按钮组或 radio group + roving tabindex；检查 125% 缩放和键盘 Tab 顺序。

**验收**：1024×720、125% 缩放下完成连接、绑定、保存模型、部署；设置按钮不遮住任何可点击元素；文字可读；键盘可以完成主流程。

### U6：回归与验收

**自动化**

- 为 `connectionBlockers`、插件资料合并、枚举标签映射、dirty guard 判定抽取纯函数并加 Vitest 测试。
- 文案守卫测试：非诊断页面禁止内部术语和错误文案。
- 每个新增页面状态用 mock fixture 覆盖加载、失败、空、旧数据四种情况；保留 `test-results` 中的场景脚本，不进入 Git。
- 现有 `npm run typecheck`、`npm test`、`npm run desktop:build` 必须保持通过。

**人工验收**

- 首次连接：没有 SnowLuma、未保存密码、版本不兼容三种状态都能看到原因与下一步。
- 无角色卡：从资料页两次点击内到达资源库并完成导入／打开目录。
- 多账号：模型配置有未保存修改时切换账号、切换页面、关闭设置都不会静默丢失。
- 私有插件：保存一次后私有插件、停用条目和 `config` 保留。
- 窄窗口：1024×720、125% 缩放下固定按钮、保存栏、dock、stepper 不遮挡、不溢出。
- 断网／核心不可达：主页、资料、模型、资源库均显示错误和重试，不显示空态。

## 4. 关键设计取舍

### 4.1 总览与实例与监听

| 方案 | 优点 | 代价 |
| --- | --- | --- |
| 总览只做摘要，实例页做完整操作（推荐） | 保留两个熟悉入口，职责清晰，路由不变 | 需要重写总览的展示和快捷入口 |
| 合并为一个“连接”页 | 页面数量少，最省认知 | 旧路由和用户习惯需要迁移，信息可能过密 |

推荐前者：总览回答“现在怎么样”，实例与监听回答“我要做什么”。

### 4.2 插件与 Skill

| 方案 | 优点 | 代价 |
| --- | --- | --- |
| 先改名为“账号插件”（推荐） | 标题诚实，改动小 | Skill 管理仍不在该页 |
| 在插件页补 Skill 列表 | 标题与内容一致 | 需要账号选择和额外数据，且与模型配置的 Skill 状态重复 |

推荐先改名；Skill 作为独立能力面另开任务，避免两个页面各展示一半。

### 4.3 资源导入

- 只做“打开目录”是最小修复，但用户仍需手工复制文件。
- 完整导入需要 Electron 文件选择器与后端导入用例，属于跨层改动；建议作为独立工作包，不混在纯前端批次。
- 导入不自动部署，保持当前 catalog 的显式版本切换语义。

### 4.4 未保存修改

- 最小方案：检测到 dirty 时提示“放弃并切换”，用户可取消后先保存。
- 不建议自动保存后切换：保存可能失败、可能触发策略重载，失败时用户会同时失去上下文。
- 所有退出路径（账号切换、页面切换、设置关闭）统一走同一个 dirty guard。

### 4.5 模型服务管理

- 复用现有接口，不新增删除语义；但 UI 必须展示 `deleteProvider` 返回的受影响账号，避免用户误以为删除只影响设置页。
- 清除密钥与删除服务分开：前者保留服务定义，后者影响账号绑定。

## 6. 主要风险

- **路由合并**可能破坏旧书签；保留 `pageFromHash` 的 legacy 重定向，并在合并前确认用户是否接受页面数量变化。
- **资源导入**涉及文件系统边界；必须复用主进程的文件选择器、校验 manifest、拒绝路径穿越，不在渲染进程直接读写任意路径。
- **插件保留**需要以完整 `AccountProfileFile` 为基础做合并；不能只根据当前页面展示的插件列表重建文件，否则会重复当前的数据丢失问题。
- **删除服务**会让已有账号绑定失效；必须在确认框里展示受影响账号，并允许用户取消。
- **字号整体放大**可能改变现有卡片密度；先做对比度和关键文字，再决定是否调整根字号，避免一次全局视觉回归。

## 7. 不在本方案内

- 不改变手动注入、账号隔离、角色卡门禁、凭据只写不回显等产品约束。
- 不新增系统自启、不自动启动 QQ／SnowLuma、不自动注入。
- 不在本轮引入 React 测试框架或大规模前端重构；优先用纯函数测试和 mock 场景验收。
- 不把全部运行诊断信息删除：它们会被移动到诊断入口，而不是丢失。
