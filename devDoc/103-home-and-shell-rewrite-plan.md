## 3. 第一批做成什么样

### 3.1 主页

直接依据 [已认可主页截图](design/character-studio/preview-home.png) 落地，保留以下要素：

- 奶油纸面、深蓝、樱粉与手账红。
- 左侧局部社团室、水墨干笔边缘与独立立绘，不使用整页背景图。
- 姓名索引与小便签，呼应角色手账的设定。
- 右侧账号资料、主要入口、自动回复开关；按钮采用角色定制的颜色、箭头端片与按压下沿。
- 少量真实关系摘要，点击进入对应账号和目标的角色绑定。

正式实现不复制原型的模拟状态、轮询、保存或导航脚本。原型只是视觉参考，按现有 React/TypeScript 与公共 UI 重写。

### 3.2 全局菜单壳

| 区域 | 行为 |
| --- | --- |
| 品牌 | 返回主页，走统一导航准入 |
| 顶部账号切换 | 明确标记“主页账号”；从旧业务页切换时经过全部草稿准入后回到所选账号主页，不切换 QQ 登录身份、不自动连接或保存配置 |
| 底部 Dock | 桌面、关系、模型、收藏、更多；反映当前页面，不再承担旧账号头像 Dock 的职责 |
| 全部菜单 | 可达主页、总览、实例与监听、资料与角色、插件与 Skill、模型配置、事件诊断、应用设置、资源库 |
| 内容区 | 当前页面独立滚动，底栏和操作不互相遮挡 |
| 状态区 | 当前账号的真实连接/操作状态，加载和未知状态不会伪装成离线 |

第一批菜单中的未迁移页面继续接入现有页面与设置弹窗；不跳到设计原型、空壳或“即将上线”页面。现有 hash、深链接、设置关闭路径与历史路由处理保持可用。

账号很多时，顶部显示有限个可见标签，并提供完整账号列表/搜索；首次加载可选有效的上次账号或明确的默认项。当前账号之后消失时，提示重新选择，禁用旧对象操作，不把待提交动作静默转给另一个账号。

底部页面 Dock 使用页面导航语义和当前项标记；顶部账号选择使用选择器语义。不能把旧账号 Dock 的 toolbar 行为直接当作新页面导航。

## 4. 真实数据与产品语义

### 4.1 主页各元素的数据来源

| 元素 | 接入方式与边界 |
| --- | --- |
| 账号列表与 QQ 号 | 复用账号查询，按 accountId 关联；PID、槽位和未确认账号提示不冒充账号身份 |
| 昵称、头像、签名 | 复用现有账号展示解析与 AccountAvatar 管线；保留真实昵称、本地显示资料和头像失败回退的现有规则 |
| QQ 连接状态 | 复用实例/监听快照，按 accountId 对齐；请求失败表达为未知或过期，不当成所有账号离线 |
| 自动回复 | 读取服务端账号 Agent 状态及有效原因，不从连接色点推断 |
| 绑定摘要 | 读取当前账号的角色绑定；完整键为 accountId + kind + peerId；未加载、失败与确实没有绑定分别表达 |
| 夏澄、局部场景、便签 | 作为内置主页主题；没有真实映射时，不宣称是运行角色、已绑定资源或真实收到的消息 |

展示主题先内置一套。第一批不新增立绘上传、背景编辑、主题市场或按每张角色卡自动换图的系统。主题素材失败时仍能看见账号、状态和主要操作。

### 4.2 自动回复开关的明确调整

13 号旧文档曾要求主页只读，不暂停。用户当前选定的设计稿包含自动回复控制，本方案将它明确纳入第一批：**只有显式点击开关才提交账号级暂停/恢复**。

切换账号、切换页面、打开菜单、加载主页与预览主题仍不产生业务写操作。暂停不调用实例 stop，不断开 QQ，不停止监听；不通过注入/卸载/发送接口模拟暂停。

配置开关与实际可回复性分开：例如“自动回复已开启，等待连接”“已开启，部分目标未绑定角色”，不能仅因开关开启就显示“全部就绪”。离线时能否更改开关，依现有端口真实能力呈现，不猜测服务端行为。

请求进行中显示反馈并限制重复提交；失败保留服务端已确认状态，展示原因和重试。所有写入绑定发起时的 accountId；晚返回结果不能覆盖另一个账号。请求体和错误处理以正式契约核对为准。

### 4.3 控制面映射

102 号文档可确认的功能入口如下，不据此臆造字段：

- 账号与运行快照：`GET /accounts`、`GET /instances`。
- 账号资料：`GET /accounts/:accountId/profile` 及现有展示资料用例。
- 角色绑定：`GET /accounts/:accountId/role-bindings`。
- 配置和逐目标有效原因分别为`GET /accounts/:accountId/policy`与`GET /accounts/:accountId/effective`。主页只读账号policy，不以虚构的peerId=0有效结果宣称所有会话就绪。
- Agent 操作：`POST /accounts/:accountId/agent`。
- 事件：`GET /events`，沿用现有鉴权、续传与重连方式。

不在 Home 再造 HTTP 客户端、SSE 或另一套定时刷新。优先共用现有查询；只有主页新增的数据缺口才添加受控读取。第一批不读聊天历史、发消息、测试模型或触发媒体生成。

## 5. 代码组织建议

保留当前工程、构建、React 与 TypeScript 技术路线，不在本批更换路由库或状态管理框架。

```text
desktop/renderer/src/
  App.tsx                          # 原有运行协调入口，接入新壳，逐步收紧展示职责
  pages/Home.tsx                   # 重写主页入口
  components/shell/
    AppShell.tsx                   # 页面框架与内容/Dock边界
    AppHeader.tsx                  # 品牌和账号区
    AccountSwitcher.tsx            # 账号标签与完整列表
    PageDock.tsx                   # 页面导航
    MoreMenu.tsx                   # 九个功能入口
  components/home/
    HomeScene.tsx                  # 局部场景、立绘、主题标识与便签
    HomeAccountPanel.tsx           # 账号资料、入口与Agent控制
    HomeBindingsSummary.tsx       # 当前账号的绑定摘要
  lib/
    navigation.ts                  # 单一导航目录，沿用现有准入及hash语义
    home-presentation.ts           # 纯展示模型映射，分清未知/失败/空/就绪
    use-home-data.ts               # 组合已有查询，不重复拥有全局连接
  ui/character-theme.css           # 语义token及公共控件外观扩展
  styles/shell.css
  styles/home.css                 # 仅布局与场景，不再叠加多轮原型覆盖
  assets/themes/xiacheng/
    character.png
    scene-ink.png
```

建议目录在源码依赖核对后可微调，但职责不重新堆回 App.tsx。公共 Button、ControlButton、Field、Input、Modal、Confirm 等仍从既有 `ui` 入口导入。

App.tsx、main.tsx、api.ts、types.ts、hooks.ts、preferences.ts、AccountAvatar、草稿保护、确认框与焦点机制均不整文件盲删。可以整理它们的展示职责，但需保留已验证的契约和生命周期。

新主题先提供命名明确的视觉变体与作用域，不一次改坏所有旧页面的默认控件。迁移中的旧页使用隔离容器；必要时将旧选择器收进 legacy 作用域。不能把整个原型 CSS 直接全局导入，也不能用不断追加覆盖的方式建立新 UI。

## 7. 按步骤执行

### P0：建立基线与实施清单

记录现有工作区改动、当前路由、API函数、组件/样式依赖、草稿入口及桌面退出协议；不覆盖用户未提交修改。把主页数据来源和可删展示段写成实际清单，核对上文尚未源码验证的字段与路径。

核对公共 UI 契约测试、类型检查、前端/桌面构建命令与现有测试基线。准备隔离数据，不使用真实 QQ 账号和付费模型做普通界面测试。

### P1：新应用壳与设计基础

先按105实现主题与开发专用组件样板，检查真实字体、控件状态、键盘/焦点、长文本、多尺寸和减少动效，再进入应用壳组装；样板不加入正式业务导航。

主题与样板已由106完成。下一步组装新壳时，须核对App控制器、DraftProtectionProvider和ConfirmProvider的主题范围；仅在Home内部包主题不能改变外层导航回调已捕获的确认主题。

落地主题、按钮/开关/导航变体、顶部账号选择与底部 Dock；将九个功能入口接回现有页面或设置弹窗。接通统一路由与草稿准入，隔离未迁移旧样式。

门槛：全部入口可达，前进后退/设置关闭/退出保护不退化，旧页仍可完成原有操作。

### P2：主页视觉重写

移入主题素材，完成局部水墨背景、立绘、便签、账号区、主要按钮和绑定摘要。直接替换旧 Home；保持数据与显示分层，用隔离数据检查视觉和异常状态。

门槛：构图符合已选设计，长内容和素材失败时操作仍可见，Dock 不覆盖内容。

### P3：真实数据与操作闭环

复用账号、运行快照与事件更新；接通实际 Agent 开关和带账号/目标上下文的导航。处理慢请求、失败、账号消失、重复点击、跨账号迟到响应。

门槛：页面不依赖模拟数据；只读操作没有写请求；暂停和恢复只影响明确账号的 Agent 状态。

### P4：验收、删除收尾与交付

按 [104 验收标准](104-home-and-shell-rewrite-acceptance.md) 完成定向回归、类型检查、桌面构建与相关既有测试；删除已迁移旧展示/孤立样式，检查剩余 import 和入口。

提供真实前端截图、变更文件清单、验证结果和未完成项。单独验证 Electron 本地窗口/托盘/缩放；不能用浏览器截图代替原生验收。本批不自动覆盖现有 release 文件或安装包。

## 8. 逐页迁移节奏与回退

每批保留一个可运行的前端，提交/快照尽量按“公共壳 → 主页 → 接口闭环与验收”分开，不能将后端、数据目录改造和所有页面重写混成一次变更。

开始前保留当前工作区基线；只记录、提交本次修改，不回滚或覆盖他人改动。出现问题时按本批文件或提交回退，用户数据和数据 schema 不变；不靠清空账号资料恢复界面。

首页＋菜单通过后，建议依次迁移：资料与角色 → 模型配置 → 插件与 Skill → 资源库 → 总览/实例与监听/事件诊断/设置。可按实际使用优先级调整，每批都沿用根 DESIGN.md，替换后清理相应旧代码。
