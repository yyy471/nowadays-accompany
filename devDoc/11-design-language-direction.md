# 提前阶段：设计语言与关键页面样板

日期：2026-10-22

状态：候选主方向与设计任务。用户明确偏好简约、炫酷动效；以下具体颜色、时长与布局为推荐值，需在可交互样板中验证，不代表已完成界面改造或用户已确认所有细节。

## 1. 顺序调整

将设计语言与关键操作流程提前，在全面扩展页面前先做样板。10 文档的 S1/S2 修复和 SnowLuma 技术验证继续保留，不因设计阶段而取消。

先确定颜色、排版、材质、动效和组件状态，再完成三个可交互样板；样板验证后用于后续页面，不要求现在一次性画完所有功能。

## 2. 推荐方向

为长期开启的 Windows AI 陪伴桌面工具，采用深色极简、少量精细高光和带弹性的状态过渡。

主方向：石墨黑 + 冰青 + 柔和物理动效。

| 方向 | 感受 | 适用判断 |
| --- | --- | --- |
| 石墨黑 + 冰青 | 清晰、轻未来感、克制 | 推荐主方向，兼顾运行管理和陪伴 |
| 深灰 + 电光紫 | 更活跃，偏 AI 创作工具 | 可作为备选主题，避免紫色渐变铺满界面 |
| 暖深灰 + 琥珀 | 更亲近，偏私人角色空间 | 适合作为角色相关主题，运维状态仍使用统一语义色 |

整体以线条、留白、层级和状态反馈建立品质感。角色形象、头像和媒体输出承担个性表达，不为每张普通卡片加装饰动画。

## 3. 基础视觉规范（样板推荐值）

### 色彩

| Token | 推荐值 | 用途 |
| --- | --- | --- |
| background | #0B0D12 | 应用主背景 |
| surface | #131720 | 主内容面板 |
| surfaceRaised | #1B212D | 弹层/浮起区域 |
| textPrimary | #E8EDF5 | 主文字 |
| textSecondary | #A4AFBF | 说明与次要信息 |
| accent | #67E8D1 | 主操作、选中、焦点 |
| onAccent | #0B1516 | 强调色按钮文字 |
| success | #7DD3A7 | 就绪、成功 |
| warning | #F4C775 | 待处理、需要注意 |
| danger | #FF8D96 | 失败、危险操作 |

颜色需按实际相邻前景/背景验证对比度；不可仅凭暗色主题声称满足可访问性。状态始终包含图标或文字，不能只靠颜色。

### 字体与形状

- 中文优先系统 UI 字体（Microsoft YaHei UI/合适系统回退），英文 Segoe UI Variable/Segoe UI。
- 正文与表单建议 14px，标题 20–24px，辅助信息一般不低于 12px；验证 Windows 125%/150% 缩放。
- PID、端口、计数、时间使用等宽或等宽数字，不把全部正文做成终端样式。
- 间距采用 4/8/12/16/24/32 的基础尺度。
- 面板圆角约 12px，输入框/按钮约 8px；避免每个区域都画厚边框或多层卡片。
- 主题只改变表达，不能改变暂停、卸载、停止等动作的语义和位置。

### 材质

主体使用清晰的实色层次，弹出菜单/轻量浮层允许局部磨砂。角色焦点区或关键状态使用轻微高光。

不默认启用全窗口透明、常驻粒子、背景视频或每张卡片的指针追光。CSS 模糊与 Windows 原生材质分别评估；不能把视觉近似称为真正的系统 Mica。

## 4. 动效语言

目标是使操作因果可见，带来精致和轻快感；不通过增加等待时间制造仪式感。

| 场景 | 推荐表现 | 推荐时间 |
| --- | --- | --- |
| 按钮按下/释放 | 很轻的缩放、填充/明暗变化 | 100–160ms |
| 导航切换 | 选中背景平滑移动，内容短淡入 | 160–220ms |
| 账号切换 | 头像/选中标记连续过渡，账号标题同步更新 | 220–300ms |
| 详情抽屉 | 从对应侧滑入并淡入，轻微弹性 | 220–300ms |
| 点击注入并监听 | 真实状态步骤更新，连接中局部反馈 | 随实际状态，不伪造百分比 |
| 监听就绪 | 状态标记变化、一次短高光确认 | 250–400ms |
| 角色详情展开 | 头像与详细资料保持位置关联 | 250–350ms |
| 媒体结果到达 | 内容渐显，预留尺寸避免列表跳动 | 180–240ms |

同一画面同时只有 1–2 个主要运动焦点。页面轮询、SSE 更新不能反复触发整页入场。常驻在线状态使用静态标记；连接/任务进行中才使用必要循环反馈。

支持系统 prefers-reduced-motion 与应用“完整/轻量/关闭装饰动效”设置。缩到托盘、窗口隐藏或失焦时暂停非必要动画；不要因多 QQ 实例而线性增加背景动画开销。

动效可被打断，不锁定输入、不延迟危险动作生效、不假装任务已经完成。过渡期间输入焦点和当前账号归属必须明确。

## 5. 信息布局

桌面优先：左侧稳定导航，中央工作区，右侧按需打开详情抽屉。顶部持续显示当前账号/全局范围，防止在错误账号下改配置。

建议分组：

- 运行：实例与监听、会话、任务活动。
- 账号：角色、插件与 Skill、账号覆盖设置。
- 公用：角色/扩展资源、模型与媒体服务。
- 应用：设置、诊断。

全局服务配置与账号能力绑定分开；公用定义与账号启用状态分开。不要在首页堆满日志、指标和所有高级设置。

“注入并监听”为当前未接入实例的主操作；“停止监听”“暂停自动处理”“请求卸载”分别呈现，不以相似图标混淆。低频、影响更广的卸载放入明确标注的更多操作。

## 6. 先做三个样板

1. 实例管理：发现 QQ、未识别账号、注入中、等待登录、监听中、暂停、异常；验证手动操作和多账号身份。
2. 角色工作台：角色头像、角色卡、已启用 Skill 摘要、会话预览；世界书/长期记忆未实现时明确标识阶段。
3. 模型与媒体设置：服务列表、凭据状态、账号绑定、测试成功/失败、云端外发许可。

先做共用组件样板：按钮、输入框、选择器、状态标签、侧栏、抽屉、确认弹窗、Toast、空状态、加载/错误状态。所有样板可用模拟数据，不等同于真实 SnowLuma 或模型验收通过。

## 7. 设计交付与验收

- 交付设计 Token、组件状态、动效 Token、三页可交互样板和页面职责图。
- 至少展示无数据、加载、成功、失败、暂停/禁用及长文本状态。
- 三个账号切换时，当前身份始终清楚，未保存编辑不被静默丢弃。
- 1024×720、1280×800、1440×900 和 Windows 缩放下验证主要操作不被遮挡；窄窗口通过布局折叠处理。
- 键盘可操作，焦点可见，抽屉/弹窗退出后焦点合理返回。
- 减少动效模式下流程仍清楚，主要操作无需等待动画结束。
- 窗口隐藏时无装饰动画持续运行；目标硬件进行实际流畅性与资源检查，不能仅凭库选型承诺帧率。
- 样板通过后再推广到其余页面；不为换肤先替换现有后端、构建体系或全部组件库。
