# 模型配置工作区验收标准

2026-10-29。与[150开发方案](150-model-config-development-plan.md)配套。状态：**正式接入已实施，实现方自验见[153执行记录](153-model-config-workspace-execution.md)；以下仍需逐项独立验收，未执行项不能视为通过**。已有HTML候选的证据见[148](148-model-config-html-execution.md)/[149](149-model-config-html-independent-review.md)，不得据此勾选正式React或EXE验收。

## 1. 记录与环境

实施方记录命令、结果、实际文件／用例数、失败和修复；独立方单独执行并留文档。每项记录为通过／失败／未执行／不适用，未执行不能写通过。截图注明主题、可用CSS尺寸、缩放、运行方式（开发版、生产dist、Electron或发行包）及样例／真实服务。

默认用FakeChannel、fake-v1及隔离临时dataRoot，不调用真实QQ或付费模型。触发真实验证时仍遵循用户显式操作、原有费用提示与确认逻辑，不自动补测。接口fixture与生产页面必须分开，不能将固定成功响应当真实服务可用。

## 2. 入口、状态与兼容（MC-N）

| ID | 操作／前置 | 预期 |
| --- | --- | --- |
| MC-N01 | 从Dock、菜单、历史入口打开model-config | 路由仍有效；默认账号任务及当前合法账号保留，没有重复页标题或第二个Dock |
| MC-N02 | 点击“服务与模型”／“账号使用” | 两视图准确、名称与ARIA同步；不提交、不授权、不写业务配置 |
| MC-N03 | 服务草稿有修改后切到账号视图再返回 | 草稿和值保持；主题／面板变化不卸载其控制器 |
| MC-N04 | 设置→模型服务→打开工作区 | 只挂载一个可编辑服务状态来源；没有隐藏ModelsPage继续注册相同草稿ID；简易草稿和ProviderManager均迁移为正确的页面owner |
| MC-N05 | 测试`#/settings`、`#/models`及已有兼容入口 | 均能到达模型服务入口；history返回／取消保留原导航纪律，不形成重定向循环 |
| MC-N06 | 设置、账号或其他页面有未保存修改，再转接入口 | requestTransition覆盖实际将销毁的owner；取消留在原处，busy不绕过 |
| MC-N07 | 切主题、减少动效、providers刷新、SSE／轮询更新 | 无意外导航、换账号、清空输入、重新提交或整页重播 |
| MC-N08 | 关闭设置、刷新、返回、退出，含拒绝／响应丢失 | 继续沿用草稿和安全退出协议；单次准入、取消恢复、焦点正确 |

## 3. 服务、凭据与测试（MC-S）

| ID | 操作／前置 | 预期 |
| --- | --- | --- |
| MC-S01 | provider目录为空、读取中、失败或旧数据 | 五类入口仍可见；空态、重试、过期提示区分，不伪造已配置 |
| MC-S02 | 每能力有0、1、多个候选／既有settingsModels标记 | 初始化遵循现有确定性规则；歧义要求选择，不自动挑第一个 |
| MC-S03 | 切换五种能力、开关文本工具声明、调整音色／视频协议 | 字段归属正确；每能力草稿、baseline、结果与busy独立，未知适配器不静默丢弃 |
| MC-S04 | 有已存凭据，同origin保持／改path | 读取不返回明文；留空按现有规则保持，不把展示占位符当密钥提交 |
| MC-S05 | 修改到另一origin并尝试读取、测试、保存 | 按现有前后端边界拒绝带旧凭据请求；解释需要重填，旧密钥不外发 |
| MC-S06 | 新地址＋新密钥保存成功，之后留空再次测试 | 可复用该地址对应的真实服务凭据；不固定比较示例域名，输入密钥清空 |
| MC-S07 | 凭据库不可用、更新失败、服务被删除 | 明确错误并保留输入；不降级明文，不将未配置误报为可用 |
| MC-S08 | 获取模型成功、空数组、不支持、鉴权失败、超大响应、超时 | 展示真实结果并保留手动输入；不清空原模型，不自动测试或保存 |
| MC-S09 | 模型列表打开后改地址／来源或新请求先返回 | 旧列表不能应用于新草稿；关闭、取消和选择后焦点符合公共浮层契约 |
| MC-S10 | 测试当前草稿，检查HTTP 200＋result.ok=false | 展示业务失败，不误报成功；测试请求和保存请求严格分离 |
| MC-S11 | 云端／生成测试、账号能力测试 | 费用提示及既有confirmCost/useConfirm条件保留；取消不发请求；不向QQ发送 |
| MC-S12 | 测试超时、取消或返回结果未知 | 保留未知，不自动重提生成；后续只有显式操作会再次请求 |
| MC-S13 | 测试返回图片／语音sample或有detail | 沿用受限展示和必要错误信息；不出现真实密钥或伪造耗时数据 |
| MC-S14 | 保存单一能力，但同provider存在其他模型／参数 | 原服务其他能力、参数、标记和引用保持；新结果以真实响应为准 |
| MC-S15 | 打开高级服务管理，编辑URL、adapter、模型名、密钥；原数据预置限流／超时／重试／媒体与options | 现有可编辑项仍可达；未提供编辑UI的字段原样保留，不将它们误列为现成功能；简易与高级视图一致 |
| MC-S16 | 删除被多个账号引用的服务；另测清除凭据 | 服务删除先展示真实provider impact并确认；清除凭据沿用独立useConfirm，不冒用provider impact为凭据影响；保留现有引用清理、凭据共享与撤权行为 |

## 4. 账号策略与生效解释（MC-A）

| ID | 操作／前置 | 预期 |
| --- | --- | --- |
| MC-A01 | accounts／slots不同步、空账号或无效初始账号 | 使用真实身份集合与现有选择规则；加载、错误、离线区别明确 |
| MC-A02 | A账号脏草稿时切B，分别确认取消／继续 | 走policy对应准入；取消不换账号，允许后不将A结果写到B |
| MC-A03 | 撤销服务授权、能力仍保留绑定 | 选择与真实有效状态正确反映未授权；不隐式重新授权或换服务 |
| MC-A04 | 关闭能力、恢复能力、清除账号绑定，预置旧kind/conversation模型覆盖 | 关闭写账号capabilities[id]=false并保留必要绑定；未绑定不误报已禁用，旧模型覆盖仍不生效 |
| MC-A05 | 预置多服务、fallback、byKind、byConversation、skills、extensions及后端允许保留的扩展字段，再只改一个模型 | 完整策略往返无无关丢失；未显示的配置不被默认对象覆盖，保留旧字段不等于重新启用会话模型覆盖 |
| MC-A06 | 调整agent、云端媒体、跨服务回退、视觉模式 | 动作、保存及现有确认正确；暂停不关闭QQ连接，不隐式放开媒体上传 |
| MC-A07 | 账号策略保存成功但effective刷新失败 | 保存结果与生效读取结果分开说明；不推算出虚假“全部可用” |
| MC-A08 | 查询private/0、真实私聊、群聊、有现行策略作用域差异的会话 | 按给定会话展示真实来源与原因；缺省样本不代表所有会话，模型仍用账号级绑定；旧响应不污染新范围 |
| MC-A09 | dirty账号草稿下点击能力测试 | 明确使用已保存配置，要求先保存；不暗中保存当前输入 |
| MC-A10 | 真实后端拒绝授权／模型不支持／路由失效 | 呈现已有原因和下一步，配置选择不冒充执行权限或本轮实际调用 |

## 5. 并发、提交与恢复（MC-R）

必要竞态用可控制响应顺序的fixture验证，不能只用普通同步成功用例。

| ID | 竞态／故障 | 预期 |
| --- | --- | --- |
| MC-R01 | A请求慢、B请求快，之后A晚到 | 仅当前最新序号及目标的结果可显示 |
| MC-R02 | 获取／测试在途，检查字段锁定及外部目录／凭据变化；完成后改baseUrl、模型、协议或工具声明 | 相关字段按正式策略锁定；仍会失效的旧结果必须丢弃，busy结束不覆盖新草稿或新一轮busy，不要求照搬HTML的在途可编辑 |
| MC-R03 | 服务读取刷新中编辑草稿，目录随后返回 | 只更新合法baseline／来源提示，不把草稿替换为旧值 |
| MC-R04 | 两能力共享同一provider并连续保存 | UI防止冲突或安全串行；第二次基于最新服务，不清除第一次保存的其他能力 |
| MC-R05 | 账号／能力／页签切换时前一请求完成 | 响应、错误、反馈、样例媒体及焦点只归属原目标 |
| MC-R06 | 保存已提交，但响应丢失或读取确认失败 | 不自动重提、不误盖成功章；草稿保留、结果待确认，可显式读取比对 |
| MC-R07 | 连点保存、测试或获取列表 | 不重复提交相同在途操作；按钮宽度和焦点稳定，仅锁定相关范围 |
| MC-R08 | 页面卸载、设置转接、退出过程中迟到响应 | 不重新挂载、不迟到写UI／draft；已提交写入不假称回滚 |
| MC-R09 | 服务被外部修改／删除或凭据版本变化 | 保留脏草稿，明确来源失效；不能用本地generation冒充服务器CAS |

## 6. 双主题、布局和无障碍（MC-V）

两主题分别检查default、hover、focus-visible、pressed、disabled、loading、error、success，以及selected/expanded组合。选择器、对话框、结果媒体、确认队列与Portal都在实际作用域下验证。

| ID | 检查 | 预期 |
| --- | --- | --- |
| MC-V01 | 1440×900、1280×800、1024×720 | 根无额外滚动／横向溢出；业务内容独立滚动，Dock不遮字段和主操作 |
| MC-V02 | 768×900、414×896、375×812、320×740及短窗口 | 必要字段、错误和按钮滚动可达；能力列表有明确可滚动性，不压成装饰小字 |
| MC-V03 | 长服务ID、超长URL／模型、长错误、多候选 | 正确换行／局部滚动／截断加完整信息入口；主动作和错误关键部分不裁切 |
| MC-V04 | 主题切换、快速反向、冷加载、回读偏好 | 不丢草稿／光标／路由，不新增业务请求；当前编辑器不重建 |
| MC-V05 | 系统reduced、应用reduced、局部scope、快速中断 | 公共策略下限正确；没有局部full解除祖先reduced；切外观不重播页面 |
| MC-V06 | 保存成功／业务失败／未知，快速连续操作 | 只有确认成功触发公共落款；失败与未知保留准确文字，焦点立即可见 |
| MC-V07 | 实际背景、hover、禁用、浮层与focus组合 | 普通文字目标≥4.5:1，必要边界／图标／焦点≥3:1；不统一降透明度 |
| MC-V08 | Tab/Shift+Tab、方向键、Home/End、Enter/Space、Esc | 顺序合理；tablist完整；dialog陷阱、取消及返回焦点正确；无隐藏面板可交互控件 |
| MC-V09 | 字段label、hint/error、API Key显隐、状态播报 | 可访问名称及关联准确；新错误可理解，无不必要整页live播报 |
| MC-V10 | 强制颜色、系统字体放大、Windows 125%／150%原生缩放 | 状态形状、焦点、操作仍可辨；网页CSS尺寸检查与原生缩放证据分开 |

## 7. 检查命令与测试落点

正式实施应根据实际变更补必要用例，不为纯视觉改动机械增加镜像测试。至少保留以下入口对应的已有回归；新测试名称可调整，但职责要可追溯：

| 现有位置 | 关注点 |
| --- | --- |
| `test/model-setup.test.ts` | 简易模型保存、发现、验证、来源与同服务其他模型保留 |
| `test/provider-manager.test.tsx`、`provider-management.test.ts`、`provider-impact.test.ts` | 高级维护、凭据、删除影响与账户关联 |
| `test/phase1-policy.test.ts`及实际覆盖策略的相关用例 | 账号授权、能力路由与保存兼容 |
| `test/settings-navigation.test.tsx` | 旧入口、设置关闭、工作区转接与草稿准入 |
| `test/renderer-quit.test.tsx` | 退出锁定、取消、最终响应丢失和输入保护 |
| `test/character-tokens.test.ts`、`ui-library-contract.test.ts` | token链、生成同步与公共基础控件归属 |
| 新工作区定向用例／独立浏览器探针 | 跨能力／账号迟到、共享provider、保存响应未知、真实DOM焦点与布局 |

在相应阶段执行并保留完整结果：

```bash
npm run ui:tokens:check
npm run typecheck
npm test
npm run desktop:build
git diff --check
```

有token变更先运行`npm run ui:tokens`；没有token变更不手动触碰生成文件。模型／策略接口若实际改动，先更新150的范围与兼容决策，不能以页面迁移名义悄悄改变公开契约。

真实页面至少检查开发版与生产dist两种运行方式。自动化失败要保留原始日志和原因；重试通过后也记录前一次失败，不能只抄历史全绿数字。

## 8. 交付与收口

每个MC工作包留实施记录；最终独立复核按ID列出结论与必要修复复验。记录须包含：变更文件、完成范围、测试命令与数字、双主题截图、未执行的真实服务／原生／发行项目，以及用户是否已采用此设计。

阻塞项示例：密钥串源、账号错写、草稿丢失、测试成功隐式保存、丢失现有策略字段、未知生成自动重试、重复服务编辑器或退出准入绕过。这些未关闭不能宣称完成。

全部本地检查通过后，可声明“模型工作区在本次自动化和实际页面范围完成”；只有实际构建并验证发行包，才可声明已接入对应EXE。源码、dist、已运行进程与旧发行EXE的状态必须分别说明。
