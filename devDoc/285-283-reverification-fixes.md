# 285 283 第 4 节复验问题修复

2026-11-12。按 [283 第 4 节复验](283-278-workflow-simplification-independent-review.md#4-284-修复独立复验) 修复 284 之后仍存在的六项问题。R04、R06、R08 在该轮复验中通过，本轮未改动。本文为实现方自验记录，复验条件仍由独立复核确认。283 第 5 节复验后的补修见 [286](286-283-reverification-fixes.md)。

## 1. 修复内容

| 编号 | 修复 |
| --- | --- |
| R01 后台记忆调用 | 记忆运行时新增 `isBusy`、`onIdle`：队列运行中或仍有排队触发都算角色在途工作；角色活动判定、停止确认与模型维护等待都计入该状态。维护开始时已发出的整理调用（含同一批后续模型调用）会先结算，整批结束后才确认停止并写入新地址；仍在维护窗口内开始的新调用继续在入口暂缓，维护结束后的唤醒会重查待处理触发。 |
| R02 旧等待提示 | 等待状态记录原消息标识。收到本窗口 `execution_started` 且触发类型为用户消息、消息集合包含原消息时才清除「等待处理」提示；其他窗口与自主消息不会提前清除。 |
| R03 连接收尾 | 已终结任务只要留着开启的续用记录并且发出过工具调用，就继续计入资源占用，直到结果结算与连接收尾完成关闭记录。仍有后台工具在途时不再关闭任务目录；最后一个工具结算后再关闭目录，目录关闭完成后才释放资源。 |
| R05 暂停超时名单 | 暂停协调分别记录「已确认停止」与「仍在等待」的角色。多角色暂停超时或后续失败时，`ROLES_NOT_STOPPED` 错误详情携带本次已停止名单；维护路由把它并入 `maintenance.pausedRoleIds`，模型详情可原处恢复已停止角色。 |
| R07 恢复按钮 | 对话页的恢复入口条件加入「发送被拒绝」状态；进入页面后才停止的角色被拒绝发送时，同样显示「恢复活动」，保留角色、窗口与草稿，恢复后由用户重新提交未入库的消息。 |
| R09 导入失败原因 | 按套保存导入失败原因；列表刷新会清空通用错误，但每套失败原因保留在预览项上，重试成功后才清除。部分失败时通用提示说明「再次确认只重试未成功的套」。 |
