# 世界书基础阶段方案

日期：2026-10-23。目标是让角色卡所带的世界书按会话、按关键词和预算参与上下文。此阶段不实现长期记忆、独立世界书资源管理、在线条目编辑、正则/递归/概率触发。

## 1. 数据与启用

规范化世界书作为role-card manifest的可选worldbook字段，随角色卡revision保存。书包含version=1、可选name、scanDepth（0～20）、budgetChars（0～8000）和最多200个条目。条目声明id、keys、content、enabled、constant、caseSensitive、priority和before-role/after-role位置。

酒馆character_book可以转换支持的基础字段；不支持的条目规则禁用或跳过并提示，不能误转成常驻条目，原文件继续归档。manifest本身的worldbook使用严格schema校验。旧角色卡没有此字段仍按原链路工作。

每个账号的每个群聊/私聊角色绑定增加独立worldbook配置：enabled、scanDepth、budgetChars。默认关闭，不因导入或部署开启；重新绑定角色默认重置为关闭。通过专用接口更新配置，保留原roleCard，并用expectedRevision检查冲突、在同一Store串行域内读改写。配置变化增加绑定revision，使旧轮回复被现有角色校验拒绝。

## 2. 触发与预算

实施补充：世界书设置变更使用新的绑定revision校验旧回复，但沿用同角色的contextRevision历史命名空间；修改扫描参数不清空历史，重新绑定角色仍重置历史隔离边界。

只扫描当前会话的当前文本和最近N条历史文本；scanDepth=0仅当前文本。匹配为字面子串、关键词OR，可按条目区分大小写；constant为常驻条目。不执行正则、宏、脚本，也不以命中条目的内容继续递归触发。

按priority降序和原始顺序稳定选择；整条放入，超预算跳过并继续考虑后续条目。书分节标题、条目间分隔和上下文join分隔均计入预算。世界书不能超出本轮扣除系统基础文本与当前消息后的剩余字符空间；剩余空间再用于原有历史。这里是字符预算，不冒充模型token计数。

## 3. 用户入口

实施补充：单次扫描最多16000个UTF-16字符，优先当前文本尾部，再扫描最近历史尾部；关键词比较工作计费上限800万，复用完整匹配结果。触及上限返回scanLimited；计算量不足而无法完成判断的条目返回unscannedIds，不混入预算不足的skippedIds。零预算、未开启或没有启用条目直接返回。扫描截断意味着更早的关键词可能不参与触发，不保证完整酒馆语义。

在“资料与角色”的每个已有会话绑定中提供“世界书设置”，使用公共Modal/表单控件。可启用、调整扫描与字符预算，展示当前角色卡条目数；没有条目时说明需导入包含世界书的新角色版本。

提供关键词触发测试，输入示例文本，按已保存配置计算选中/超预算条目和实际使用字符；不调用模型、不发送QQ、不写记忆，也不读取真实聊天历史。未保存草稿、切换账号、离开页面、请求中和退出锁遵守现有公共保护。

## 4. 验收

1. 旧卡/未开启/未绑定会话不注入；启用仅影响指定账号、群聊或私聊。
2. 当前文本与限定历史可命中；大小写、常驻、禁用、稳定顺序、非递归和整条预算有自动测试。
3. 世界书文本和分隔符总增量不超过预算；本轮基础文本已满时无世界书增量。
4. 导入与部署仍不自动启用；不支持的酒馆触发规则有提示且不错误常驻。
5. 旧版本配置提交409，保留用户草稿；同账号并发不同会话更新不丢失。
6. 测试接口有鉴权、只读；前端busy/dirty/退出锁有效。原生窗口实机限制另行披露。
