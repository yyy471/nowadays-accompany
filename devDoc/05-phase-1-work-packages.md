日期：2026-10-22

## 2. 推荐推进次序

### 里程碑 A：共同契约

先完成 P1-01。至少用两份配置样例与假服务调用记录走查：

- A 使用本地纯文本模型 + 云端识图/视频/生图；B 使用不同绑定。
- 两个账号共用服务但配额与上下文不混用；群聊禁用生图。

同时定下首批真实服务和模型，记录协议；供应商尚未选定不阻止隔离/路由开发，但阻止相应适配器和真实验收完成。

### 里程碑 B：最小纵向闭环

完成单账号内置文本回复与双账号隔离，再打通“非视觉 chat + 外部识图”。通过 Core/API/设置页面的真实链路，不只完成独立模块。

P1-02、03、04 与 P1-05/06 可按接口分工推进；不要绕过 P1-01 各自定义配置格式。

### 里程碑 C：媒体与策略闭环

完成异步视频、生图、会话作用域、取消、重启状态和凭据保护。媒体任务由独立队列执行，返回结果仍经过会话队列与统一发送出口。

### 里程碑 D：实际环境验收

完成 UI、迁移、真实 QQ/模型验证和打包。按 04 清单交付；模拟与真实结果分别标识。

## 3. 各开发任务的共同要求

- 提交与工作包相关的有意义测试；避免用“UI 出现按钮”“配置能保存”代替端到端生效。
- 不在模块顶层引入可变全局注册表；通过 Core 依赖注入。
- 不直接绕过 QqInstance.send 发送，不从插件读取原始密钥，不跨账号读取私有文件。
- 不为并发简单删除现有账号串行链后继续共享可变状态。
- 不改变旧配置语义而不迁移；不在原目录覆盖旧版本制品。
- 不把 launch、完整酒馆兼容、长期记忆质量混入本阶段必交范围。
- 新增能力不是服务连接测试成功即完成：必须通过路由、账号作用域、取消和结果发送的实际链路。

## 4. 建议责任边界

- 核心开发：P1-02/03，负责 instance/Core 生命周期集成。
- 能力与模型开发：P1-05/07，负责服务协议、限流与凭据；与媒体开发共用 Adapter 契约。
- 扩展与媒体开发：P1-04/06，负责作用域、Skill、任务与媒体归属。
- Agent/UI 开发：P1-08/09，负责用户配置到实际行为的闭环。
- 集成负责人：P1-01/10，负责契约定稿、共同文件合并和验收证据。

人数不足时可合并职责；以上没有要求必须多人同时开发，也不承诺具体工期。先估算适配器与真实测试条件，再排开发时间。

## 5. 第一阶段结束后再讨论

下一阶段重点：角色卡导入兼容范围、世界书触发与预算、记忆提取/检索/修正、人格关系与情绪状态，以及受管 QQ launch。按独立方案安排，不因预留接口就视为已实现。
