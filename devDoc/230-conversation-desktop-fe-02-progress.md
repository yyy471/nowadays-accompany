# 230 桌面对话 FE-02 接入进展

2026-11-09，`dev-front` 工作树。接续 [225](225-conversation-desktop-development-guide.md) 和 [229](229-conversation-desktop-fe-01-record.md) 的前端工作。本记录为实现方进展与自验，FE-02 尚未收口。

## 接入与本轮补修

- 工作树已有窗口列表、消息快照与游标、SSE、真实消息提交、句段演出、按句语音和手动过场图任务接入。
- 输入时向当前角色与窗口发送输入状态；连续输入续期，停输一秒退出，切换窗口或离开时有序清理在途状态。
- 发送响应尚未返回时暂存 SSE 事件，以已确认的用户消息 ID 认领执行，避免其他执行的事件被错误归入当前轮。角色或窗口切换后，晚到的发送和生图结果不更新当前页面。
- 加入按窗口向前加载消息和滚动锚点保持；不同角色与窗口的未发送草稿分别保留。发送失败恢复草稿，相同内容重试沿用原提交 ID。后端返回重复提交时，从原游标重新订阅，恢复可能已消费的执行事件。
- 推进到动作段时取消尚未开始的自动语音，已开始播放的语音继续；用户消息不参与语音预取，合成缓存键包含文本。
- 当时历史面板仅检索已加载消息；本条的后续改进见第 4 节。

## 本机自验

- Node 24.22.2，桌面 `npm test` 48／48 通过，包含 2 项输入状态顺序测试。渲染器 `npm run typecheck`、`npm run build` 通过。构建出现既有 API 同时静态／动态导入的提示。
- 隔离 Electron 使用本机假 HTTP／SSE 服务验证：输入状态 `true → false`；发送失败后恢复原草稿且重试提交 ID 相同；插入无关执行后，让目标执行的首段和完成事件先于发送响应到达，仍归到正确轮次并在单句显示后恢复输入；浏览器异常 0。
- 补充「已提交但响应丢失」：假服务先发布完成事件再返回失败，重试返回重复提交；客户端复用原提交 ID、重订阅原游标并恢复回复终态，输入框恢复。
- 另用假服务验证加载更早消息及两个窗口的草稿隔离。以上验证使用已有本机 Electron 运行时，不代表干净安装或正式桌面包验收。
- 使用独立临时目录启动实际本地后端，注入脚本化离线模型并从 Electron 发送消息。SSE 驱动首句、动作和末句逐段呈现，末句后输入框恢复；数据库保存 1 条用户消息、1 条完整角色回复和 3 个句段，模型调用 1 次，浏览器异常 0。

## 4. 继续补修：历史、舞台与语音竞态

- 历史面板打开后通过现有窗口消息分页依次读取该窗口的已保存记录，展示读取进度和失败重试；搜索结果按真实消息／句段定位，未加载到对话栏的结果先向前补页再定位，关闭面板或切换窗口时取消后台读取。缺少句段的早期角色消息保留原文，不提供无法使用的逐句语音或生图入口。
- 本方案复用现有分页接口在客户端统计日期和检索，没有新增 225 所列的服务端窗口级统计与关键词查询。历史很多时需要逐页读取并驻留内存，性能和大数据量尚未验收；专用接口及其独立验证仍是后续工作。
- 舞台回看服饰按保存的句段选择，差分只从同轮当前及更早句段回退；图片解码晚到不会覆盖更新的选择，双缓冲保留旧图以支持淡入淡出。过场图缺少起止锚点时不自动落到其他句段，较旧的分页快照不能把同次尝试的终态任务回退到生成中。
- 语音预取随角色和窗口变化重新判断；已离开窗口的请求失败不再显示旧错误，旧请求结束也不会清除新窗口的同键在途请求。
