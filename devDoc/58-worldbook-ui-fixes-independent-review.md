## 2. 新发现：P2 取消退出后详情加载提示无法恢复

位置：desktop/renderer/src/components/WorldbookSettings.tsx，依赖identity/visible/locked/disabled的失效effect、loadDetail及其finally。

上述effect增加detailSequence以拒绝旧响应，但不清除detailBusy，也不在恢复可操作状态时重新请求。原请求finally只在ticket仍匹配时清除busy，因此被作废的请求永远无法完成加载状态。

已复现：

1. 打开已选独立书的设置，指定版本详情保持慢请求。
2. locked变true（进入退出确认），然后变false（取消退出）。
3. 原详情请求成功返回，但ticket已失效，结果和finally均被忽略。
4. 弹窗仍显示“正在读取指定版本…”，请求已结束却不消失。

这不会造成跨账号写入或改变已保存来源；重新选择版本/关闭重开可以恢复，所以定为P2，不能重新打开已关闭的R1～R4。但它影响退出取消后的明确状态反馈，需要在世界书完整UI验收前修复。

建议修法：作废详情请求时同时结束其展示加载状态；恢复后如需详情，按当前来源显式启动新ticket。清理必须由请求所有权控制，不能让旧finally清除后来新请求的busy。不要仅在finally去掉序号检查，否则引入新的竞态。

新增正式回归应覆盖：详情慢请求→锁定→取消→旧请求返回；隐藏/身份变化同类失效；新请求已启动后旧响应不能清除新busy。断言旧内容不回填、加载状态正确结束或由新请求接管。
