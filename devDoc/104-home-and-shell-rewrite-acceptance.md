# 主页与全局菜单重写：验收标准

后续修订：首页范围已按用户截图调整，顶部账号栏、首页开关和绑定摘要不再是当前验收要求。当前一屏布局及两套昼夜预置以 [108](108-home-presets-refinement-plan.md)、[109](109-home-presets-refinement-execution.md) 为准，以下保留原始第一批标准。

日期：2026-10-27。执行方案见 [103](103-home-and-shell-rewrite-plan.md)，视觉基准见 [DESIGN.md](../DESIGN.md)。本批实现及自动化验收证据见 [107](107-home-and-shell-implementation-review.md)，涵盖19组主页检查、17组组件检查、类型检查、全量测试与桌面构建。真实QQ/服务、真实托盘及发行包验收仍另行执行；125%为隔离进程渲染检查，未改变OS缩放。下文保留完整验收标准，不据自动化结果宣称所有现场项通过。

字体、控件尺寸、状态、布局和动效按 [105 前端总体设计规范](105-frontend-design-system.md) 与 [tokens.json](design/character-studio/tokens.json) 验收。实际公共UI组件样板已完成，结果见 [106](106-ui-foundation-and-workbench-review.md)；这不能替代下述正式主页、真实账号与全局菜单的整体验收。

## 1. 放行条件

第一批完成后必须同时满足：

1. 正式前端的主页与菜单达到已认可设计稿，而不是打开独立设计 HTML。
2. 真实账号、运行状态和明确的 Agent 操作已经接通，演示数据未混入业务。
3. 九个功能入口仍可用，未迁移页、草稿、设置和退出流程未被新壳破坏。
4. 已迁移旧 UI 被实际移除，主题与样式没有双套竞争，验证证据齐全。

| 编号 | 场景 | 通过标准 |

## 3. 主页数据与动作

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| D01 | 首次加载 | 账号、连接、Agent和绑定各自有明确读取状态；不先闪出空账号或“已开启”假状态 |
| D02 | 确实无账号 | 给出前往实例/连接的入口；不自动启动 QQ 或 SnowLuma，不显示模拟账号 |
| D03 | 首次查询失败 | 错误与重试可见；不显示“还没有账号” |
| D04 | 有缓存后刷新失败 | 可保留旧数据但必须标明过期/更新失败，不伪装成当前就绪快照 |
| D05 | 昵称、头像和签名 | 沿用现有身份优先级与头像管线；昵称缺失、头像失败、空签名均有稳定回退；不写成 PID 或 QQ0 |
| D06 | 账号 A/B 快速切换 | A 的慢响应不能覆盖 B；资料、绑定、开关和忙碌态不串号 |
| D07 | 当前账号移除 | 有明确不可用状态；不会把旧操作自动提交给下一个账号 |
| D08 | Agent暂停/恢复成功 | 只有用户点击才写；请求绑定正确 accountId；最终状态取服务端确认 |
| D09 | Agent写失败或超时 | 不冒称成功；错误原因和重新读取/重试可见；未知结果先核对状态，避免盲目重复 |
| D10 | QQ离线或条件不齐 | 配置开启与实际可回复性分开表达；不能用开关开启代替所有目标就绪 |
| D11 | 暂停动作 | 不调用实例 stop、QQ注入/卸载或消息发送；连接状态不被UI主动伪造改变 |
| D12 | 绑定摘要 | 使用当前账号真实绑定；查询失败不当“未绑定”；群号与QQ号相同不混淆kind |
| D13 | 摘要进入角色页 | 目标账号和完整会话键正确；不能进入账号B或错误的同号群/私聊 |
| D14 | 主题插画 | 标明展示主题；没有真实映射时不声称运行角色、当前绑定资源或真实对话 |
| D15 | 普通浏览 | 切页、切账号、打开菜单、展示主题不保存配置、不发消息、不调用模型或付费媒体 |

## 4. 导航、草稿与原生行为

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| N01 | Dock四入口与更多 | 当前页高亮正确，九个有效功能均可到达；未迁移页继续真实工作 |
| N02 | 顶部菜单、快捷入口、程序跳转 | 进入同一导航准入，不绕开现有草稿保护 |
| N03 | 脏表单后切页/切账号，取消 | 页面、URL、账号、草稿、滚动位置和焦点保持原上下文 |
| N04 | 脏表单后确认离开 | 只丢弃明确范围的本地草稿；不自动保存，不重复弹窗或重复跳转 |
| N05 | 保存中离开 | 按现有busy准入阻止会丢失上下文的动作，说明原因；请求完成后不自动重放过期动作 |
| N06 | hash、前进后退、旧链接 | 深链接和历史补偿正确；不出现URL已切而内容未切、重复确认或事件循环 |
| N07 | 设置关闭/遮罩/Esc | 共用原有关闭准入；取消保护时设置与底层草稿仍在 |
| N08 | 窗口X与托盘退出 | 隐藏保留草稿；正常退出经既有退出协议，确认前不先停止Core；迟到确认不误放行 |
| N09 | 菜单焦点 | 键盘可完整访问，Esc关闭、焦点返回；嵌套确认不失去焦点或触发背景操作 |
| N10 | 账号与页面导航 | 两类控件语义分开；当前账号/当前页可被辅助技术识别；账号长列表可键盘访问 |

## 5. 工程与清理

- 新主页使用 React/TypeScript 与现有 API/契约，不能以 iframe 嵌入原型，也不能复制模拟服务替代真实接入。
- 所有基础交互控件从现有 `ui` 稳定入口导入，公共 UI 契约测试继续有效；不另建重复 Modal/Confirm/系统 confirm 流程。
- 原有账号头像、草稿登记、导航、鉴权、事件重连与桌面桥得到复用或等价承接，不能仅凭页面能打开就认为迁移完整。
- 新主题隔离，未迁移旧页面不受全局颜色/布局重置污染；不在巨大 styles.css 尾部叠加多轮覆盖维持效果。
- 删除前确认旧Home/旧壳样式无剩余调用，删除后检查 import、历史路由与失效链接。API、类型、公共UI和保护机制不因“重写前端”被清空。
- 不修改后端运行规则或数据schema，不删除用户数据，不把历史文档或设计样例打包为业务页面。
- 记录素材尺寸与包体影响；保留透明边缘、原画比例与布局空间；减少动态效果时无持续跟随动画。

## 6. 验证与交付证据

1. 基线：记录实施前状态、未提交改动、已知失败和实际删除清单。
2. 定向测试：展示模型映射、账号迟到响应、Agent请求归属、导航与草稿真实调用路径、公共UI契约。
3. 工程检查：核对并运行现有类型检查、桌面构建及相关测试；已有文档中的命令包括 `npm run typecheck`、`npm run desktop:build`、`npm test`，正式执行前确认当前脚本。结果如实记录，不复制历史通过数字。
4. 浏览器：使用隔离数据覆盖空、慢、失败、过期、离线、多账号与长文本，提供实际新前端截图及关键状态证据。
5. Electron：单独记录真实窗口、托盘、退出确认与125%缩放结果；无法执行的项目列为待验收。
6. 最终交付：新增/修改/删除文件，三种桌面尺寸截图，测试结果，原生验证结果，剩余事项和下一页迁移建议。

上线或覆盖发行包不在本清单的自动动作中。界面通过与真实QQ/付费服务联调通过分别记录，不用一项代替另一项。
