## AD-R01 · P2 · 并发删除可以删到只剩零个角色

准备两个已停止角色，让第一个 DELETE 在运行时收尾等待时提交另一个角色的 DELETE。两个请求都选择保留历史，结果均返回 200，`GET /v1/roles` 返回 0 个角色。当前在等待运行时收尾前检查角色数，之后写事务未复验。最后一个角色的检查应与移除索引处于同一事务，复验时应有一个请求返回 409 `LAST_ROLE_REQUIRED`，并保留对应角色。 [删除服务](../backend/src/application/role-deletion-service.ts#L55) · [DL-148](161-digital-life-direction-decisions.md#dl-148-配置修改直接删除与运行限制)

## AD-R02 · P2 · 未传历史选择也会删除历史数据

对可删除的已停止角色调用 `DELETE /v1/roles/:roleId`，省略 `keepHistory`。接口返回 200 和 `keepHistory=false`，角色详情返回 404，业务库文件已删除。DL-148 要求由用户选择是否保留历史。首次删除应要求明确传值，缺失或无效时返回 400，保留角色索引与目录。 [删除路由](../backend/src/http/routes.ts#L139)

## AD-R03 · P2 · 角色已删除，清理记录写入失败却返回 500

临时库只阻止删除 `role_deletions` 中的记录。选择一并清理后，角色索引和目录已删除，待清理记录保留，但首次 DELETE 和故障期间重试都返回 500 `INTERNAL_ERROR`。移除故障后重试返回 200。角色删除已提交后，清理记录删除失败应保留重试依据，并按实际删除结果响应。可对照第二包已复验的同类行为。 [角色清理收尾](../backend/src/application/role-deletion-service.ts#L98) · [第二包复验](258-resource-management-independent-review.md#259-第-8-节补修独立复验)

## AD-R04 · P2 · 旧图清理失败会使新主页立绘无法读取

上传一套含主页立绘的服饰，旧图未被历史句段引用。注入故障只阻止旧素材行的清理，再上传新立绘。替换返回 500，服饰列表已经指向新立绘，读取新图返回 404，旧图仍可读取。立绘切换事务已提交，后续清理异常进入上传失败处理，删除了新图文件。应让新图写入、当前立绘指向和成功响应保持一致。旧图清理失败应可延后处理，或在替换提交前完整回滚。 [替换服务](../backend/src/application/appearance-service.ts#L185) · [替换事务](../backend/src/storage/appearance-store.ts#L252)

分别让主页立绘补传和单张差分上传在图片解码期间等待，同时通过 HTTP 删除同一服饰，保留另一套。DELETE 先返回 200。放行解码后，两类上传都返回 201，各自在已删除服饰下新增一条未标记删除的素材。服饰列表已隐藏该服饰，素材仍能按 ID 读取。上传只在异步解码前校验服饰，入库时未重验删除状态。应在提交素材的同一事务中校验服饰仍有效，并在拒绝后清理本次写入的受管文件。 [差分上传](../backend/src/application/appearance-service.ts#L121) · [主页立绘替换](../backend/src/application/appearance-service.ts#L185)

### AD-R06 · P2 · 角色删除后在途上传仍会写入角色目录
