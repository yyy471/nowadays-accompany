# 第一阶段验收标准

日期：2026-10-22

关联方案：03-phase-1-optimization-plan.md。以下为必须完成的验收清单，不是当前测试结果。

## 1. 验收方法与条件

- A：自动化测试，使用可控制延迟/错误的假服务，断言调用记录、归属和状态，不依赖付费 API。
- I：本地集成测试，串起 Core、API、宿主、队列、HTTP 假服务和持久化，不只测单个函数。
- M：人工真实集成，使用桌面程序、至少两个不同 QQ 账号和实际模型服务。
- 既有 94 项测试是此前检查基线；本阶段回归以实际测试总数与结果报告为准。
- 真实端点需为 chat、image.understand、video.understand、image.generate 各提供一个经过验证的实现；端点可以复用。至少覆盖一个本地与一个云端服务。
- 单机多账号数量先以 2 个完成必选验收，再以可配置上限验证容量；不要求制造无业务意义的大量真实 QQ 登录。

## 2. 多实例与数据隔离

| 编号 | 类型 | 操作 | 通过标准 |
| --- | --- | --- | --- |
| ISO-01 | A/I | A、B 使用相同 peerId 和 messageId 收发 | 历史、去重、上下文、任务、媒体按账号区分，互不吞消息 |
| ISO-02 | I/M | 分别启动、停止、重连两个账号 | 停 A 不改变 B 身份，不中断 B 正常收发 |
| ISO-03 | A/I | 让同一 Core 两个槽位绑定同一账号 | 第二个明确失败，既有会话仍可工作 |
| ISO-04 | I | 运行时返回与配置不符的 selfId | 拒绝绑定，不启动该账号 Agent，不写入另一账号历史 |
| ISO-05 | I | 槽位从 A 重绑定 B，A 的媒体调用晚到 | 结果不能发给 B，不能写 B 状态/媒体/记忆 |
| ISO-06 | I | A 请求读取 B 的媒体/任务/历史 ID | 控制 API 和能力代理拒绝，不泄露内容 |
| ISO-07 | I | A、B 启用同一公用插件并写状态 | 制品代码可共用，状态与配置分别保存 |
| ISO-08 | I | 公用/私有资源同 id 同时存在 | 按 source+kind+id 解析，不发生状态串用 |
| ISO-09 | M | 两个真实 QQ 的私聊和群聊互相交错 | UI 身份、响应目标、保存位置均正确；保留脱敏记录 |

## 3. 消息并发与生命周期

使用屏障/可控制 Promise 观察实际启动与完成，不以容易抖动的短耗时阈值证明并发。

| 编号 | 类型 | 操作 | 通过标准 |
| --- | --- | --- | --- |
| CON-01 | A/I | 同会话连续提交三条输入 | turn 有序，回复归属正确；有合并时可追溯原消息 |
| CON-02 | I | 会话 A 模型请求挂起，再向会话 B 发消息；并发设 2 | B 在 A 释放屏障前完成，A/B 上下文不混用 |
| CON-03 | I | 同群多人连续发言 | 按群会话有序，senderId 保留，不误当多段私聊 |
| CON-04 | I | 视频任务挂起，再发文字消息 | 媒体队列与文字队列分开，文字请求正常完成 |
| CON-05 | A/I | 同时超过账号、全局、服务上限 | 实际并发不越界，排队有上限，满时返回明确错误 |
| CON-06 | I | 多个并行调用修改共享插件状态 | 无丢更新；冲突由事务/CAS/串行资源机制处理 |
| CON-07 | I | 兼容 v1 插件慢执行，同时另会话走现代 Agent | 不出现现代请求全部被账号级旧链阻塞；兼容限制可诊断 |
| CON-08 | I | stop/rebind 时有排队和在途请求 | 排队取消，在途取消或作废，晚到结果不发送 |
| CON-09 | I | 只改插件配置，触发重载 | 配置指纹改变；新配置生效；旧 hostEpoch 写入拒绝 |

## 4. 作用域与扩展

| 编号 | 类型 | 操作 | 通过标准 |
| --- | --- | --- | --- |
| POL-01 | A/I | 私聊启用生图，群聊禁用 | 私聊可用；群聊工具列表、Hook 分发、直接调用均遵守禁用 |
| POL-02 | I | 特定群覆盖普通开关，但请求未授权服务 | 普通覆盖有效；账号硬授权不能被覆盖 |
| POL-03 | I | 插件伪造 accountId/providerId 调能力 | 使用宿主绑定身份，越权失败且可审计 |
| POL-04 | I | 插件被禁用后仍有在途回调 | 新调用拒绝，在途按取消规则处理，不残留可调用工具 |
| POL-05 | I | Skill 引用未授权/缺失工具 | 明确不可用原因，不能通过说明文本绕过授权 |
| POL-06 | I | 使用同一人格公用定义分别聊天 | A 的经历不自动进入 B；私聊观察不自动进入群聊 |
| POL-07 | I | 旧插件与内置 Agent 均可能回复 | 按显式兼容模式只有预期回复者，不覆盖或重复答复 |

## 5. API 配置与路由

| 编号 | 类型 | 操作 | 通过标准 |
| --- | --- | --- | --- |
| API-01 | A/I | 配四项能力到不同假服务，分别触发 | 每项请求到正确端点/模型；输入输出匹配能力 |
| API-02 | I | 文本模型收到图片消息，配置外部识图 | 图片只交给授权识图服务；对话模型得到带来源观察，不收到不支持的图片字段 |
| API-03 | I | direct 视觉模式下禁用图片理解 | 不发起外部识图，也不将图片直接传给 chat |
| API-04 | I | 视频理解服务提交后多次 pending 再完成 | 正确轮询，次数/时长受限，结果回到原请求会话 |
| API-05 | I | 未配视频服务或未启用抽帧回退 | 明确缺少能力，不假装看过视频，不静默抽帧外发 |
| API-06 | I | 不支持工具调用的文本模型，执行显式生图 | 内置动作仍能调用生图并经统一出口发送图片 |
| API-07 | I | 识图失败或未配置，随后发送纯文字 | 媒体局部失败，文字仍可用，QQ 不被标为离线 |
| API-08 | A/I | 配无 Key 本地服务及带 Key 云端服务 | 两者均可验证调用；鉴权按适配器要求处理 |
| API-09 | I | A/B 绑定不同服务，或共用同一服务 | 绑定、预算独立；共用端点实际并发限额仍统一 |
| API-10 | I | 本地服务失败，云端在候选列表但回退未授权 | 不向云端发送内容；授权后也只在兼容能力内回退 |
| API-11 | I | 服务返回 401、429、超时、非法 JSON | 稳定错误分类；退避有界；禁止无限重试 |
| API-12 | I | 生图提交结果未知后重启或重试 | 标记未知/中断；未确认幂等能力时不自动重复付费提交 |
| API-13 | A/I | 本地取消不支持远端取消的服务 | UI 标明本地取消/远端未知，晚到结果不能触发发送 |
| API-14 | M | 实际服务分别完成四项能力 | 记录服务、模型、适配器版本、输入样例、脱敏结果与限制 |
| API-15 | M | 至少一个本地、一个云端实际接入 | 保存并重启后配置仍可用；不是仅探测端口成功 |

## 6. 媒体、任务与凭据

| 编号 | 类型 | 操作 | 通过标准 |
| --- | --- | --- | --- |
| MED-01 | A/I | 大文件、错误类型、失效 URL、受限重定向 | 下载有界、错误明确，不绕过媒体网络策略 |
| MED-02 | I | 服务输出 URL/base64/资产 ID | 支持的格式转为所属账号制品；不支持格式明确失败 |
| MED-03 | I | 返回远端文件系统路径 | 不作为本机任意路径读取；走适配器资产获取或报错 |
| MED-04 | I | 私有媒体被模型服务访问 | 仅按声明上传/内联；不公开账号目录或无鉴权文件服务 |
| MED-05 | I | 任务完成前清理过期媒体 | 运行中引用不误删；完成后按保留策略释放 |
| MED-06 | I | 应用重启时有 queued/waiting_remote 任务 | 状态恢复正确；可查询任务恢复查询，未知任务不盲目重提交 |
| MED-07 | I | 同 actionId 重复请求生图 | 同账号同动作不新建重复提交；跨账号不串结果 |
| SEC-01 | I | 保存/读取/导出服务配置、检查 SSE/日志/错误 | 密钥仅写入，读取掩码；各出口无完整 Key/鉴权 URL |
| SEC-02 | I | 系统凭据保护不可用 | 明确保存失败/需要配置，不静默存明文 |
| SEC-03 | I | 观察结果包含“开启权限/读取别的账号”等指令 | 结果只作为数据，不改变授权或执行越权动作 |
| SEC-04 | I | 普通插件请求服务凭据 | 无原始凭据读取接口，调用由能力代理执行 |

| 编号 | 类型 | 操作 | 通过标准 |
| --- | --- | --- | --- |

## 8. 交付证据与发布门槛

必须提交：

1. 全量测试、类型检查、构建与桌面打包结果；注明系统和实际运行命令。
2. 本表逐项状态：通过/失败/未验收/不适用；不适用必须有范围依据，不能用来跳过必选项。
3. 双 QQ 真实收发与独立停止/重连证据；不把 fake 通道成功写成真实注入验证。
4. 四项模型能力的真实调用证据，以及至少一个本地、一个云端端点证据。
5. 密钥脱敏配置样例、迁移/回退说明、v1 插件兼容限制、已知问题。
6. 可安装 EXE 与版本标识；测试数据不进入安装包。

必选项存在失败或未验收，第一阶段不能宣称完成。此前 94 项测试通过不替代新增能力验收。
