## 已确认决定

### DL-01 产品中心：Nowadays 是数字生命的载体

- 项目从以 QQ 注入编排为核心，转向以 Nowadays 自身承载数字生命为核心。
- 用户可以在 Nowadays 中搭载或创建不同的角色，与角色进行页面对话，并为角色提供功能和 API 支持。
- 看视频、浏览网页、记笔记，以及通过 Agent 控制电脑，属于用户提出的能力方向；各项具体范围、交互与实施顺序尚未逐项确定。
- 插件、Skill 等扩展能力围绕新的角色 Agent 核心接入，通用接入与重写方式见 DL-35～DL-37，不预设直接沿用旧实现。
- QQ、其他社交平台及 SnowLuma 接入作为额外扩展，不再决定角色能否存在、对话或拥有记忆；QQ／SnowLuma 的实施顺序已在 DL-42 确认为后置。
- 角色的记忆、对话历史和活动经历以 Nowadays 为归属中心。

### DL-02 角色实例：一个实例就是一个独立数字生命

- 每个角色实例拥有持续、独立的身份，以及自己的设定、记忆、经历和扩展状态。
- 同一张角色卡可以创建多个独立实例；这些实例各自拥有自己的经历。
- 同一实例可以通过 Nowadays 页面、QQ 或其他入口参与交流，入口变化不创建另一个角色身份。

### DL-03 更新设定：修订同一角色，不重建生命

- 用户可以反复更新角色设定，包括完善初版角色卡。
- 更新后仍是同一个角色实例，保留身份、历史对话、记忆和扩展状态。
- 系统不检测、标记、解决或自动修正角色设定与已有记忆、历史之间的冲突。
- 设定冲突由用户自行处理；不建立冲突待办、不自动清理或改写已有记忆。
- 早期讨论中提出的“当前设定优先、冲突记忆标为待处理”未被采用，以本条用户纠正后的决定为准。

### DL-04 对话组织：多个独立窗口，主界面只展示用户与角色的直接对话

- 同一角色拥有多个独立对话窗口。QQ 私聊、群聊及其他入口的会话分别保存。
- 在角色视角中，这些是它参与的不同对话窗口。
- 用户主聊天界面只呈现用户自己与该角色的直接对话，不把角色其他窗口的消息混入其中。
- 用户进入该角色的“消息与活动日志”一类页面，才能查看其他对话详情和活动记录；页面正式名称与布局尚未确定。
- QQ 等外部平台上的消息属于 Nowadays 中的正式对话历史，保留对应会话并标注来源平台。
- “全部进入 Nowadays 的历史”不等于“把所有窗口合并为一条聊天记录”。

### DL-05 记忆范围：角色共享长期记忆，窗口保留独立上下文

- 同一角色在不同对话窗口之间共享角色层面的长期记忆，由 Nowadays 统一管理。
- 每个窗口保留自己的聊天上下文与原始消息记录。
- 角色可以在主窗口回忆从 QQ 等其他窗口获得的经历，但其他窗口的原始消息不会因此成为主窗口的聊天记录。
- 具体的记忆提取、检索与上下文注入机制另行设计，不将“共享记忆”解释为每次调用都加载全部窗口历史。

### DL-06 Agent 核心：采用 LangGraph TypeScript 编排

- 采用 LangGraph 的 TypeScript 版本构建角色 Agent 核心。
- LangGraph 承担执行流程与运行状态的编排，组织上下文读取、记忆检索、模型调用、工具执行及后续处理。
- Nowadays 自己掌握角色身份、角色设定、对话历史、记忆规则和扩展规则。
- 用户设计的记忆系统作为核心能力接入；不因采用 LangGraph 而强制替换为框架默认的记忆方案。
- 执行检查点与角色长期记忆承担不同职责，不把运行检查点直接等同于角色完整经历的存储。
- 实施方式已修订为 DL-37 的新空分支重写。现有插件、Skill、模型服务与工具执行的设计经验可供评估参考，具体代码复用不作为前提；Skill 按 DL-36 的通用规范重新设计接入。
- 正式实现前，先以小范围原型验证集成，首轮范围已在 DL-60 确认；具体依赖版本、执行检查点持久化方案与实施步骤尚未确定。
- 网页操作、视频处理和电脑控制需要具体能力实现，再由 Agent 调度；采用框架本身不代表这些能力已经具备。

### DL-07 自主活动：属于核心设计目标

- 自主活动是本次方向调整的重要能力，不限于收到消息或用户分配任务后才行动。
- 角色在没有新消息时也可以产生并开展活动。
- 自主活动形成的经历进入角色记忆及活动日志。
- 用户能够为角色决定是否开启自主活动及其活动范围，具体控制方式尚未确定。

### DL-08 活动动机：角色形成意图，用户可以引导

- 角色依据角色设定、已有记忆和持续关注的事情，自行形成活动意图。
- 用户可以提供长期方向，无需逐项安排全部任务。
- 角色需要持续保留正在关注的事情、想做的事情和未完成意图，让活动能够跨轮次延续。
- 看网页、看视频、记笔记等活动可以由角色自己的动机推动，不仅来自用户的直接命令。

### DL-09 统一主体：协调多个对话与可并行任务

- 同一角色拥有一个统一的决策主体，协调不同对话窗口和自主活动。
- 角色应掌握自己正在进行的活动，并据此协调回复、暂停、继续或稍后处理。
- 具体任务可以并行执行，各对话窗口仍保留独立上下文。
- 不将每个窗口设计成彼此不知道对方活动的独立角色副本。
- 统一主体是产品与调度上的一致性要求；同一角色决策串行、独立任务可并行的原则已在 DL-49 确认，不将其等同于全部工作使用单线程或所有任务串行执行。

### DL-10 唤醒方式：事件唤醒与自主安排相结合

- 消息到达、网页加载完成、视频处理结束等事件可以唤醒角色，推进下一轮思考和行动。
- 角色可以根据自己的意图安排后续唤醒，例如稍后继续阅读、次日关注事情进展。
- 系统负责持久保存并调度这些安排。
- 没有待处理事件时，角色保留状态并等待；不以持续进行无意义模型调用维持存在。
- 关闭窗口与明确退出时的运行行为已在 DL-29 确认；再次启动后重新评估安排的原则见 DL-30，具体任务恢复和唤醒执行细节仍待确定。

### DL-11 能力开关：用户按角色启用或停用，角色自主使用

- 本条原有额外授权表述已按用户在 DL-59 的决定修订为开关控制。
- 用户为角色启用或停用相应资源与能力，开启后角色可自主使用，不另设授权、审批或逐次调用确认。
- 网页浏览、笔记、QQ 接入、电脑控制等能力可以分别通过开关控制。
- 安装和配置资源后，用启用状态决定角色是否使用，不再增加一套授权操作。
- 具体开关默认状态、组织方式和变更时对在途任务的影响尚未确定；不将这些细节扩展成额外授权流程。

### DL-12 主动交流：角色可以主动发起对话

- 主动发起交流属于角色的核心能力，角色无需等待用户先发消息。
- 角色可以依据自己的动机，在 Nowadays 中与用户的主对话窗口主动表达，例如分享发现、延续话题或谈起共同经历。
- 主动发出的消息作为该窗口的正式对话记录保存；具体活动经历仍归入角色的记忆与活动日志。
- 主动交流的频率，以及是否通过 QQ 等外部渠道主动联系，尚未确定。免打扰当前不纳入功能范围，见 DL-13。

### DL-13 当前范围：暂不加入免打扰功能

- 用户明确决定当前不需要免打扰，暂不增加该功能。
- 本轮不规划免打扰时段、因免打扰暂存主动消息或结束后补发等行为。
- 本条不改变 DL-12 已确认的角色主动交流能力。
- 免打扰不继续作为当前待确认功能推进；将来用户提出需要时，再讨论是否加入。

### DL-14 角色工作空间：独立持久保存，默认位于 Nowadays 所在目录

- 每个角色实例拥有独立、持久的工作空间，保存笔记、收集的资料及任务成果。
- 角色可以在后续活动中打开、修改和引用此前保存的内容。
- 工作空间与记忆互相补充：记忆用于回想经历，工作空间用于保存和持续维护实际内容。
- 用户明确要求默认放在 Nowadays 所在文件目录下的专用文件夹中，不使用系统默认用户数据路径作为工作空间默认位置。
- 具体文件夹名称、角色子目录结构及路径配置方式尚未确定；本条仅确认存放原则，未创建运行数据目录或改变现有存储实现。
- 此决定针对角色工作空间，不自动扩展为所有现有数据和凭据的迁移决定。

### DL-15 模型配置：全局管理服务，角色按能力独立绑定

- 全局统一管理可用的模型服务。
- 模型选择与能力绑定归属于角色实例，目标设计从以 QQ 账号为配置主体转向以角色为主体。
- 每个角色可以独立选择模型，并按能力分别绑定，例如对话、图片理解和视频理解可以使用不同模型。
- 同一角色在 Nowadays、QQ 及其他对话入口中沿用该角色的模型配置。
- 具体配置结构、现有账号策略的迁移方式与界面改造尚未确定，本条不代表已修改现有配置实现。

### DL-16 记忆基础：以经历事件组织记忆，关联原始证据

- 采用用户专门设计并在参考底稿中提出的事件记忆组织与检索基础：经历事件关联原始证据。
- 保留实际发生的原始记录，包括对话、网页阅读记录和工具执行结果等。
- 从原始记录中整理可检索的事件记忆，描述发生了什么，并关联对应证据，以便回忆时追溯具体内容。
- 事件来源覆盖角色参与的对话与自主活动，适配 DL-04 的多窗口和 DL-07 的自主活动。
- 角色的计划、猜测与实际完成的事情在记录中应有所区分。
- 此次确认记忆的基础组织方式；具体事件字段、整理时机、召回与深度检索流程仍逐项讨论，不等于采纳参考底稿全部细节。
- 后续可以提出优化建议，但需与用户讨论确认后再修改已确认设计。

### DL-17 召回原则：多维事件索引与按需深入检索

- 用户确认“自动召回相关事件＋角色按需深入检索”的方向；该确认不代表实际运行链路已经确定。
- 事件形成后，为其建立时间、事件名称、情绪、内容等多个可检索维度，支持记忆召回。
- 常规对话自动获得相关事件概况；需要具体原话、前因后果或更多证据时，角色可进一步查阅事件及对应原始记录。
- 用户指出当前关键未决问题是普通对话如何整理为事件，以及事件形成和确认的链路控制；接下来优先逐项讨论这一部分。
- 本条不确定事件切分规则、整理触发时机、确认机制、索引技术、排序权重或调用预算；“事件确认”也不预设为必须由用户人工审核。

### DL-18 事件粒度与生命周期：筛选零碎日常，精炼低召回事件

- 用户基本认可对话逐步整理、补充事件再形成记忆的方向，同时明确要求控制事件粒度，避免产生过多细小事件。
- “今天吃了什么”等零碎日常不应全部整理为独立事件；需要在事件形成环节进行筛选或聚合。
- 可以考虑事件级别筛选、事件触发统计等方式；具体采用哪种机制尚未确定。
- 对经过一定对话轮次、较少被召回的事件进行精炼，使其不再作为独立事件保留。
- 原始记录的保留与追溯仍遵循 DL-16；精炼事件不等于删除原始对话。
- 精炼去向已在 DL-19 确认为简短日常摘要；具体筛选规则、统计口径、轮次阈值仍待逐项讨论，尚未决定实现算法。
- 后续提出的“日常片段／一般事件／重要事件”三档优先级方案不采用，见 DL-23。事件形成阶段的粒度筛选继续保留。

### DL-19 事件精炼去向：合并为简短日常摘要

- 对符合精炼条件的零碎事件，合并为简短的日常摘要，撤去各自的独立事件索引。
- 摘要保留对日常经历的概括，并关联原始记录，必要时可以继续深入查找。
- 原始记录继续保留，不因事件精炼而删除。
- 摘要聚合范围、更新周期、长度及参与召回的具体方式尚未确定。
- 上一轮提出的“同时考虑重要性和未完成状态”等优化建议尚未逐项确认，不作为本条已确定的精炼条件。

### DL-20 记忆整理：独立于实时对话的后台流程

- 角色正常聊天和开展活动，记忆整理由独立后台流程读取已经保存的对话及活动记录后进行。
- 整理流程承担批量整理事件、补充索引及精炼日常摘要等职责。
- 可以积累上下文再判断事件边界，不要求每次回复都额外调用一次记忆整理模型。
- 尚未整理的新消息保留在近期上下文中，供角色使用。
- 本条确认职责与执行流程分离，不预设必须增加独立操作系统进程、另一角色主体或单独模型服务。
- 整理触发原则已在 DL-21 确认；批量大小、时间阈值、调用预算及具体调度方式尚未确定。

### DL-21 整理触发：记录积累、交流停歇与活动结束相结合

- 新增记录达到一定量时，安排批量整理。
- 交流暂停一段时间后，对尚未整理的少量记录进行补充整理。
- 阅读、观看视频或执行任务结束后，将相关记录交给整理流程。
- 触发条件由程序判断，有新记录才需要整理。
- 触发整理仅表示检查相关内容，不直接决定事件边界；已有事件可以继续补充，也可以没有值得新增的事件。
- 具体记录量、时间阈值及批量大小尚未确定。

### DL-22 整理职责：模型判断语义，程序校验并保存

- 整理触发后，整理模型读取新增记录与相关事件草稿，依据后续确定的筛选标准判断事件的语义归属和价值。
- 整理模型可以提出新建事件、补充已有事件、归入日常概况、暂留待续四类处理结果。
- 程序检查引用的来源记录是否存在、结果格式是否正确、修改目标是否合法，再保存结果并更新索引。
- 本条确认模型与程序的职责划分；具体筛选标准、结果协议与校验细则尚未确定。

### DL-23 检索简化：不额外设置固定事件优先级

- 当前不加入“日常片段／一般事件／重要事件”等固定优先级划分，沿用多维索引查找与按需深入回忆。
- 普通召回的事件摘要交给对话模型结合上下文使用，不额外要求另一个模型逐项审阅或打分。
- 当匹配结果过多时，可按当前查询的匹配程度控制放入上下文的内容；具体选择算法、数量与长度预算尚未确定。
- 事件形成阶段仍按 DL-18 控制粒度、筛选或聚合零碎内容；取消固定优先级不意味着所有片段均形成事件。

### DL-24 角色成长：保留主观体验，允许心理与理解随经历变化

- 事件记忆同时保留发生经过和角色的主观体验，包括感受与对经历的理解。
- 发生经过关联原始证据；感受与理解明确属于角色的主观体验。
- 用户明确目标是角色可以拥有自己的成长和变化；角色卡提供性格底色和基础，角色的心理活动、想法与理解可以在后续经历中变化。
- 角色可以重新理解旧事，原始经历与记录仍然保留。
- 角色经历带来的成长与用户主动更新角色卡分别理解，不把成长等同于重建角色实例。
- 此决定不新增角色设定冲突检测或处理，仍遵循 DL-03。具体主观体验的生成与更新方式尚未确定；独立保存角色当前状态已在 DL-25 确认。

- 角色运行时，将角色卡底色、当前状态与相关经历记忆共同作为上下文，使成长形成的变化能够延续到后续交流和自主活动。
- 当前状态由角色自主提出局部变化、核心校验保存的方式已在 DL-48 确认；具体接口、触发细则与保存结构尚未确定，不预设每条消息都调用模型重写状态。

### DL-26 角色日记：与当前状态摘要联动

- 当前状态保持简短，描述角色目前的近况；日记与状态关联同一段经历和反思，分别保留过程与当前变化。
- 状态随有意义的变化更新，日记可以在角色想记录时书写，不要求每次状态变化都生成一篇日记。
- 本条确认两者联动及职责；书写方式已在 DL-27 确认，具体触发机制、更新顺序和界面呈现尚未确定。

### DL-27 日记书写：由角色自主决定，作为自主活动执行

- 当前状态可以独立更新，不以角色写日记为前提。
- 本条确认书写自主权，不预设固定的每日书写次数或时间；日记参与记忆召回的原则已在 DL-28 确认。

### DL-28 日记召回：作为可检索的主观记忆，与事件关联

- 第一版以多维条件过滤与全文检索作为记忆召回的技术起点，沿用参考底稿的先程序检索思路。
- 用时间、情绪、来源等条件缩小范围，检索事件名称、摘要和内容。
- 全文检索优先验证 SQLite FTS5，中文分词及实际匹配效果需要单独验证，不预先宣称能够满足召回要求。
- 以实际查询样例建立测试基线，后续根据漏召回情况判断是否增加语义向量检索；向量检索当前保留为候选，不作为第一版必选依赖。
- 本条不确定具体查询构造、分词、排序、返回数量或上下文长度参数，也不增加 DL-23 已取消的固定事件重要等级。

### DL-52 自主活动预算：按角色配置，与主动对话分开统计

- 为每个角色的后台自主活动设置可配置执行预算，管理模型调用量和工具执行量。
- 达到预算上限时保存活动进度，等待后续预算或安排再继续。
- 用户主动对话与后台自主活动分开统计，避免后台活动挤占正常聊天的预算。
- 本条确认预算机制，具体预算单位、周期、默认值、恢复方式及执行限制细则尚未确定。

### DL-53 工具异常：明确失败自主处理，结果未知先核查

- 明确失败的工具调用，由角色在预算内决定重试、换方法或结束任务。
- 执行结果未知时，先核对实际状态，再决定后续操作；无法核实时保留未知状态。
- 不把连接中断或未收到响应直接等同于操作未发生，例如保存笔记后响应中断，应先检查实际文件状态。
- 本条确认异常处理原则；具体状态协议、核查工具、重试上限及恢复流程尚未确定，不代表所有工具都具有可核查的执行结果。

### DL-54 经历连续性：第一版不做剧情分支与回档

- 第一版每个角色采用一条持续的经历时间线，围绕独立数字生命持续成长的主线建设。
- 不同对话窗口仍各自保存，共同构成该角色的生活经历，不因统一经历时间线而合并聊天窗口。
- 第一版暂不实现平行剧情分支、剧情回档或重生，不直接采用参考底稿中的分支运行方案。
- 本条不取消角色数据备份、迁移和故障恢复的设计方向；数据恢复与主动回退剧情分别理解。
- 普通消息重试和历史记录编辑的具体规则不由本条自动确定；记忆人工修改的页面管理定位见 DL-55，具体修改规则仍待确定。

### DL-55 人工记忆修改：定位为页面上的数据管理操作

- 页面入口、交互及具体字段修改规则遵循 DL-45，在前端阶段再细化；人工管理对应后端的基础数据读写职责，角色自主核验与纠错另按 DL-56 设计。
- 本条不改变 DL-22 的后台记忆整理职责，也不增加 DL-03 已排除的设定冲突自动处理。

### DL-56 角色纠错：自主核验记录与陈述，判断后更正或回应

- 用户明确修订上一步决定，要求角色具备自主核验与纠错能力，不仅依靠用户在页面中修改数据。
- 角色可以检索记忆和来源，自行判断是记录错误，还是用户的回忆或表达有误，不预设任意一方总是正确。
- 若判断记录错误，角色可以更正对应记忆；若判断是回忆或表达有误，由角色结合自身性格与情境决定如何回应和处理，不强制采用固定纠错话术。

- 可修改的数据范围与原始来源保护已在 DL-57 确认；核验工具、证据不足时的处理及修订记录方式仍需逐项确定，不预设每轮额外调用独立审核模型。

- 具体更正接口、修订记录、索引同步和并发校验方式尚未确定。

- 系统进行实际加载、解析和调用所必需的处理，运行中自然产生的错误如实记录或返回，后续按 DL-53 交给角色处理。
