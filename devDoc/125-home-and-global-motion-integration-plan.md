# 主页与全局公共动效接入计划

日期：2026-10-28。状态：待实施方案，不代表效果已接入。

## 1. 本轮目标与范围

依据用户最新约定：**公共能力直接统一全局使用；页面设计只推进主页，其他业务页面不重新设计。** 不创建主页专用 Dock、按钮、菜单或另一套动效实现，也不安排“先主页分叉、以后再合并”的迁移路线。

范围分为两层：

| 层级 | 本轮实施 | 明确边界 |
| --- | --- | --- |
| 全局壳与公共UI | PageDock/MoreMenu、基础按钮、菜单、Modal/useConfirm、Disclosure/Switch、动效偏好和生命周期；公共导航入场能力 | 所有调用者使用同一套契约；未设计页可自然获得公共动效，但不重排其内容、表单、配色和操作流程 |
| 主页 | 主入口书签反馈、阅读分组入场、现有场景跟随的偏好与清理统一、长内容/错误状态适配 | 保持当前插画、文案结构、账号只读展示和一屏布局，不新增业务开关、保存表单或模拟活动 |

工作台、角色、模型、资源、插件、诊断、设置页面不做页面级设计。设置窗口和这些页面使用到的公共控件会随公共组件更新，因此必须回归其交互；这不等于本轮完成了这些页面设计。不得为迁移动效批量替换其业务实现。

依据：[105 总体规范](105-frontend-design-system.md)、[110 深色标准](110-nightwave-ui-standard.md)、[117 书签与落款](117-frontend-motion-standard.md)、[120 手账Dock](120-dock-notebook-standard.md)。验收执行[126](126-home-and-global-motion-integration-acceptance.md)。

## 3. 统一技术方案

1. 复用现有React、公共UI、CSS和WAAPI；本计划不要求新增动效依赖。复杂度不足以证明新引擎必要时，不安装第二套动画库。
2. 统一参数读取、有效偏好、取消/结束及代际清理。代码放`desktop/renderer/src/ui/`，必要工具由公共入口暴露；页面仅声明动作语义和阅读分组。建议名如MotionProvider/useMotionPolicy只是待设计API，不是已有导出承诺。
3. token以`devDoc/design/character-studio/tokens.json`为唯一数值来源，复用`component.motion.*`与`component.dockNotebook.*`；缺少的材质配方先登记用途再生成，不手改character-tokens.css。
4. 应用本机system/reduced/full偏好统一计算：reduced关闭位移和跟随；full可覆盖系统reduce；forced-colors仍禁用装饰材质。CSS与JS使用同一结论，Portal、排队确认继承调用范围。时间读取同时支持ms/s。
5. 所有活动动画、监听器、rAF、结果计时器和层管理状态归组件或应用Provider实例所有；卸载、隐藏、失焦、主题/偏好变化有明确收束。连续操作从当前绘制状态接续，旧回调不得清理新状态。
6. 保留现有UiThemeScope/UiThemeProvider分层。全局动效策略独立于页面主题作用域；不能通过给所有业务页包xiacheng scope的方式顺带重置其控件尺寸和颜色。公共组件有新旧外观时，共用同一行为，分别消费其现有外观变量。
7. 不引入模块级可变单例；不持有第二份可交互页面、不改变整个App/编辑器key、不延迟业务等待以播放动画。所有装饰透传指针，不进入辅助技术和Tab顺序。

## 4. 执行工作包与顺序

### HM-0：基线与公共策略收口（前置）

- 冻结当前主页、顶部/底部、设置与一张长业务页的双主题截图；记录路由、主题、动效偏好、视口和缩放，不复用旧截图冒充本批。
- 清点motion/dockNotebook变量的实际消费者和现有动效；确认按钮、浮层、主题过渡、HomeScene对full/reduced的判断一致。建立公共策略接口及中断工具。
- 审计`ui/modal.tsx`现有模块级`layers/backgroundState/previousBodyOverflow`。扩展存在状态时将层管理收口到应用级实例所有者，保持公共Modal API和嵌套行为；这是本轮共享依赖，不扩展到后端重构。
- 如公共触发器、origin/ref或结果事件接口需要增量扩展，先在公共UI文档确定；保留现有调用方式，不复制整套组件。
- 交付门：多Provider隔离、偏好切换与现有契约回归通过；未设计页基线仍完整可用。该包不宣称视觉接入完成。

### HM-1：全局按钮与结果反馈

- 普通按钮继续1px按压及下沿收短；entry在hover/focus-visible探出3px，尾部最多8px，箭头2px；按压收回，装饰不裁切/不扩张命中框。
- 按语义扩展现有Button，不给所有ControlButton强加书签外观；导航、Disclosure和Switch仍各自表达其语义。
- 保存反馈复用真实busy/feedback。若需新增结果事件键，应按操作对象和请求代际触发一次；重渲染、切主题及相同旧结果不得重复落款。未知结果、失败、导航成功均不能当保存成功。
- 对已有显式成功反馈的调用提供公共勾画；没有真实结果输入的调用保留原反馈并列明待接点，不靠猜测请求或自动监听HTTP。仅为接落款而改旧页面保存流程，不在本轮范围。
- 交付门：普通、主入口、危险、禁用、busy、success/error组合通过；主页“进入工作台”获得端片反馈，保持立即进入导航准入。

### HM-2：全局手账Dock与真实更多菜单（优先视觉工作包）

- 只迁移现有`PageDock`。保持桌面/关系/模型/收藏/更多顺序，采用120的纸签/布面、图上文下、单个选中书签及分隔。
- Dock常规68px、紧凑64px、短窄58px；单项命中≥44px。Dock自身高度与footer预留分别处理，保持现有104px区域基准；不采用尚未认可的88px整体留白。
- 分离选中书签、hover、按压与内部跟随层；跟随±1px，hover上移2px，按压下沉1px/缩放0.96。文字和命中框不移动。
- 选中只跟随已提交路由；草稿准入未完成/取消不提前移动。点击当前页不重播；快速反向取当前绘制位置。返回/前进、窗口缩放后重新对齐，不把hover当selected。
- MoreMenu继续DropdownMenu；在公共菜单增量支持需要的触发器内容/ref与来源，不创建嵌套按钮。开更多不切页；非直接入口才对齐更多并说明真实当前页，菜单选择走原导航准入。
- 鼠标处理每帧至多一次，进入时缓存稳定命中框；离开、取消、抬键/抬鼠标、失焦、隐藏、resize、切主题/减少动效时清理。触摸不继承hover。
- 交付门：全部路由上的同一Dock、双主题、更多菜单及导航/草稿/退出契约通过。旧业务页只接受全局壳变化。

### HM-3：全局浮层、折叠与开关动作

- DropdownMenu按160ms进退；来源来自真实trigger，视口边缘定位和长菜单内滚动保留。
- Modal/useConfirm按117来源位移与缩放，缺来源使用中心退化；打开立即隔离，退出结束前保留模态隔离，完成后恢复可用焦点。快速开关、嵌套确认、closeDisabled及安全退出继续受原契约约束。
- HM-0确定的层管理实例负责存在状态，装饰结束不得替代用户取消或发起第二次onClose。进入、退出或卸载后的回调按代际丢弃。
- Disclosure保持同一编辑器DOM、草稿和选区；关闭内容退出Tab/辅助技术，内部焦点先回触发器；中途反向连续衔接。Switch不延迟真实状态/aria-checked，不新增页面开关。
- 此包更新公共组件，设置及旧页自动获得对应动作；不重绘设置或其他页面，不新增抽屉业务。
- 交付门：公共样板和至少设置弹窗、草稿确认、嵌套层、真实Disclosure/Switch消费者完成回归。没有实际消费者的能力明确标“仅公共层已验证”。

### HM-4：主页阅读入场与组合收口

- 用现有Home/HomeScene结构实现少量阅读组：叙事标题→账号/签名或空态→入口/注脚；角色场景独立小幅入场，避免对大图叠加无界缩放。阅读间隔24ms、累计≤72ms，总完成≤280ms，位移4px。
- 首次进入和真实返回主页可入场；切主题只播放既有天气过渡，账号/SSE/轮询/错误重试不重播整页。全局导航仅在准入成功后触发一次；旧业务页不新增逐段阅读组。
- 保留既有历史焦点与滚动策略；减少动效立即可读，任何入场都不延迟按钮可点击或错误可见。
- HomeScene改用统一有效动效策略并补窗口隐藏/失焦清理；保持既有场景幅度和人物素材，禁止添加未采用环境光或模拟叙事。
- 复验主页长昵称、长签名、首次加载、缓存后错误、无账号、图片失败及错误重试。现有`home-copy>.error-note`有max-height/overflow限制，必须确认原因和重试入口不会被裁切；如无法保证，应在主页局部调整排版。
- 交付门：双主题一屏布局、主入口及错误/空态可操作，公共动效与天气过渡组合不冲突。执行126完整验收。

顺序：HM-0 → HM-1 → HM-2 → HM-3 → HM-4。每包独立可回归、可回退，先实现方自验再独立复核；没有用户新要求时，不扩展其他页面设计。
