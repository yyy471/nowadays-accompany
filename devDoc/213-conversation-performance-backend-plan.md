## 回复消息设计

| 层次 | 保存和呈现 |
| --- | --- |
| 消息 | 一轮角色回复保存为一条助手消息，保留发送者、完整正文、时间和生成状态。用户消息、角色回复及主动分享可区分。历史与记忆按消息读取，终态按原有完成和中断规则处理 |
| 句段 | 按表达完整意思的自然段切分，连续短句可合为一段。桌面按段序自动追加气泡。每段有稳定标识，便于重连和回看 |
| 演出 | 立绘、语音和过场图按句段定位。表情可以跨段延续，媒体迟到时回到原位置，文字可先显示 |

普通对话以角色实际说出的台词为主，动作优先通过立绘表达。必要旁白单独呈现，默认跳过 TTS。正在查找之类的执行状态用于临时显示。角色明确说出的「我去查一下」照常作为台词保存。

## 共用的句段与恢复契约

候选字段为 `messageId`、`segmentId`、段序、原文范围和段类型。保留现有正文流和消息终态。已确定的句段可以作为独立 SSE 事件重放，历史读取可取回同一组句段与标注。已经输出的中断尾段按现有规则保留，未完成的尾段可以跳过自动合成和生图。

打开窗口时，建议一次读取最近消息、当前回复及已产生文字、现有句段、SSE 游标。历史向前翻页和按消息 ID 读取用于补齐正文及演出关联。主动分享可以直接带句段和结果，无需前置增量。切换角色或会话时按角色、窗口和句段归属处理迟到结果。

## 三条后端链路

### TTS

- 角色配置候选为 `GET/PUT /v1/roles/:roleId/voice`，提供参考音色绑定和保存。参考音频以导入后的受管引用关联，首个引擎及其专用参数随适配决定。
- 试听候选为 `POST /v1/roles/:roleId/voice/preview`。传入试听文本及本次拟测试的参考音色，返回音频，可在保存配置前比较效果。试听使用和对话合成相同的服务适配。
- 对话合成候选为 `POST /v1/roles/:roleId/windows/:windowId/segments/:segmentId/speech`。后端查本段文本、角色音色与可用表情语气，返回音频字节和对应 `Content-Type`。预取、播放和翻页停止由客户端掌握。内部复用或缓存仅用于减少重复合成。

### 表情立绘

- 模型从当前服饰已登记的素材中为句段选择差分。参考 AnimaVN 的标注分离，把 `outfitId` 与 `spriteAssetId` 作为句段演出信息保存，校验素材属于本角色和该服饰。衣柜和受管图片读取沿用现有接口。
- 标注可晚于正文到达，更新按句段定位。表情保持到下一次变化。缺少对应差分时沿用现有回退规则。换装后新的句段读取已提交的服饰，旧句段保留原演出信息。 [外观与对话](208-character-appearance-import-and-dialogue.md#桌面与演出) · [Agent 穿搭](209-agent-daily-outfit-development-guide.md#状态与提交)

### 生成过场图

- 后端将剧情片段、角色外观和场景变化整理成画面方案，再由生图适配执行。图片生成与对话执行分别记录，正文可以先完成。
- 任务记录角色、窗口、目标消息及句段、执行状态和结果素材 ID。生成成功后保存图片并发布对应事件，桌面按位置淡入。迟到结果仍归原句段。失败时保存任务错误，原对话按既有语义处理。重复提交与重连复用已有任务或结果。
- 过场图生成的触发入口、是否自动生成、出图条件与频率，待该工作包确认。外部服务与角色能力配置遵循已有资源及 MCP 边界。

## 开发和验收顺序

先用离线模型确定句段标识、表情标注和恢复契约。再接角色音色、试听及直接合成返回，最后接过场图规划与生成任务。TTS 和生图先用本地假服务验证正确响应、失败与取消，真实服务按用户配置另验。后端接口经实现方自验和独立复核后，再接桌面对话与角色配置。

最小验收覆盖一条回复自动展示多个气泡且历史只保存一条、台词可合成而旁白默认跳过、执行状态与角色台词区分、当前窗口已有一半回复时打开、快照与 SSE 衔接、用户打断、主动分享、同服饰缺差分、换装前后历史重放、试听和实际回复使用同一参考音色、过场图晚到与重连后仍定位原句段。首个引擎或生图服务及自动触发规则由对应工作包确认。
