## 1. 本阶段完成边界

按 DL-87、DL-88，P2 必须完成“实际记录形成记忆 → 多维检索与维护 → Agent 按需深入后回复”的完整闭环。原始消息和实际工具记录进入后台整理，生成事件及索引；后续对话自动召回相关概况，Agent 能改写查询、查看详情与原始依据、按需使用 Skill／本地 MCP，再完成流式回复和状态保存。

只接 LangGraph、只读取近期对话、只查预置事件，或仅能输出模型文字，均不足以宣布 P2 完成。日常摘要、主观体验、日记关联、角色记忆纠错、输入等待、新消息中断、未完成部分保留及客户端重连都在本阶段联动。

首轮继续单角色、单个 TypeScript 后端进程，扩展现有 `backend/`，CLI 与后续桌面共用本地 HTTP／SSE。自主安排和定时唤醒归 P3；组合退出／重启验收归 P4；远程 MCP 按 DL-115 在 P5 后补充。正式页面、QQ、浏览器／视频／电脑控制不进入 P2。活动整理触发可用本地文件任务验证，不以此宣称已实现网页浏览。

## 2. 开发顺序与运行分工

开发依赖顺序固定为：**记忆形成与保存 → 查询与维护 → Agent 对话联动**。这是 DL-88 的实施顺序，不意味着运行时每次聊天都要先等后台整理。

| 职责 | 运行规则 |
| --- | --- |
| 角色决策 | 同一角色有效决策串行，结合最新设定、状态、近期消息、召回概况与已保存结果 |
| 后台整理 | 同角色单批运行，多种触发合并；不占用实时角色决策位置，不让聊天逐轮等待 |
| 独立工具调用 | 登记后执行，结果先保存；转后台、回复切换或客户端断线不重新发起同一次调用 |
| 模型适配 | 对话与整理共用调用抽象和服务配置，各自构建上下文；默认整理模型继承角色对话模型，可单独绑定 |
| Skill／MCP | Skill 提供方法与知识，外部实际操作通过 MCP；开关和任务链资源延续沿用已确认规则 |

不增加模块级可变业务单例，不拆分成按角色部署的服务。后台失败保留待处理范围，延后重试，不自动换模型；最新相关记忆发生变化时重新处理受影响内容。

日期时区、中文检索实现、查询排序及上下文容量等尚未固定的工程选择，在相应工作包实测留证。角色归属必须由服务上下文限定，不依赖模型自行填对 roleId。

## 4. 记忆形成、检索与维护

### 4.1 后台触发与批次

沿用 DL-21、DL-94～DL-96、DL-125～DL-127：

- 同窗口新增待整理消息达到 **50 条**时安排整理；至少 **30 条且交流停歇 60 秒**时也安排。用户消息和角色回复按记录计数，流式片段不重复计数。
- 具体任务结束且有新实际记录时独立触发；单次回复、模型思考或工具返回不自动等同于整项任务结束。
- 程序判断触发，模型判断事件语义。可新建、补充已有事件、归入日常概况或暂留待续，不强制每次触发都新建事件。
- 批次开始固定输入范围；多个触发合并，同角色仅一批。新记录保留待处理，各窗口原始历史不混并。
- 按模型可用上下文分批，并为结果留容量；超长记录按顺序分段，完整保留原文和未处理部分。50／30 条是触发条件，不是硬切分容量。
- 正文、来源和索引成功保存后才推进处理进度。失败保留已提交部分和待处理范围，不重新等消息凑够阈值，不阻塞聊天或自动换模型。

先使用可控离线整理模型测试语义协议与保存。程序只校验格式、来源存在、归属、目标版本及提交一致性，不引入额外语义审核模型、用户审批或角色卡冲突处理。

### 4.2 检索与 Agent 深查

统一入口同时返回事件和日常摘要，标明类型。基础召回由程序结合本轮已发送消息、近期话题及当前关注事项构造首批多维条件／全文查询，不固定增加一次独立模型调用。

角色可回忆同角色其他窗口的经历，但当前窗口原始对话仍独立。人物、主题、时间、来源、情绪按查询意图使用；不因当前心情就排除其他相关记忆。匹配、去重、数量和长度依据上下文容量控制，不设置固定事件重要等级。

Agent 获得概况后可继续搜索、查看事件详情、按摘要范围搜索原文或读取工具结果。必须区分成功但无命中与查询失败；未命中不表示事情从未发生。证据不足时保留不确定，不编造回忆，也不强制每次闲聊都增加检索回合。

中文检索需要用实际中文样例验证。P2-01 确定候选全文检索／分词方案，P2-03 比较命中、查询错误、角色隔离和性能；不未经决定增加向量检索或固定评分审核器。

### 4.3 精炼、主观记忆与纠错

按 DL-97、DL-98，事件实际提供给角色上下文或被主动读取才计召回；同一 executionId 的同一事件只计一次。只在数据库匹配、未提供给角色的候选及后台维护查询不计数。

初始精炼候选条件为：事件创建或最近补充后至少 **100 轮对话**，且最近 **100 轮召回不超过 1 次**。一轮是该角色完成一次已发送消息的回复决策，各窗口合计；同次工具循环不另计，事件有补充则重算观察期。达到条件仅进入候选，由整理模型决定是否精炼，不自动删除。

实际精炼后，零碎事件退出独立检索结果，归为简短日常摘要；按经历发生日期聚合，可按话题分条并持续补充。摘要正文只概括，后台保留各窗口及消息／时间范围，原始记录不删。日记单独保留，不被摘要替代。

日记由角色决定书写，也可由用户邀请后选择书写；不把每批后台整理变成日记。P2 提供实际保存、读取、事件关联与召回路径，定时自行书写的唤醒由 P3 接入。角色当前状态可以独立局部更新，不以写日记为前提。

角色可以核对记忆与原始来源，自行判断记录或陈述是否有误，决定如何回应。纠错只改整理后的事件、摘要与索引，原始对话和实际活动观测保留原貌；unknown 的核查补录保留原诊断。后台整理和角色纠错并发修改时，校验目标及依据版本，旧结果不覆盖新内容，受影响范围重新处理。

## 5. 模型、Skill 与本地 MCP

沿用 DL-117～DL-120 的统一模型入口，覆盖 OpenAI Chat Completions 兼容、Responses、Anthropic Messages 三类协议。SDK／具体版本和请求格式在正式后端中验证后锁定，不把 P0 的脚本模型等同于真实协议兼容。

后端提供获取模型列表与主动测试连接的 CLI／API；保留手填模型 ID。列表失败返回实际原因、保留配置，不自动清空或切换服务。测试连接使用选定配置发起简短真实请求，不携带角色／记忆，不进入聊天和自主额度；不是保存配置的强制前提，也不自动随测试套件执行。

Skill 按通用 Agent Skills 接入，按需加载元数据、正文及所需参考文件／脚本；不恢复旧私有 Skill 或插件协议。脚本通过已启用的执行工具运行，依赖和环境由用户处理，不做额外审查、预检或试运行。

本地 MCP 至少验证文件读写、目录检索和命令／脚本执行基础工具，真实返回进入任务／调用记录。普通文本、结构化输出和多内容块均需保存原始响应并提供合适的模型输入；unknown 先核查，无法核实保留 unknown，后续确认沿原调用补录，不因响应丢失重发。

关闭开关立即阻止新任务使用，已在执行的原任务链保留资源使用至链结束；后续未发调用使用最新同一资源配置，已发调用不取消后重发。任务结束后的在途结果仍保存，不自动重启任务。不开辟额外授权或逐次确认流程。

调用量按任务来源登记：用户对话／交办任务与后台记忆维护不扣自主额度，角色自行发起活动按 DL-104～DL-111 计量。P2 固定并接入归属和实际调用登记接口；完整自主额度周期、余额耗尽与到时唤醒在 P3 验证，不把前后台模式当作额度归属。

## 6. LangGraph、输入状态与 SSE

LangGraph TypeScript 在正式 backend 中编排，保留 P0 已验证原则。一个 executionId 对应一个 thread_id；同次恢复沿用，新决策新建。图进度不代替角色业务历史，每次恢复后的新判断读取最新角色设定、状态、配置及实际结果。

建议链路：已保存待处理消息 → 等待该窗口退出输入状态 → 角色串行决策入口 → 最新上下文和自动召回 → 模型／记忆工具／Skill／MCP 循环 → 回复与局部状态提交。具体节点、状态和接口在 P2-01 定清；不能退回固定一次检索即回复。

| 交互／保存边界 | 必须行为 |
| --- | --- |
| 输入状态 | 实际编辑刷新状态，停止输入 1 秒后退出，暂不提供用户配置；输入法组词仍保持输入状态，只有焦点不算持续编辑 |
| 新消息 | 输入先保存；同次提交编号重试不重复登记或打断；同窗口已发送待处理消息共同交给下一轮决策，不无限等待积累 |
| 中断 | 实际新消息才替代未完成回复，单纯打字不打断；旧模型迟到的工具请求不能发起新操作，已发调用仍保存真实结果 |
| 部分文字 | 可见片段持久保留并标记未完成；提交失败也不能丢弃已显示部分，补齐 P0 C07 已知限制 |
| 正式完成 | 回复、角色局部状态和执行完成标记同一业务事务保存，成功后才通知完成；后台整理不能直接改角色状态 |
| SSE 断线／重连 | 后端原执行继续；重连按已有事件位置／进度读取，不新增决策或重复调用；片段及完成通知可去重 |
| 临时输入清理 | 对应窗口关闭、客户端确认断线或后端重启后清理，不恢复旧输入状态，不把未发草稿交给模型 |

P2-01 需明确片段保存与发送顺序、事件编号及重连游标，保证已显示内容可追溯，正式完成事件可重新读取。可采用持久事件记录与业务事务衔接，不能只把内存 SSE 发送成功当作业务完成。保存频率、批量方式和客户端会话交接属于工程验证事项，不改变上述行为。

任务、调用与结果保持独立。结果保存领先检查点时重入复用；已登记步骤不能重建新身份；未知结果不能当作未执行。每轮决策的有效性在模型返回、登记及派发边界检查，同时保留在途结果，避免旧输出覆盖新回复、状态或记忆。

## 8. 验收矩阵与记录方式

| 场景 | 可核对结果 |
| --- | --- |
| 实际记忆闭环 | 保存原始对话／工具结果，触发整理形成事件，后续问题自动召回；Agent 改写查询并读取原始依据后回答，不只使用预置事件 |
| 阈值与批次 | 49／50、29／30 条与 59／60 秒边界；任务结束独立触发；多触发合并、运行中新记录保留、未处理段不提前完成 |
| 失败与并发 | 整理／保存失败不丢进度、不阻塞聊天、不自动换模型；重试及重启不重复事件；纠错与后台旧版本冲突不覆盖新内容 |
| 精炼与召回 | 同决策同事件只计一次，后台候选不计；100 轮／不超过 1 次边界；补充事件重算；摘要日期、来源范围及独立索引退出正确 |
| 主观记录 | 事实与感受区分；角色可选择写日记并实际保存、关联、读取；纠错不改原始对话与实际观测 |
| 对话与流式 | 输入状态固定 1 秒、草稿不入模、重复提交不打断、新消息替代旧回复、提交失败保留部分文字，状态只在正式事务完成后更新 |
