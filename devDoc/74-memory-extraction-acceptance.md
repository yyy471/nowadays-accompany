# MEM03 自动fact提取验收标准

日期：2026-10-26。状态：已执行；A/I/Q/O/S关键项在FakeProvider/FakeChannel与隔离临时目录下通过，复核修复与逐项证据见[75 执行记录](75-memory-extraction-execution.md)。对应[73 实现方案](73-memory-extraction-implementation-plan.md)，补充62号T01～T09，范围仅自动fact，不包括summary/页面/遗忘曲线；真实服务与MEM04页面仍待验收。

## 1. 测试条件与放行规则

准备账号A/B、相同peer的群私聊、角色R1/R2、旧v1状态（含autoExtract=true但无激活）、已删除fact、手工修正fact、跨页历史、带媒体/工具的轮次、故障Provider及满额文件。

全部自动测试使用FakeProvider、FakeChannel、隔离临时目录与可控时钟/门控；不依赖真实时间sleep达到5/10分钟，不访问付费服务或生产QQ。P0为越权/隔离/旧结果写回/数据丢失/未授权付费调用；P1为频率、水位、配额、恢复或主链路错误。两级全部通过才能放行。

## 2. 激活、兼容与删除抑制（M3-A）

| ID | 级别 | 操作/故障 | 预期 |
| --- | --- | --- | --- |
| A01 | P0 | 旧文件autoExtract=true升级/重启/页面读取 | needs-confirmation，无模型调用；不静默授权 |
| A02 | P0 | 未鉴权、缺confirm、startFrom非now、过期双expected | 拒绝，无开关/水位/模型副作用 |
| A03 | P1 | 明确激活，聊天已存在 | enabled必须已开；边界准确，旧聊天不回溯；激活不调用模型 |
| A04 | P0 | 删除fact同时有排队/运行提取 | 同次提交删除+暂停+失效；旧结果不能复活，取消通知丢失也安全 |
| A05 | P0 | 清空/关闭/编辑模型fact、写失败 | 原子联动，失败不半生效；手工修正不被模型覆盖 |
| A06 | P0 | 删除后重新激活 | 只处理新激活边界之后消息；旧任务旧激活身份均拒绝 |
| A07 | P1 | 未来新消息再次表述已删信息 | 按方案允许形成新fact，状态/说明不承诺永久语义遗忘 |
| A08 | P1 | 原设置/记录/回执文件重启读取 | 兼容字段准确，原MEM01幂等/容量/CAS回归不退化 |

## 3. 完成通知与输入批次（M3-B）

| ID | 级别 | 场景 | 预期 |
| --- | --- | --- | --- |
| I01 | P0 | 正常文本最终发送成功且持久化 | 仅此类合格完成通知可触发；模型返回不是完成 |
| I02 | P0 | 发送失败、guard抑制、手工/插件发送、工具确认/媒体轮 | 不触发提取，不以伪完成事件启动模型 |
| I03 | P0 | 跨账号/群私聊/epoch相同seq或恶意source | 仅当前scope输入，来源端口不能由HTTP伪造 |
| I04 | P1 | 积压超过50条/24000字符、多个分页 | 正向连续处理，未读中间消息不丢，水位不跳到最新触发seq |
| I05 | P1 | 单条过长、纯媒体、空文本、旧epoch | 明确过滤/跳过计数和游标，不永久堵塞或回填其他角色 |
| I06 | P0 | 助手生成内容、角色/世界书、旧记忆、观察文本 | 不作为新事实来源；群聊保留sender身份 |
| I07 | P1 | 相同完成通知多次、重叠范围、提示版本变化 | sourceKey确定，重复可识别；边界不倒退 |

## 4. 并发、费用与生命周期（M3-C）

| ID | 级别 | 场景/故障 | 预期 |
| --- | --- | --- | --- |
| Q01 | P1 | 少于6条新用户文本/间隔不足5分钟/无新完成轮 | 不调用；无周期后台唤醒补跑 |
| Q02 | P1 | 同scope连续完成，其他scope同时提交 | 每scope1运行+1合并、全局并发/待处理上限准确，普通收发不被阻塞 |
| Q03 | P0 | 账号/全局额度用完、请求失败后立刻重试 | 调用前配额准入，失败仍计数，不能换requestId绕过 |
| Q04 | P0 | 重启/崩溃前已有任务 | 不自动重发付费请求，额度不重置，已提交水位不回退 |
| Q05 | P1 | 网络/超时/鉴权/格式失败 | 至少10分钟冷却，不推进成功水位，日志无正文；新触发条件满足才再考虑 |
| Q06 | P0 | 排队期间撤权、换模型配置、暂停、解绑、退出 | Provider调用前重新校验，未开始的调用为0 |
| Q07 | P0 | Provider已开始后取消/退出、远端不响应abort | 不承诺退款；不无限卡退出，晚结果不写入/投递，取消状态如实 |

## 5. 输出与原子提交（M3-D）

| ID | 级别 | 场景/故障 | 预期 |
| --- | --- | --- | --- |
| O01 | P0 | 模型返回toolCalls/目录/权限指令 | 全部不执行，严格输出拒绝；提取请求没有tools |
| O02 | P1 | 非JSON、代码围栏、未知字段、超长/超条数/证据越界 | 确定性拒绝，不部分写入，不推进成功水位 |
| O03 | P0 | 模型伪造origin/pinned/id/时间/source | 客户端字段拒绝；服务端仅生成model fact与当前批证据范围 |
| O04 | P1 | 空facts、全部精确重复、批内重复 | 视为合法完成，实际处理批次推进一次，无重复记录 |
| O05 | P0 | 输出返回前发生删/改/清空/暂停/角色或generation变化 | 提交重验拒绝旧结果，现有记录/回执/水位不变 |
| O06 | P0 | 模型建议与手工记录冲突 | 不静默更新手工事实，也不以提取结果覆盖模型旧记录 |
| O07 | P0 | 记录写入/rename失败、提交响应丢失、重复回调 | 同文件记录/水位/回执一致；相同sourceKey幂等；成功后不重复模型调用 |
| O08 | P1 | 超1000条/正文总量/实际8MiB字节上限 | 全批拒绝，无半写；暂停或熔断及恢复状态明确 |
| O09 | P0 | 提交发生在另一文本轮活跃期、工具延迟回调 | 按会话链协调，不能用后台generation更新意外破坏正在发送的同scope轮次；旧工具guard仍有效 |

O09要检查提取提交排入会话队列后的实际顺序，不能用直接调用MemoryStore单测替代。仅比较generation字符串不足以证明记录和发送正确。

## 7. 必需端到端证据

至少一组真实FakeChannel→正常Agent发送→稳定消息存储→提取通知→协调器→Fake文本Provider→MemoryStore→下一轮Agent提示词的完整闭环，证明模型fact确实生效，不靠手工调用内部提交伪造完成。

另单独覆盖：删除暂停/重新激活新边界；跨页水位；慢Provider期间角色切换；响应丢失幂等；大字节容量；配额跨重启；已开始调用不再落盘。要同时记录Provider调用数、state水位/条目和通道发送数。

真实服务验证须有执行当次的配置与调用授权，并记录模型/协议/格式限制，不声称Fake通过代表所有服务兼容。无真实条件可限定“实现与自动验收通过，真实服务待验收”。
