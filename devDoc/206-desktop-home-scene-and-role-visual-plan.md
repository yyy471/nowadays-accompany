# 桌面主页精简、环境流转与角色外观入口

本文记录 [DL-132](161-digital-life-direction-decisions.md#dl-132-桌面主页只做角色展示对话与其余功能移到独立页面)、[DL-133](161-digital-life-direction-decisions.md#dl-133-环境与人物动作流转天气来源可切换)、[DL-134](161-digital-life-direction-decisions.md#dl-134-预置角色只保留夏澄角色外观从用户配置的来源获取)的前端实施方案与实现方自验。代码位于 `desktop/desk-preview/`，分支 `dev-front`。

用户已确认的内容以决策记录为准。本文中的参数、文件命名和模块划分是工程设计，不是新增的用户决定。本文取代 [205](205-luminary-study-theater-frontend-plan.md) 中与主页底部在场脉搏、姿态按钮和器物托盘相关的描述。

## 1. 主页

主页只保留五样东西：

| 元素 | 说明 |
| --- | --- |
| 窗景与角色 | 全屏，天气、光影和人物随环境变化 |
| 角色名 | 左上角 |
| 时间与天气 | 右上角只读显示 |
| 一行状态 | 底部。来自后端真实活动时不带标记，按本地日程显示时带“日常”小标签 |
| “去找她” | 进入对话页。角色有主动分享折信时，折信替代这个按钮 |

右上角 `⋯` 菜单默认折叠，里面是日记、记忆、她的一天、设置。只有多个角色时，菜单底部才出现角色切换。

对话页沿用原有的器物剧场（`data-focus="theater"`），左侧保留角色和当前动作说明，右侧是信笺、手账、胶片、推演。本轮没有重新设计这些页面，只是把它们的入口从主页移到了菜单和按钮。

已从主页移除：五个姿态按钮、底部器物托盘、前景角落文字、台灯按钮、环境调节怀表胶囊、角色并排头像、模拟活动入口。点击人物不再切换动作。

## 2. 环境流转

`environment.js` 是唯一的环境来源，是纯函数，浏览器和 Node 都能加载。渲染层只读它的结果。

| 项目 | 做法 |
| --- | --- |
| 日出日落 | 随日期连续变化。夏至约 5.3～19.5 时，冬至约 7.0～17.0 时 |
| 季节 | 边界为 3/1、6/1、9/1、12/1，边界前后各 5 天交叉过渡。输出 `seasonFrom`、`seasonTo`、`seasonBlend` |
| 时段 | 清晨、白昼、黄昏、夜阑，时段间平滑过渡，规则沿用原有 |
| 台灯 | 由室内亮度自动决定：夜越深、云越厚越暗，低于阈值点亮。设置里可以手动覆盖 |
| 天气强度与风 | 输出 `weatherIntensity`、`cloudCover`、`wind`，雨丝密度、水珠数量、雪量和树枝摆动幅度随之变化 |

春夏的窗外底图目前没有，季节混合量已经算出但没有对应的图可用，画面仍用现有的秋景和雪景加调色。补图后接入即可。

开发时可以用 URL 参数检查：`?at=2026-12-24T18:30` 固定起始时刻并继续走时，`season`、`weather`、`time`、`lamp`、`activity`、`weatherSource` 可以覆盖对应项。

### 天气来源

`weather-provider.js` 定义来源接口：`{ id, available, sample(now, ctx) → { kind, intensity, cloudCover, wind } | null }`。

- `simulated`：离线、确定性。同一时刻总是同一天气，所以重启不会重新抽签。天气按 3 小时一段，用按季节调整的转移概率逐段推演。切换天气时 5 分钟内强度先降到 0 再升起。冬天才下雪，其他季节才下雨。
- `real`：占位，`available` 为 `false`。选择它时回退到模拟，并在设置里提示“真实天气尚未接入”，输出带 `weatherFallback: true`。
- 设置里的“天气来源”开关已可切换并保存在本地，后续接入真实天气只需实现来源接口并把 `available` 置为 `true`。真实天气的定位和联网方式尚未讨论。

## 3. 角色与外观

`createRoleProfile` 按后端角色清单建档，连上后端后以 `GET /v1/roles` 为准。离线时只有夏澄一份演示档案。

`role-visual.js` 提供角色外观适配器：

- 外观来源是函数 `(roleInfo) => manifest | null | Promise`，依次尝试，第一个返回清单的生效。内置来源只认识夏澄。用户配置好的位置确定后，在 `app.js` 创建解析器的地方加一个来源即可，不改渲染代码。
- 清单中的坏数据（未知动作、空路径）会被丢弃并写日志，不会让主页打不开。
- 没有立绘的角色显示印章占位。
- 来源返回的清单会整体替换内置清单。来源只给动作图而不给基础立绘时，基础立绘会变成占位。如果希望和内置清单合并，需要另行调整。

### 动作

动作集合共 7 个：`reading`、`writing`、`thinking`、`tea`、`window`、`sharing`、`resting`。

当前动作按优先级选择：

1. 后端状态里的 `activity`（真实活动）。
2. 天气反应：下雨或下雪且强度大于 0.3 时，约 40% 的停留时段看窗。
3. 本地日程：深夜和午休小憩，清晨喝茶，上午和下午阅读，傍晚执笔，晚间静思。

每 2 分钟为一个停留时段，同一时段内结果固定。按日程算出的动作在主页以“日常”标记，且不会写回后端状态。

后端目前没有实时活动流，只能读取状态里的 `activity` 字段，所以“真实活动”实际只覆盖这一个字段。

### 动作图投放规范（工程提案）

- 格式与尺寸：透明底 WebP，1024×1536，和现有 `xiacheng-day.webp`、`xiacheng-night.webp` 一致。人物底边对齐画面下缘，水平居中。
- 每个动作可以给 `day` 和 `evening` 两种光照。只给一种时两种共用。`evening` 在夜间和黄昏使用。
- 缺少某个动作的图时，该动作显示基础立绘，不会报错。
- 清单格式：

```js
{
  seal: "澄",
  sprites: { day: "…", evening: "…" },
  actions: { tea: { day: "…", evening: "…" }, window: "…" }
}
```

文件存放位置和清单的读取方式由用户配置的来源决定，目前未确定。

## 4. 删除阿柚

- 前端：删除角色表、立绘占位、角色并排头像和相关样式，删除 `assets/photo-ayou.webp`。
- 桌面主进程：首次启动只创建夏澄，离线模型的固定回复不再区分角色。
- 后端没有删除角色的接口。已经存在于本机旧数据目录里的阿柚不会被清除，连上后会出现在 `⋯` 菜单的角色切换里，需要时请自行清理数据目录。

## 5. 实现方自验

范围：Electron 渲染进程离线加载 `index.html`，没有启动后端，也没有重新打包 EXE。

- `npm test`（在 `desktop/desk-preview`）：21 项通过。覆盖季节过渡的连续性、日出日落、时段、台灯、手动覆盖、模拟天气的确定性与季节合理性与连续性、来源回退、外观清单校验、动作优先级与停留时段。
- 截图：秋季白天晴天、冬季雪夜、春季雨夜、夏季自动天气、对话页、菜单展开、设置抽屉。主页只有设计要求的元素，对话页和设置页正常显示，控制台只有“后端离线”这一条预期警告。
- DOM 检查：天气来源开关切换后状态、说明文字和本地存储同步；给一个测试来源提供 `tea` 动作图时，动作图淡入显示并盖住基础立绘，没有图的动作回退，未知动作写日志并忽略。检查后已恢复代码和本地存储。
- 渲染层：雨丝、水珠、雪量和风力已读取新字段，只检查了代码路径和静态截图，没有逐帧检查动态效果。
