## 1. 本轮交付

- 设置弹窗分为模型服务、连接、外观、诊断；普通打开记住本次运行的分类，定向入口进入指定分类。连接表单保持单一实例，切换分类不丢失输入。
- 模型服务保留文本、视觉、视频三个固定入口，生图和语音为扩展；填写 Base URL，不增加本地/云端选项或凭据引用输入。
- 新增默认折叠的“全部服务”：编辑地址、适配器、模型名和密钥；清除密钥与删除服务独立操作。保存后可以去账号模型配置，经过统一草稿导航保护。
- 编辑保留原高级参数、模型能力、工具支持标志及媒体策略；dirty 草稿不被刷新覆盖，检测到服务新基线后阻止旧草稿覆盖，重新读取前确认放弃。
- 删除先读取影响账号、再确认、最后执行删除；取消、预览失败、卸载取消确认都不删除。操作期间登记 busy，防止重复提交及离开。

分任务证据：[37 设置壳](37-stage-c-settings-execution.md)、[38 模型服务管理](38-stage-c-models-execution.md)。

## 2. 后端与契约

新增经过现有 API 鉴权的 `GET /providers/:id/impact`，只对 ConfigStore 快照计算影响，不写配置、备份或凭据。预览与实际删除共用 `src/providers/provider-removal.ts`，清理账号授权、账号绑定、群/私聊类型和具体会话的绑定及回退项，避免两处独立实现。

调用链仍为 routes → Core → ModelSettingsService → ConfigStore。未新增另一套 Store 或配置格式。

通用编辑请求新增顶层 `inferLocationFromUrl: true`：服务端复用已有 `inferProviderLocation`，使改址后的内部来源与 URL 对应。前端不复制推断逻辑。旧调用不带标志时继续尊重显式 location；标志类型错误或 URL 无效返回 400，配置不变。

预览是读取时快照；确认期间若另一个调用修改账号绑定，最终删除返回实际 affectedAccounts，前端展示实际结果。此次未引入跨客户端配置版本条件写入。
