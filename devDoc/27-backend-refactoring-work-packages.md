# 后端改造任务包与验收标准

日期：2026-10-23。状态：可派发的实施计划。目标架构以[26号文件](26-backend-target-architecture.md)为准，问题依据见[25号文件](25-backend-consolidation-review-and-plan.md)。

## 1. 执行约定

- 开始实施前先冻结当前用户改动，形成可恢复的基线。最近一次核验是46个测试文件、289项通过；执行者应在自己开始时重新记录结果，不把旧结果当成当前结果。
- 每个任务独立提交，提交必须同时包含迁移后的调用方和必要回归测试。不能先加第二套实现，长期保留新旧两条独立路径。
- 每份任务交付：变更范围、唯一能力入口、兼容说明、测试命令与结果、未解决事项。任务负责人不能仅以“编译通过”宣称验收完成。
- 测试源码进入Git；截图、报告、临时复现与release产物不进入Git。默认不进行真实QQ注入或付费模型调用，使用模拟服务和临时数据验收。
- 不改变公开Core/HTTP调用语义、旧导出路径、账号目录及数据格式；确有必要变更时先提出单独迁移方案。

## 3. 可直接派发的任务说明

### B00：冻结基线，列出不能改变的行为

目标：整理当前未提交改动并形成可恢复提交；运行类型检查和全量测试，记录当时版本与结果。

交付一份行为清单：QQ身份/进程映射、显式注入、恢复资格、暂停/停止区别、角色逐会话绑定、模型账号级授权、凭据版本、生成请求未知结果、账号存储隔离。

验收：能用提交号重建本次治理起点；无测试产物和release误入Git；已知问题与已有失败明确记录。B00只准备基线，不解决全部历史问题。

### B01：修复Semaphore名额交接

范围：`src/core/concurrency.ts`、相关回归测试。保持现有constructor、acquire、run调用兼容。

要求：直接交接名额、排队公平、release幂等。先用“排队者被唤醒前新请求到达”的确定性反例验证旧问题，再修复；不要只用大量随机并发代替反例。

验收：上限1时任何交接过程active不超过1；重复release不增加可用名额；run抛错会释放名额；实例启动/重启、OneBot动作、媒体任务现有测试不退化。可先保持原路径，实现迁移到platform/async时通过兼容重导出完成。

### B02：串行执行、文档提交与展示资料丢更新修复

范围：`platform/async`、`platform/fs`、展示资料Store及对应调用方。现有atomic-write可以先保持原路径，迁移时旧路径重导出。

要求：提供实例级SerialExecutor、KeyedSerialExecutor，明确run/drain/close、容量、失败恢复与空闲键回收。将展示资料完整读改写放到同一资源串行域。先把能力接入该确定存在问题的用例，不一次性替换所有Promise链。

文档型修改采用“读取已提交状态→校验/合并→落盘成功→发布状态/事件”。当前展示资料自由函数并非`src/index.ts`公开导出，可以迁为Store方法并同步内部调用及测试；公开的`Core.saveAccountDisplay(accountId, raw)`签名保持不变，直接委托Core拥有的Store。不能给每次调用创建新队列，也不能增加模块级全局Map。

验收：并发修改昵称和签名都保留；同账号竞争被串行化，不同账号独立；失败修改不会进入已提交内存快照；后续修改能恢复；close拒绝新任务并等待在途任务结束。超时不能使同一资源的后台任务继续与后继任务重叠。

补充审计：逐个记录ConfigStore、DesiredStateStore、SlotStore、ListeningStore等失败时内存/磁盘的行为。其他Store接入分独立小提交，不把通用机制误当成跨文件事务。

### B03：统一AccountDirectory与AccountPresentation

范围：`profiles/account-directory.ts`、展示资料Store、头像缓存组合、Core中账号路径及展示相关方法。

AccountDirectory统一默认目录、自定义账号目录和已运行实例对应目录；区分resolveExisting与业务允许的create，查询未知账号不能偷偷创建目录。AccountPresentation统一真实昵称、本地别名、账号号、本地头像/QQ头像回退优先级。

验收：账号列表、主页资料、进程卡片、角色绑定、消息/媒体/插件状态使用一致账号根；自定义目录用例通过；昵称与身份分别处理；探测提示不会建立账号租约；跨账号头像/别名不串用；头像接口失败按原规则回退。

不要求一次移动所有Store目录。先统一路径解析入口，再逐调用点迁移。

### B04：抽出控制面契约与整理错误归属

范围：`contracts/`、`application/ports/`、公共错误和兼容导出、server/Core及前端类型引用。

将CoreView等控制面端口和传输DTO从server实现中抽出。只共享浏览器可用的纯类型，内部领域对象不直接成为API响应。公共错误保持一个构造器；MediaError、JobError逐步回到所属模块，原路径兼容重导出，避免破坏instanceof。

验收：Core不再从HTTP实现文件导入契约；领域模块不依赖HTTP/Electron/React；前端构建不引入Node运行时代码；错误码、状态码和脱敏结果保持兼容；模型配置和凭据DTO无明文泄露。已有模块不必为了目录形式而重命名全部错误类。

### B05：提取AccountService

范围：`application/accounts`、Core的账号用例委托及账号路由调用。

迁移账号列表、展示资料、插件资料、角色绑定等用例。通过窄运行端口请求重载或读取实例状态，不将整个Core传给AccountService，不直接持有QqConnectionService制造互相调用。

验收：Core、HTTP、CLI委托同一实现；每个私聊/群聊仍必须显式绑定角色卡；保存失败/重载失败的返回与原接口一致；迁移后的原Core方法仅委托，不保留第二套业务判断。

### B06：提取QqConnectionService和ProcessReconciler

范围：`application/qq-connections`、Core的接入方法和定时器、相关控制面调用。

复用ManualInjectionService管理注入操作；复用Supervisor管理实例，不重新建立注入状态机或账号所有权表。ProcessReconciler接管扫描、映射代际、失联阈值和清理；列表查询读取其快照，显式刷新可触发一次reconcile。

验收：新旧扫描与换号结果一致；网络失败不能当作空进程列表；旧快照不能删除新连接；PID复用不能绑定旧账号；候选展示和恢复执行资格仍由同一规则得出；用户停止不会被后台自动恢复；注入前提示不等于已验证身份；扫描/监听/退出无死锁。

特别要求：写出本用例锁顺序。不要在持有某锁的情况下调用会再次取得同一锁的用例。停止和移除的调用关系须避免Core门面与服务互相回调。

### B07：提取ModelSettingsService

范围：`application/model-settings`、模型配置/凭据相关Core方法、模型路由调用。

迁移全局服务维护、简化配置、模型发现、测试与账号绑定用例。复用ConfigStore、PolicyService和ProviderRouter，不在新服务中重新实现能力授权、计划指纹或回退策略。

验收：对话/视觉/视频及扩展能力仍按账号配置；配置服务不自动开放工具；凭据加密与撤销规则不变；排队期间配置变更会在执行前复核；生图/语音远端结果未知时不自动重提；配置失败不会返回伪成功。

### B08：提取DeploymentService

范围：`application/deployments`、Core部署/回滚方法、制品路由调用。

将目标收集、调用RollingDeployer、结果记录和查询收为一个用例入口；继续使用现有部署器和制品Store，不复制部署串行器。

验收：按账号滚动切换；单账号失败保留原有效worker；旧revision在途行为与状态写入保护不变；回滚与部署错误响应兼容；同一部署不能被新旧两条路径重复执行。

### B09：最后拆Core装配与生命周期

范围：`bootstrap/assemble-runtime.ts`、`application/lifecycle`、Core构造/静态创建/启动关闭。

先列资源所有者和启动/关闭依赖顺序，再迁移装配。assemble-runtime不导入Core类；Core门面接收已装配的服务。保留createCore、Core.create等外部入口和现有注入工厂能力。

验收：创建失败释放dataRoot锁及已创建资源；关闭先拒绝新工作、停止周期任务，再排空在途工作并释放依赖；同一个Core的资源不重复关闭；一个Core关闭不影响另一个Core。启动不新增自动QQ/SnowLuma操作。

### B10：抽取有界响应读取和取消能力

范围：`platform/http`，OpenAI/视频适配器、模型发现、SnowLuma管理和头像读取按小提交接入。

第一步仅统一读取上限、流中止、超时覆盖响应体和基础错误脱敏；保留端点访问策略、协议解析及业务重试所有者。

验收：超限在完整缓冲前取消；慢响应体超时；调用方取消能结束读取；重定向遵守各类端点规则；本地模型仍可配置；附件不能因复用本地模型策略而开放原先禁止的地址；生成结果未知不重提。远端伪服务必须覆盖这些反例。

### B11：拆HTTP路由并建立架构守卫

范围：`service/http`、`service/routes`、架构约束测试及文档。

HTTP基础只负责鉴权、参数解码、错误映射、SSE和静态资源；路由委托应用端口。按领域建立公开入口，新增跨域调用优先走契约或注入端口。

验收：现有HTTP接口契约和错误码兼容；SSE顺序、续传和容量上限不退化；生产普通JSON覆盖写只经公共原子写入能力；对锁文件、JSONL追加、日志等特殊写入建立明确例外。依赖检查能阻止新反向依赖与重复入口，但不禁止有明确契约的领域协作。

## 4. 并行与集成安排

第一批：B01、B02、B04可分别开发；B03等待B02的接口固定。基础能力目录和契约导出各指定一个负责人，禁止多方同时建立不同版本。

第二批：B05～B08可按服务实现文件分工，但Core、server和公共契约的集成由同一负责人顺序合并。各任务先提供窄端口和委托改动，不同时大范围编辑Core。B10可在契约边界稳定后独立推进。

第三批：完成服务集成后执行B09，再完成B11与总验收。不在其他任务仍依赖旧构造时提前搬迁Core创建过程。

## 5. 总体验收与回退

- 执行`npm run typecheck`、`npm test`、`npm run desktop:build`，与B00记录比较，新增测试不能替换或删除原有关键反例来获得通过。
- 独立验收并发名额交接、并发字段更新、跨账号并行、写失败恢复、PID复用/账号切换、服务不可达、凭据撤销、生成结果未知以及关闭排空。
- 使用临时数据跑通：启动→检测→显式连接模拟QQ→角色绑定与模型配置→消息处理→暂停/停止→重启候选展示。真实QQ操作另行实机验收，不冒充已通过。
- 新目录中的实现有明确调用方；旧兼容路径只转发。Core和HTTP内不再各自拥有同一业务规则，不以减少行数替代这一检查。
- 不改账号数据schema时，按任务提交回退即可；若任务产生了数据迁移，应先停下并补充迁移/回退方案，不能继续套用“回退代码即可”的假设。

建议派发指令：先执行B00；随后派发B01、B02、B04，完成独立验收后推进B03。每个执行者阅读26号架构说明、对应任务以及相关现有测试，提交实现与验收记录，交集成负责人复核后再开始下一批。
