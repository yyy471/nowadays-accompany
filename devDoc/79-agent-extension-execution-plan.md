# Agent 主体、统一工具与扩展作用域执行方案

日期：2026-10-26。状态：待实施，可按任务包派发。验收依据见[80 执行验收标准](80-agent-extension-acceptance.md)。

本方案落实阶段回顾中的第2、3、4项：Agent与插件协同、统一工具执行、群私聊扩展隔离及Skill管理。用户已明确当前没有需要兼容的旧插件，因此只实现一套标准，不建设双协议、旧宿主兼容或插件独占回复模式。记忆管理页面列入后续待做，不在本轮实现。

## 1. 目标与范围

最终产品行为：每个已绑定角色的会话，由Agent统一组织角色卡、世界书、事实记忆、Skill及插件提供的数据；模型可以选择已授权工具；工具执行结果返回同一轮对话，Agent决定最后如何回答。安装插件不会替换Agent。不同账号、群聊和私聊可以使用不同插件、工具和Skill。

本轮交付：

- 单一Agent编排入口，插件通过受控钩子和工具扩展。
- 工具定义、授权、参数校验、执行、幂等记录、返回及模型续答统一。
- 生图、语音迁入统一入口，继续复用现有媒体任务和交付链。
- 插件工具可实际被模型调用，提供一个无外网、无付费依赖的示例插件验证闭环。
- 账号/群私聊/具体对象的扩展策略，以及全局和账号私有Skill管理。
- 清理互斥回复模式和原插件消息回复协议，不保留两套运行路径。

本轮不做：具体网页浏览/视频浏览/QQ空间工具、浏览器自动化引擎、跨账号工作流、任意插件市场、操作系统级恶意代码沙箱、通用长任务调度平台、记忆管理页面、摘要/情绪/遗忘曲线。工具框架应允许以后接入这些能力，但不能以一个注册接口宣称这些业务已经实现。

## 2. 代码基线与应收口的位置

| 当前代码 | 现状 | 本轮处理 |
| --- | --- | --- |
| `core/core.ts`、`policy/policy.ts` | 根据replyMode选择插件宿主或Agent | 删除互斥分支，统一组合宿主 |
| `host/worker.ts` | 每账号Worker执行onMessage，可直接产生回复和发送列表 | 改为单一插件运行协议，不再拥有自动回复权 |
| `extensions/registry.ts` | 工具描述注册，无统一handler执行入口 | 拆清静态目录、账号运行时绑定和可执行入口 |
| `agent/engine.ts` | 只处理第一个toolCall，生图/语音分支硬编码 | 有界工具循环，按注册handler分发 |
| `providers/contract.ts`、`adapters/openai.ts` | 输入尚无完整assistant工具调用消息表示 | 增加结构化assistant toolCalls及对应序列化 |
| `profiles/profile.ts` | 账号选择插件并解析版本 | 保留安装/选择事实，不承载另一份运行授权策略 |
| `providers/config-store.ts` | 保存模型、账号策略、公用/私有Skill | 复用唯一写入链，提供扩展子树CAS操作 |
| `jobs/`、`media/` | 生成任务、媒体存储、延迟交付 | 继续复用，不写第二套生图/语音任务 |

建议新增应用用例模块`application/extensions/`；扩展协议、目录、作用域解析、工具执行分别放入`extensions/`内的明确模块。Core只装配与委托，不继续堆积插件解析、策略合并和工具执行细节。

## 3. 单一运行链路

```text
QQ消息 → 原会话队列 → 角色/世界书/记忆快照
  → 有效扩展快照 → beforeContext数据钩子
  → 上下文构建（含有效Skill）→ 模型
  → 无工具：最终回复
  → 有工具：整批预检 → 统一ToolExecutor → 工具结果 → 模型续答
  → 原发送入口及历史持久化 → afterTurn通知
```

原会话队列、跨会话调度、角色与memory guard继续生效。新扩展快照至少包含账号、kind/peer、scopeToken、所选插件固定版本、runtimeGeneration、有效授权/Skill内容摘要及配置revision。调用前、出队后、执行副作用前、返回后及最终发送前按需要重验。

扩展变更不修改角色的history/contextEpoch，也不创建新的记忆命名空间；它使用独立extensionGuard使旧扩展任务失效。其他账号或其他会话的无关修改不能让当前对话误失效。插件版本、handler绑定或相关授权变化必须使旧工具失效。

账号暂停、未绑定角色、解绑、退出仍停止自动处理，不允许插件通过另一条回复入口绕过。

钩子错误、超时或结果不合规只使该插件本轮补充数据失效并记录原因，普通对话继续；不能让一个插件失败阻断全部Agent。afterTurn按最终发送/抑制/失败的真实状态通知，失败不撤销已完成的发送，也不阻塞下一轮。包含补充数据的轮次不标记为MEM03纯文本提取候选。

### 3.1 删除互斥模式

删除`ReplyMode`、`replyModeFor`、配置里的auto/agent/plugins及对应页面选择、DTO和诊断文案。保留正常的Agent启停开关。自定义host若仅为内部注入端口可以保留，但不能作为面向用户的第二套插件标准。

现有开发数据若含废弃字段，交付一次性开发配置整理说明/脚本：只移除明确废弃的replyMode等字段，保留模型、凭据引用、角色、授权和历史。不要通过静默吞字段保留隐形兼容，不要清空用户数据或自动开启工具。没有旧插件需要迁移；仓库内示例和协议消费者直接改用新标准。

## 4. 插件标准与生命周期

开发期直接修订现有插件`apiVersion:1`为本轮唯一标准，所有导入、目录读取、版本解析、运行时加载使用同一严格schema。不再额外支持旧onMessage/reply/sends协议。

插件manifest增加声明性`tools`、`skills`和`hooks`；manifest只含可校验JSON，模块入口提供声明对应的handler。所有声明先经过制品原有安全路径和发布校验。manifest未声明的导出不能成为工具，声明没有可用handler也不能被提供给模型。

插件可用端口：

| 端口 | 内容及边界 |
| --- | --- |
| 初始化/关闭 | 初始化本插件资源、有限时间清理；没有QQ发送、自动模型调用端口 |
| beforeContext | 返回有来源标记的补充数据；不修改角色、system指令、权限或原消息，不直接发送 |
| afterTurn | 收到最终结果摘要/状态；不产生第二条自动回复，不触发递归模型调用 |
| tool handler | 接收校验后的参数与宿主生成的只读上下文，返回结构化结果 |
| state | 默认按账号+插件来源/id+会话kind/peer+角色contextEpoch隔离，由宿主生成路径 |

账号级共享状态须在manifest显式声明并由账号启用，不能把群成员数据默认混入整个账号共享状态。插件版本升级默认保留同插件状态命名空间，要求声明stateVersion；不兼容升级应明确拒绝或显式迁移，不能默默丢弃状态。不同角色contextEpoch默认不共享会话状态。

建议每账号、每插件一个Worker，串行执行该插件的钩子/工具/状态变更，不把所有插件塞入同一个不可独立终止的Worker。不同插件/会话可在全局限额内运行，同一插件的跨会话调用可以排队。不要为每条消息新建Worker。

消息RPC必须带requestId、账号、插件完整来源、runtimeGeneration及会话scope；结果、状态提交和迟到响应均核验。Worker超时后终止本插件运行代际并丢弃晚结果，不能只Promise.race后让旧任务继续写状态。插件重新加载前不自动重跑已发生副作用的工具。

先实现只读数据钩子和通用工具，插件不提供直接send或递归调用Agent的端口。需要模型/媒体能力的工具通过宿主受控能力端口请求，并复用ProviderRouter/MediaJobService；RPC处理不能排在当前正在等待它的会话链或插件请求之后，避免互等死锁。

Worker是生命周期与故障隔离，不是任意Node代码的操作系统权限沙箱。本轮标准面向用户信任的本地插件，不能宣称已阻止恶意模块自行访问文件/网络。

## 5. 统一工具执行

### 5.1 工具身份与契约

工具身份使用完整来源，区分`builtin`、`public/plugin/<id>/<tool>`、`private/plugin/<id>/<tool>`；固定版本和runtimeGeneration另行捕获。同id的公用/私有插件不能互相覆盖handler或授权。

模型工具名由宿主映射成协议支持的稳定名称，检测碰撞，单轮固定映射；执行只通过该轮映射找handler，不能按模型返回的任意字符串动态import或访问文件。

工具描述至少声明输入schema、输出上限、超时、effect（read/action）、所需模型能力（可空）、owner。可执行绑定必须同时具有handler与所属运行代际。没有模型capability的工具仍必须经过工具授权，不能因为capability为空就默认开放。

统一结果包含：调用ID、状态`ok/error/submitted/unknown`、安全错误码、有限文本/JSON数据、可选jobId或账号内media引用。禁止返回宿主路径、密钥和任意跨账号对象句柄。原始页面/网络内容作为带来源的工具数据进入tool消息，不拼成system指令。

### 5.2 执行顺序

1. 按本轮scope和能力筛选可执行工具，再将描述提供给模型。
2. 对模型返回的整批调用预检：名称、重复ID、参数解析、输入schema、当前授权、handler版本及剩余预算；任何预检错误则整批不执行副作用，逐项返回明确拒绝结果。
3. 通过预检后顺序执行，副作用前重验；每一步仍可能失败，已执行的外部动作不能承诺全批回滚。
4. 结果校验和限长，写执行回执，再构造tool结果；失效/取消不得写回新代际或向QQ交付。
5. 模型读取工具结果后继续回答。模型输出文本与工具调用并存时，文本先作为内部assistant消息，不提前发送两份回答。

参数schema首轮采用明确有界子集：object/array/string/number/integer/boolean/null、properties/required/additionalProperties、enum、长度/数值/数组数量限制；递归深度、属性数、schema字节数均有上限。不支持的schema关键字在注册时拒绝，不假装执行完整JSON Schema。

### 5.3 幂等与副作用记录

在账号私有目录实现最小`ToolInvocationStore`，作为工具执行账本，不建设通用任务平台。复用现有串行与原子写原语。记录invocationKey、参数摘要、scope/代际、工具完整身份、状态和有限结果引用，不记录完整聊天或敏感参数。

invocationKey由宿主生成：账号+kind/peer+原始入站消息稳定标识/seq+轮内模型回合+调用位置/规范调用ID+工具身份。无模型callId时生成确定性内部ID并用于assistant/tool消息配对。重复ID拒绝；重试同key不同参数返回冲突，不能再执行。

effect=action的工具必须先持久写入started意图，再触发副作用；写入失败则执行0次。完成记录与外部动作无法物理原子，进程在两者之间退出时恢复为unknown/interrupted，禁止自动重试。成功/进行中/结果未知的重复key都不能重复执行动作。

首轮建议账本每账号最多256条终态回执、7天保留，进行中和未知动作不能为了腾空间自动删除；文件上限2MiB，满额拒绝新动作并明确状态。幂等保证限于保留窗口，不承诺外部exactly-once。重启不恢复执行、不自动付费补跑。只读工具同样要有本轮幂等和预算控制。

生图/语音的invocationKey映射到现有job actionId，不能在统一工具账本和MediaJobService分别重复提交。完整关闭时先停止工具准入、取消本地等待，再有限排空；远端不响应取消时不承诺撤销动作或退款。

### 5.4 工具循环与成本边界

补齐`ChatInputMessage`中的assistant toolCalls结构，以及OpenAI兼容适配器的assistant.tool_calls和tool_call_id序列化；工具结果必须关联同一调用ID，不能用普通user文本冒充工具协议。

默认一轮最多3次工具回合、累计4个请求工具调用、4次模型调用；被拒绝的请求也消耗调用预算，防止无限修复循环。最后一次模型请求不再提供工具；仍返回工具调用则终止执行并给有限说明。多调用按原顺序处理，不再只读`toolCalls[0]`。

首轮工具参数最多16KiB/调用，结果最多8KiB/调用、累计24KiB/轮；必须同时遵守现有总上下文预算，不能为工具结果无界扩容。超限返回带截断/拒绝标识的有限结果，不把完整大对象塞入模型。

工具执行默认30秒，同步工具执行期间占当前会话轮次；同账号其他会话仍可运行。全局工具并发默认4、每账号2，排队最多32，钩子单次500ms、单轮总计2秒。限额由统一服务实现，不在每插件各写一套。

生图/语音继续提交现有异步媒体任务，工具立即返回submitted和jobId，模型可以说明“已提交”，不能在结果尚未生成时声称已生成/已发送。媒体完成继续通过原会话延迟交付和guard；不要在占用该会话链时等待必须回到同一链完成的任务。

工具协议中间消息只用于本轮临时模型上下文；普通历史仍保存实际用户消息及实际对外回复。工具账本另存摘要。MEM03完成标记仅保留无工具、无插件补充数据等原有合格纯文本路径，不能把工具结果/补充数据当成用户事实自动提取。

## 6. 群私聊作用域与唯一策略源

插件安装/所选版本仍由账号profile管理；运行开关、授权和Skill策略只由ConfigStore的账号扩展子树管理，不在profile再存一份相同运行策略。新增ExtensionApplicationService提供局部读写和有效状态解析。

现有`enabledTools`及Skill enabled/disabled的运行选择整理到这一套策略；整理成功后删除旧字段和旧判定分支，不同时维护两个授权源。已有生图/语音明确授权仅作等价搬迁，不扩展为所有工具允许；公用/私有Skill的正文仍使用现有定义存储。profile的插件停用只表示安装不可用这一硬边界，不另行承载群私聊开关。

有效执行条件是以下条件的交集：账号持有该插件且未停用、插件handler已就绪、账号工具授权、会话有效开关、声明允许的作用域、所需模型能力和Agent/角色状态。细作用域不能重新启用未安装/账号停用的插件，不能突破账号工具授权或服务授权。

运行开关采用`inherit/on/off`，覆盖次序账号默认→kind(private/group)→具体kind+peer。kind层off属于软运行开关，具体会话可以显式on覆盖，前提是账号硬授权仍允许。撤销账号硬授权总是优先。会话键必须包含kind，不使用裸peerId。

新安装插件默认没有自动工具授权，群私聊运行开关默认off；用户在账号页明确启用目标作用域。新版本新增工具、钩子或Skill不能借用旧版本授权自动扩大范围；新增声明需明确授权，已有相同权限可保留。全局资源发布不等于账号启用。

插件/工具/Skill都返回有效来源及不可用原因，例如未安装、作用域关闭、未授权、依赖能力缺失、handler未就绪、版本变化。页面展示与模型可见工具、钩子执行使用同一个解析器，不能前端自行算一套。

账号暂停/解绑/角色变化/插件禁用/工具撤权立即阻止尚未开始的执行，已在途结果丢弃或标记不能交付。取消仅节省资源，硬保证来自副作用前和提交/交付前的重验。

### 6.1 存储、CAS与生效状态

复用ConfigStore mutation链，新增扩展子树原子patch和expectedRevision；版本摘要覆盖该子树以及相关profile插件清单，事务中检查关联profile版本。前端不回传整个AccountPolicy覆盖providers、模型绑定或其他作用域。

profile安装版本与config策略是两文件，明确使用末次关联版本校验作为逻辑提交边界，不声称跨文件原子事务。每次执行动态重验安装和授权；不依赖“重载事件一定送达”保证安全。

保存策略成功与Worker重载成功分别返回`persisted/applied`及原因。落盘失败无生效；已落盘但Worker启动失败则展示配置已保存、插件不可用，不能返回整体成功，也不通过改写另一个文件伪造回滚。

## 7. Skill的统一管理

Skill只有说明、工具引用和依赖，不是另一套可执行JS或权限来源。可用性沿用统一作用域解析，并且所有引用工具都必须有可执行handler且已授权。启用Skill不会自动开启工具。

来源：公用用户定义、账号私有定义、所启用插件的声明。公用/账号私有定义继续使用ConfigStore现有skills与账号definitions存储；插件提供的Skill绑定完整插件来源，不复制到公用或账号定义里。

现有用户定义同id的账号私有覆盖公用语义保留；插件Skill使用完整命名空间，不能遮蔽用户定义。页面展示实际来源和覆盖关系。Skill本身的声明范围与账号策略范围取交集；新作用域使用明确kind+peer键，旧peers/kinds声明作为定义限制统一解释，不成为第二个策略存储。

支持公用定义新增/编辑/删除、复制为账号私有、账号私有编辑/删除、启停、群私聊和指定对象覆盖、依赖诊断与只读有效预览。预览不调用模型、不执行工具、不修改配置。删除定义前展示引用影响；保存使用CAS，公共修改使受影响会话extensionGuard变化，不影响无关账号。

首轮限制：说明正文8000字符、每Skill最多8个工具、单scope最多8个Skill进入提示词、说明累计16000字符，并受原总上下文预算约束；按账号私有→公用用户定义→插件声明、各来源内按完整id升序选择，状态标注因预算未注入项，不静默截断重要指令。后端和页面使用同一计算逻辑。

## 8. API与前端接入

建议路由，具体命名实施时统一在`contracts/extensions.ts`定义：

| 路由 | 用途 |

| GET `/accounts/:id/extensions` | 插件、工具、Skill目录、运行状态、revision，不含凭据 |
| PUT `/accounts/:id/extensions/policy` | 带expectedRevision的局部策略patch，后端校验授权与范围 |

| POST `/accounts/:id/skills/private`、PUT/DELETE同集合的`/:id` | 私有定义/从公用复制，scope在服务器确定 |
| POST `/accounts/:id/extensions/reload` | 用户明确重载失败插件，不重放工具调用 |

复用现有鉴权、请求体限制、审计和错误映射。第一轮不提供任意HTTP工具执行入口，不把模型执行器直接暴露给页面。页面的配置测试不应隐式调用副作用工具。

前端沿用工作台：现“账号插件”扩展为“插件与Skill”，包含账号插件、工具授权、Skill三个标签；公用Skill管理放资源库，模型配置仍只管理五类模型绑定与能力，不把模型服务再拆到会话。

先选账号，再配置账号默认、群/私聊、具体对象；明确展示继承来源和账号硬停用原因。不要新增会话聊天、任务媒体历史页面。角色/世界书页面保留原职责。

所有控件复用现有ui导出，接入已有草稿保护、账号切换代际、加载/失败状态及焦点处理；异步旧账号响应不能覆盖新账号。插件页不得再宣称“Skill必然由插件提供”，应准确展示多种来源。
