## 4. 原型验收与实施顺序

1. 先画两个最短任务。全局设置中填写服务，手填模型 ID 或获取列表，主动测试后保存。回到角色配置绑定对话模型，记忆模型默认显示继承。每页明确保存范围，空状态可跳转到下一步。
2. 角色配置并行画设定、外观、声音、扩展和自主额度。声音画克隆／预置互斥、试听中、参考缺失、模式待确认、音色下架。外观画上传进度、部分失败、缺主页图和当前服饰。自主额度画已用点数、无限制和预算暂停，现有接口足以支撑。
3. 先完成模型凭据与连接能力，再接入音色管理及错误状态。角色编辑对象、直接删除、运行限制与单份语音配置按第 8 节设计和验收。

离线复跑角色、资源、模型、外观和 TTS 六组现有测试，50 项通过。模型列表异常响应由模拟 `fetch` 复现。新增接口、真实服务联调和桌面凭据跨重启验证属于后续实施。

## 6. 从建角色到启用扩展的完整链路复核

2026-11-10，按最新需求重查角色创建、外观、对话、记忆整理、TTS、生图和扩展。第 1～4 节保留原始缺口复核，本节作为下一版原型的流程和接口缺口清单。表中的接口补法及删除语义是工程建议。

### 6.1 页面顺序与生效条件

1. **创建角色并保存设定。** 填显示名和人设正文，建立独立角色实例。新增结构化人设字段时，应先明确是展示信息还是实际参与 Agent 提示词。角色初始化失败可重试。用现有的设定版本处理重复编辑。
2. **配置外观。** 按第 5 节导入角色文件夹，或给具体服饰单独补主页图和对话差分。显示导入结果和当前穿搭。配置素材只改变可用衣柜，穿搭继续由 Agent 决定。素材可以后补。
3. **配置模型与服务。** 角色页提供「对话」「记忆整理」「语音」「生图」。全局模型服务在设置页维护，角色按用途选用，找不到可用服务时可跳去新增并返回原角色。记忆整理默认继承对话模型，可单独绑定。语音沿用当前按角色保存地址、协议和音色的接口。生图建议全局保存服务连接，角色选择文生图或图生图模型，页面随所选类型显示对应的锚点字段。
4. **配置 MCP 和 Skill。** 全局维护资源，角色页添加绑定并启停。配置顺序用于引导，已有角色可独立编辑任一区域。停用阻止新任务使用，已开始的任务链沿用 DL-71。

建议原型区分「已保存」「测试通过」「当前生效」。角色数据创建后即可编辑，绑定有效对话模型后才具备常规对话所需配置。TTS、生图、外观和扩展各自可用、可缺省；独立记忆模型是可选项。各模型区都提供主动测试。对话服务测试仍遵循 DL-119，允许用户在测试未通过时保存草稿或配置，界面如实标出状态。 [角色创建与设定](../../../backend/src/http/routes.ts#L83) · [记忆模型继承](../../../backend/src/application/model-binding-resolver.ts#L94) · [DL-119](../../161-digital-life-direction-decisions.md#dl-119-模型配置手动填写列表失败保留与主动测试连接)

### 6.3 生图锚点、输入能力和运行时选图

2026-11-10：文生图一侧已按 [248](248-comfyui-adaptation.md) 落地（ComfyUI + MOSS-Image 首版），图生图的锚点图上传与按类型切换待下一包。

两类模型共用角色基础锚点提示词，描述脸型、发型、发色、瞳色等跨场景和服饰保持稳定的视觉特征。服饰配置按模型类型显示，场景提示由规划器随本次任务提供。

| 所选模型 | 角色配置字段 | 生成含人物场景时的输入 |
| --- | --- | --- |
| 文生图 | 角色基础锚点提示词；每套服饰的锚点提示词 | 基础提示词 + 目标服饰提示词 + 场景描述。 |
| 图生图 | 角色基础锚点提示词；为每套服饰上传并关联锚点图 | 基础提示词 + 场景描述，再传目标服饰的锚点图。服饰提示词输入框在此类型下隐藏，提交时无需该字段。 |

- **按所选模型校验。** 文生图检查基础提示词与目标服饰提示词，图生图检查基础提示词与目标服饰锚点图。建议切换模型类型时保留另一类已编辑的服饰配置，生成与测试按当前类型取值。图生图缺目标服饰锚点图时提示上传；如需要文生图回退，须有可用的文生图模型及相应配置，是否自动回退另行确认。模型类型及参考图支持范围以所选模型和适配协议为准。
- **按目标服饰取锚点。** 文生图生成新服饰时，可保留角色基础身份，由本次提示描述新服饰，避免沿用旧衣着。图生图更换服饰时读取目标服饰的锚点图。纯背景只传环境描述；如果当前模型需要强制图像输入，纯背景的模型选择规则另行确认。
- **保持导入边界。** 第 5 节批量导入仍只处理 `standees` 和 `expressions`，不扫描源目录的 `outfits`。生图配置里由用户显式上传的参考图属于独立资源，可替换或删除，不进入主页或对话素材列表。
- **与现有行为的差距。** 当前规划器读目标回复、服饰名和描述，生成器只接收规划描述；整幅图会自动拿主页 `home` 作为参考。需要增加提示词组装和明确的参考来源，将主页图与生图配置解耦。当前取该回复第一个有服饰的句段；如果同一轮未来允许多套服饰，需要按最终目标句段定位或拒绝跨服饰范围。任务提交时固定服务、模型和锚点版本，避免切衣服或编辑配置影响已排队任务。 [现有服饰和参考图读取](../../../backend/src/storage/scene-image-store.ts#L151) · [生成调用](../../../backend/src/application/scene-image-service.ts#L408)

## 8. 已确认的配置操作规则

按 [DL-147～DL-149](../../161-digital-life-direction-decisions.md#dl-147-设置页编辑角色与当前陪伴角色分离) 和 [DL-151](../../161-digital-life-direction-decisions.md#dl-151-删除不做归档) 实施。本节纳入《角色配置页与设置页》复核后的修订，覆盖其中按 TTS 模型保留多份配置、只按开启状态计算扩展占用及直接清除历史素材的旧表述。

| 操作 | 规则 | 验收场景 |
| --- | --- | --- |
| 设置页选择编辑角色 | 只改变设置页的编辑对象。切换当前陪伴角色使用独立按钮。异步操作按发起角色处理。 | 正与甲对话时在设置中编辑乙，主页和对话仍为甲。乙的导入、保存或试听结果不会改变当前陪伴角色，也不会覆盖后来选中的编辑对象。 |

| 修改或删除角色配置 | 后端确认该角色活动已停止后才可写入或删除；停止请求处理中仍可读。 | 运行中及已请求停止但尚未确认时，保存人设、修改外观或绑定、删除配置均被拒；后端确认停止后可操作。 |

| 修改、删除或全局关闭 MCP／Skill | 有角色开启，或未结束的原任务链仍有使用权，均算占用。占用时后端拒绝操作，界面说明原因。 | 关闭角色侧开关后，新任务不能使用。旧任务链仍可按 DL-71 使用，此时修改、删除和全局关闭均被拒。链结束后，若没有其他角色开启或任务链占用，关闭的绑定不再拦截。 |
| 删除服饰或差分 | 直接从衣柜、管理列表和 Agent 可选范围移除。保留被历史句段引用的受管副本，其余可清理。用户源目录和源文件保留。 | 删除后新对话不能选中该素材，历史回放仍按原句段读取旧主页图或差分，取图不依赖衣柜列表。同名重导不影响旧句段的素材指向。 |

| 停用及修改语音配置 | 每个角色只保留当前一份，不按 TTS 模型留副本。停用阻止新的对话语音合成，保留该份配置。保存新配置覆盖旧配置。 | 保存 A → 停用 → 启用，仍用 A。保存 A → 停用 → 保存 B → 启用，只用 B。保存 B 不自动更改停用状态；重新选择旧模型不会恢复 A 的音色、参考录音选择或高级参数。 |
