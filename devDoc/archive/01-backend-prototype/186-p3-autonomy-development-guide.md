## 1. 范围与边界

P3 在 P2 的完整 Agent、记忆、模型与本地扩展链路上增加：

- 角色自主安排及系统持久保存；
- 到期唤醒；没有新用户消息时仍可按安排推进；
- 使用既有 Skill／MCP 工具开展实际活动，保存 Markdown 成果、活动记录与经历；
- 角色自主决定主动分享、继续安排或等待；
- 自主活动统一额度、每日恢复及耗尽暂停。

首轮通过 CLI／API 与本地 MCP 验证，例如角色安排稍后阅读本地资料、写出笔记、记录活动并消耗自主点数；主动分享写入主对话窗口。浏览器及完整网页阅读闭环仍归后续工作包，本地资料样例不作为网页浏览证据。

不在 P3 首轮：正式前端、QQ、远程 MCP、浏览器／视频／电脑控制、完整重启与异常组合验收（P4）。P3 仍沿用单角色决策串行、多窗口、资源开关、原任务链延续、真实结果保存和记忆规则。

## 2. 现有基础

- 业务库已预留 `executions.trigger_type='autonomous'`、`tasks.origin='autonomous'`、`windows.kind='custom'`、`model_calls.purpose='autonomous'` 与 `call_metering.purpose='autonomous'`，P3 直接使用并补充额度、安排与活动表。
- 会话服务已有单角色运行槽、用户消息优先调度、任务续行、资源目录缓存、SSE 与记忆通知；P3 的到期唤醒进入同一调度器，不新建独立执行体系。
- 记忆运行时已有定时器模式；P3 唤醒只按最近到期安排设置一个计时器，不进行空闲模型轮询。
- 角色初始化已创建 `kind='main'` 的主窗口；P3 另建每角色独立的 `kind='custom'` 自主活动窗口，来源为 `nowadays-autonomy`，用于活动历史与证据，不把内部活动文字直接写入主对话。

## 4. 工程契约

### 4.1 业务库 v3

新增表（名称和字段为工程稿）：

`autonomy_budget`

- `role_id` 主键，引用 `roles`；
- `local_date`：当前额度所属本地日期 `YYYY-MM-DD`；
- `used_points`：本日已用点数；
- `daily_limit`：默认 200；
- `unlimited`：0／1；
- `updated_at`。

`autonomy_wakes`

- `wake_id` 主键；
- `role_id`；
- `kind`：`scheduled`（角色安排）或 `budget_resume`（额度恢复后重新评估）；
- `scheduled_at`：ISO 时间；
- `intent`：唤醒时交给角色的目标；
- `status`：`pending`、`claimed`、`completed`、`cancelled`；
- `source_execution_id`：创建安排的执行；
- `task_id`：`budget_resume` 关联的暂停任务，可为空；
- `activity_id`：领取后关联的活动；
- `claimed_at`、`completed_at`、`last_error_code`、`created_at`、`updated_at`。

`autonomy_activities`

- `activity_id` 主键；
- `role_id`、`wake_id`、`task_id`、`execution_id`、`window_id`；
- `status`：`running`、`completed`、`failed`、`paused`；
- `summary`：活动最终文字摘要；
- `shared_message_id`：主动分享到主窗口的消息，可为空；
- `started_at`、`finished_at`、`created_at`、`updated_at`。

索引至少覆盖：每个角色的待唤醒时间、活动创建时间、任务与唤醒关联。

迁移必须从 v2 升级到 v3，并保留 P0～P2 已有数据；新库直接以 v3 建表。升级失败按既有 `SchemaMigrationError` 处理。

### 4.2 额度

- 每角色默认每天 200 点；可改为有限正整数或“无限制”。
- 本地日期按应用配置的时区计算；读取和扣点前检查日期，跨日先把 `used_points` 重置为 0。跨多日只恢复当前日一份，不累积。
- 有限额度下，每实际发起一次自主模型调用或自主工具调用扣 1 点；同一次调用重连、流式分片和重试读取不重复扣点，新的实际重试另计。
- 用户消息、用户交办任务与后台记忆维护不扣自主额度，仍写实际调用记录；按需记忆检索、日记、分享与再安排等工具在自主活动内执行时，按实际工具调用扣点并登记，不按 `memory`／内部工具来源一概豁免。
- 自主执行的模型调用与工具调用 `purpose='autonomous'`；有限额度扣点时 `call_metering.counted=1`，无限制时记录调用但不计数（`counted=0`）。
- MCP 工具在异步建连前先预留额度，建连与任务检查通过、即将发送工具请求时提交；未派发时撤销预留且不写工具计量。建连期间任务结束、用户消息替代或连接失败不消耗工具点；已真正派发的晚到成功／失败仍计 1 点并保留真实结果。
- 预留记录所属本地日期。提交时按实际派发日结算：同日已扣点保留；跨日或原本未扣点的预留在当前额度日重新检查并取得点数，当天有限且余额不足时不得派发并进入预算暂停。取消只撤销该预留确实占用的点数，按原所属日期释放；未扣点的无限制预留不减任何点数，已扣点的有限预留不因当前模式切换而遗失。
- 额度耗尽时不发起新的自主模型／工具调用；已发出调用继续接收并保存真实结果。执行置为 `paused`，任务与活动保持暂停；最后模型返回但未执行的外部工具请求保留为 `pending`，不记为已执行，其他工具的未执行请求也不产生副作用。
- 耗尽时为同一任务创建 `budget_resume` 安排，时间取下一本地自然日零点；恢复后角色先结合最新情况与实际结果重新评估，不自动重放全部旧操作。
- 无限制不触发暂停；资源开关、任务来源和串行决策规则不变。
- 预算暂停不结束任务链；原链已取得的模型、MCP 与 Skill 资格保留到任务结束，恢复时可用原资源并在派发时读取最新配置；新任务仍只使用当前启用资源。
- 同进程内预算暂停保留原任务链的 MCP 客户端与服务会话，直到任务完成、失败或显式结束再释放；配置指纹变化时下一次派发重建客户端。跨应用重启的会话恢复不在本阶段。

### 4.3 安排与唤醒

- 角色通过 `autonomy_schedule` 创建 `scheduled` 安排；只接受未来时间，持久保存，不因进程内状态丢失而丢失记录。接受的时间统一规范化为 UTC 后存储，最近安排、到期判断与领取按实际时刻比较，不按原始字符串排序。
- 自主活动不占用对话 `decision_round`，只有回复用户消息的执行计轮；自主消息、结果、状态与记忆证据仍正常保存。
- 每个角色同一时间只运行一个决策。到期唤醒等待当前用户消息、任务续行和运行槽释放；优先级为：未处理用户消息 → 任务续行 → 到期自主安排。
- 有最近到期安排时设置一个计时器；无待处理安排不调用模型、不轮询。安排变化后重新计算最近时间。
- 到期后在事务中领取安排。`scheduled` 安排创建自主任务（`origin='autonomous'`）、`trigger_type='autonomous'` 执行和活动记录，并关联自主活动窗口；`budget_resume` 只恢复仍可继续的原自主任务，任务缺失、非自主或已 completed／failed 时取消恢复安排，不创建替代任务。
- 自主活动窗口按角色惰性创建，`kind='custom'`、`source='nowadays-autonomy'`；活动最终文字作为该窗口的 assistant 消息保存，供活动历史与记忆证据使用。只有 `autonomy_share` 才向主窗口追加主动分享消息。
- 用户在新窗口或主窗口发送消息时，仍按 DL-101／DL-102 处理；正在运行的自主执行可被新用户消息替代，释放决策槽，原自主任务按既有续行机制在用户回复后继续。角色可在续行时决定分享、再安排或结束。
- 安排取消只允许 `pending` 状态；已领取或已完成不能取消。取消后重新计算计时器。

### 4.4 Agent 工具

`autonomy_schedule`

- 输入：`{ wakeAt: string（ISO 时间）, intent: string（非空，限制长度） }`；
- 只允许未来时间；保存来源执行与角色；
- 返回 `{ wakeId, scheduledAt }`；同时唤醒计时器。

`autonomy_share`

- 输入：`{ content: string（非空，限制长度） }`；
- 仅自主执行可用；向该角色主窗口追加一条 assistant 消息，并登记消息证据；
- 返回 `{ messageId, windowId }`；
- 不改变任务状态；同一次活动多次分享按实际消息保存。

工具由 Agent 可选调用；没有额外审批、授权或逐次确认。安排在用户对话中也可以创建，分享首轮只允许自主活动，避免在普通回复中插入额外消息。

### 4.5 自主系统提示

自主执行加载角色最新设定、当前状态、相关记忆、原任务进度与安排目标。提示明确：

- 这是角色自己的安排，不是用户新消息；
- 可以使用已启用 Skill／MCP 实际做事，保存真实成果；
- 可调用 `autonomy_share` 主动分享，或调用 `autonomy_schedule` 安排后续，或不调用工具等待；
- 不虚构用户发言、离线经历或未实际发生的工具结果；
- 额度耗尽或开启状态变化时按真实结果处理。

### 4.6 CLI／API

工程路由草案（实现时按现有 `/v1/roles/:roleId/...` 风格落地）：

- `GET /v1/roles/:roleId/autonomy`：额度、最近到期安排、近期活动与暂停状态；`paused` 只反映当前仍待恢复的任务，历史 paused 活动保留但不把已完成任务报告为暂停；
- `GET /v1/roles/:roleId/autonomy/budget`、`PUT .../budget`：读取／设置每日额度和无限制；
- `GET .../autonomy/wakes`、`POST .../autonomy/wakes`、`DELETE .../autonomy/wakes/:wakeId`：查询、手工创建与取消安排；
- `GET .../autonomy/activities`：活动记录。

CLI 对应 `autonomy status`、`autonomy budget get|set`、`autonomy wake list|add|cancel`、`autonomy activity list`。接口只读写角色自身数据，错误不回传密钥、SQL 或上下文全文。

## 5. 验收矩阵

| 场景 | 通过条件 |
| --- | --- |
| 自主安排 | 角色创建未来安排并持久保存；无新用户消息时到点唤醒；安排状态与来源正确 |
| 实际活动 | 唤醒后使用本地 MCP 读取资料、写出 Markdown 成果；活动记录、工具结果与记忆证据可追溯 |
| 主动分享 | 调用分享时主窗口新增主动消息；未分享时主窗口无新增 assistant 消息 |
| 继续安排 | 活动结束后创建下一次安排；计时器按最近时间重新设置，不进行空闲轮询 |
| 额度 | 默认 200；模型与工具各扣 1；跨日重置；无限制不暂停；用户对话不扣自主额度 |
| 耗尽暂停 | 新调用被阻止，在途结果保存；任务与活动暂停；次日安排恢复后重新评估 |
| 串行切换 | 用户消息优先；自主执行被替代后原任务可续行；不重复扣点、不重复执行成功工具 |
| 接口 | 额度设置、安排查询／取消、活动记录可通过 HTTP 与 CLI 验证 |
| 隔离 | 其他角色不可读写同一安排、活动或额度 |

离线模型与本地 MCP 自动回归；真实模型按 DL-116 在 P3 关键场景按需单独联调，不纳入每次自动回归。

## 6. 限制

- P3 首轮只证明本地资料与本地工具闭环，不证明浏览器、网页阅读、远程 MCP 或其他厂商兼容性。
- 完整退出、强杀、重启恢复与并发异常组合在 P4 验证；P3 只实现基本持久化与到期恢复。
- 文档中的字段、路由、状态名和工具参数仍可在实施中按验证结果调整；调整不改变已确认的用户行为。
- 未提交、未推送前不宣告 P3 完成；实现方自验与独立复核分别记录。
