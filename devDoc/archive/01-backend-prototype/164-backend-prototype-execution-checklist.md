## 1. 首轮交付范围

一个独立角色通过本地 CLI／HTTP API 使用完整记忆、Agent 对话及 Skill／MCP，能够自主安排并在到时唤醒后开展实际本地活动，保存身份、经历和任务进度，重启后结合最新情况恢复。后端使用 TypeScript 与 LangGraph，同一后端进程内各职责分模块、独立调度，业务与检查点使用角色独立的两份 SQLite 文件。

工作空间位于 Nowadays 所在目录的专用文件夹，笔记使用 Markdown。重写从全新运行数据开始，旧代码和历史保留在 `dev`，不复制旧依赖及兼容层作为新实现。

首轮通过 CLI／API 验证，P5 收口后进入桌面前端阶段，远程 MCP 按 DL-115 在桌面前端完成后实施。网页阅读闭环、视频、桌面控制及 QQ 等仍按已定方向在后续工作包推进。

## 3. P0 的具体起步与证据

以下是 DL-85、DL-128 的执行归集，不代表已经执行。

1. 选择并记录运行时、LangGraph、模型及 MCP 接入、SQLite 业务驱动和检查点驱动的候选版本。建立独立的小样及数据，使用可控离线模型和确定性本地工具；不沿用旧构建结果或自动调用付费服务。
2. 跑通输入登记、模型决策、调用前登记、MCP 实际执行、结果保存及图暂停／恢复。分别记录角色业务数据、执行编号、原任务和工具调用的关联，验证检查点与正式业务数据的分工。
3. 在中断及恢复边界复现已保存工具结果不重复执行、旧输出隔离、最新资料刷新；结果未知按既有原则处理。记录实际接口、保存顺序和失败情形，不能将外部操作和业务库当作同一事务。
4. 交付可复现命令、依赖及锁定信息、关键持久记录、自验和独立复核结果。未通过项修正后复验；小样未覆盖的能力明确留到相应阶段验证。

P0 不以完成全部正式 API、角色管理、记忆整理或远程服务作为小样目标，也不将最小链路通过解释为 P1～P4 已完成。

P0 面向开发的工作包、最小职责、验收用例及证据模板见[开发文档 165](165-backend-development-guide.md)；实际实现、依赖版本、运行命令和自验结果见[P0 实施记录 166](166-p0-implementation-record.md)。R01～R04 修正后已通过[独立复验 167](167-p0-independent-review.md)：37 项检查、5 个原边界场景及 4 个真实强杀场景全部通过，P0-01～P0-05 完成。后续[168](168-p0-followup-fix-list.md) 的 L01、L03、L06 已修正并通过独立复核（38 项检查），其余条目按第 7 节不修改实现或留待 P1／P4；该后续修改已通过独立复核，见 168 第 9 节。
