## 首轮功能补齐

### GAP-01 慢工具自动转后台

**依据与现状。** DL-49、DL-50、DL-68 和 DL-70 要求短时间等待工具，较慢的调用保留原任务和调用身份，在后台继续。当前图节点等待 MCP 调用返回，运行时没有自动切换模式，执行详情也固定返回 `foreground`。本地复现中，窗口 A 的工具已执行，窗口 B 提交消息后在 2.2 秒观察窗口内无回复。放行工具后，窗口 B 才收到回复，调用模式历史只有 `foreground`。[DL-68](../../161-digital-life-direction-decisions.md#dl-68-工具调度短暂等待未返回则原任务自动转后台) · [工具执行](../../../backend/src/application/agent-graph.ts#L470) · [执行详情](../../../backend/src/storage/conversation-store.ts#L373)

**补齐与验收。** 短工具直接回到当前决策。慢工具越过前台等待窗口时，记录模式变化并释放角色决策位置，其他窗口可以先得到回复。工具返回后先保存真实结果，再交回原任务。用快返、慢返及等待边界返回三种时序验证，同一次调用只派发和计量一次。加入关闭资源、同窗口插话、任务结束后晚到结果的组合验收。

### GAP-02 角色决定任务暂停、继续和结束

**依据与现状。** DL-09、DL-69 和 DL-72 要求角色掌握正在执行的目标，并根据实际进度决定继续、暂停或结束。当前每轮提交回复后，会把关联任务记为 `completed`，结束原链的资源延续。额度暂停和异常续行已有路径，角色一般的后续安排会新建唤醒事项。离线复现中，角色为同一目标安排下一次唤醒并明确表示「尚未完成」。第一次回复把原任务标为完成，后续唤醒的 `taskId` 为空，到期后创建了第二条任务。[DL-72](../../161-digital-life-direction-decisions.md#dl-72-任务链边界按具体目标组织由角色判断结束) · [回复后的任务收尾](../../../backend/src/application/conversation-service.ts#L1494) · [自主安排](../../../backend/src/application/agent-tools.ts#L694)

**补齐与验收。** 在角色决策中提供当前任务目标、状态和已保存的进度，使角色可以表达本轮先回复、继续原目标、延后或结束。暂停后继续同一目标时，保留原任务编号、资源延续关系及已保存工具结果，重启后仍可接续。以分两次阅读同一份本地资料为验收例，中途插入一条用户消息，核对原任务保持可恢复，第二次唤醒接回原链。另起目标按当前资源开关创建新链。按任务真实结束触发经历整理。

### GAP-03 核查未知结果后补录原调用

**依据与现状。** DL-53、DL-70 及 P1 工程契约要求保留未知事实，并允许核查后在原调用下补录。角色已经能调用工具核查，存储层已有带历史记录的补录机制，运行时尚缺将明确核查结果交回该机制的入口。P4 的 `check-unknown` 场景实际核查成功，原调用仍保留 `unknown`。[调用结果保存](../../../backend/src/storage/role-store.ts#L1259) · [P4 核查证据](190-p4-recovery-acceptance-report.md#72-新增组合)

**补齐与验收。** 角色取得明确证据后，按原 `toolCallId` 保存核查结论、证据关联及时间，保留此前的未知记录。证据仍不足时保持未知。复验「写入文件后断线，重启确认文件已存在」场景，核查成功后可从原调用详情读到明确结果与历史记录。覆盖重复补录、冲突证据和已结束任务，确保原工具只执行一次，补录只改变该调用的事实记录。

### GAP-04 记忆整理按实际模型容量分批

**依据与现状。** DL-127 要求根据模型可用上下文，把整理说明、关联事件、待处理证据和输出预留纳入容量计算。现有长证据分段及待处理进度机制已经可用，生产路径仍采用固定字符预算，请求组装时额外加入相关事件等内容。[DL-127](../../161-digital-life-direction-decisions.md#dl-127-整理容量按可用上下文分批超长记录分段且原文完整保留) · [预算默认值](../../../backend/src/domain/memory.ts#L283) · [整理请求](../../../backend/src/application/memory-runtime.ts#L398)

**补齐与验收。** 按当前绑定模型可核实的容量计算单批输入和输出预留。模型容量资料不全时使用明确的保守估算。用两个不同容量的离线模型接收相同材料，核对完整请求受各自预算约束。长证据跨批按顺序处理，成功保存后才推进进度。同一事件跨批补充，原文完整保留。

### GAP-05 Skill 随包脚本从 Skill 目录定位执行

**依据与现状。** DL-58 要求角色按需通过已启用的执行工具运行 Skill 随包脚本。当前 `skill_read` 把正文或文件内容交给模型，通用命令工具以角色工作空间为执行根。Skill 文档里的包内相对脚本路径缺少到执行入口的交接。[Skill 读取](../../../backend/src/application/agent-tools.ts#L830) · [命令工具](../../../backend/src/mcp/local-server.ts#L174)

**补齐与验收。** 角色提供已启用的 Skill 与包内脚本路径，由运行时定位脚本并使用既有执行工具。验证一个脚本可以访问自己的随包资源，其实际输出与失败状态进入原任务调用记录。沿用现有资源开关及原任务链规则，脚本、依赖和环境仍由用户提供。用另一条用例验证读取 Skill 和脚本正文时只发生读取动作。

### GAP-06 角色按日记编号读取正文

**依据与现状。** DL-28 和 DL-87 将日记纳入角色记忆检索与深入读取。日记 Markdown 正文和按 ID 读取的服务与 HTTP 接口已实现。Agent 的 `memory_search` 命中返回记录编号、标题和片段，现有工具目录缺少按日记 ID 继续读取正文的路径。离线复现中，模型收到日记 ID，未收到长日记末尾细节。同一日记由后端读取服务成功读到末尾。[Agent 工具目录](../../../backend/src/application/agent-tools.ts#L47) · [日记详情服务](../../../backend/src/application/memory-query-service.ts#L311) · [搜索片段](../../../backend/src/application/memory-query-service.ts#L681)

**补齐与验收。** 角色从日记搜索命中拿到 ID 后，复用现有日记详情服务按需读取正文及关联事件。长日记可分段读取，保留 Markdown 正文与工作空间文件的对应关系。使用一篇远长于搜索片段的日记，验证模型能主动读到尾部细节，并确认角色隔离与缺失文件的错误处理。

## 桌面接入准备

### UI-PREP-01 角色清单

后端内部已有角色索引枚举，供启动恢复和后台整理使用。公开的角色 API 与 CLI 目前从创建结果或已知角色 ID 开始操作。桌面首次启动或重开时需要通过接口列出已有角色并进入所选角色。建议复用全局角色索引提供列表，验证重启后角色可被发现，以及空列表、未就绪角色和已就绪角色的响应。此项归入桌面接入准备，首轮单角色验收以创建返回的 ID 为入口。[角色索引](../../../backend/src/storage/app-store.ts#L145) · [角色路由](../../../backend/src/http/routes.ts#L75)

| OPS-04 · 长期记录的筛选与翻页 | 消息已能按序号翻页。任务和日记列表全量读取，活动接口只有数量限制，较久的任务与活动不易定位。[任务列表](../../../backend/src/http/routes.ts#L292) · [活动列表](../../../backend/src/http/routes.ts#L416) · [日记列表](../../../backend/src/http/routes.ts#L610) | 活动页按日期、来源及状态查询，使用稳定游标翻页。验证新活动插入时，客户端仍能定位历史记录并按编号读取对应执行与工具结果。 |

OPS-01 的本地复现结果位于 `backend/test-results/p5-gap-audit/retry-message.json`。OPS-02 至 OPS-04 根据路由和运行代码核对。建议先确认角色备份与恢复的最小范围，MCP 测试连接随 DL-115 推进。下一批桌面可用性工作可集中处理当前活动、重连状态、失败重试与诊断，再按实际使用情况排其他候选。

建议将 GAP-01 与 GAP-02 作为同一个调度工作包，先核对任务身份及角色让出的契约，再补运行时。GAP-03 使用同一任务和调用记录。GAP-04 至 GAP-06 可以分别落实和验收。桌面前端完成后按 DL-115 开展远程 Streamable HTTP MCP 后端补充时，共用上述工具调度、结果保存和资源开关规则，远程样例验证后再进行真实服务联调。桌面、网页阅读、视频、电脑控制和 QQ 按各自排期跟进。[阶段清单](164-backend-prototype-execution-checklist.md)
