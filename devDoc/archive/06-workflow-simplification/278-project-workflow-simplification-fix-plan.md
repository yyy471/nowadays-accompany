## 1. 角色配置在原页面完成

1. 运行中可以修改人设、绑定、语音、生图和额度草稿，也可以选素材文件夹并看导入预览。点击保存时，以后端状态决定按钮为「保存」或「暂停并保存」。导入同理使用「导入」或「暂停并导入」。单张素材上传、语音启停等受保护写入也复用这条路径。按钮在原操作区显示「正在暂停角色」「正在保存」或具体失败原因。 [现有写入策略](../../../backend/src/http/config-writes.ts) · [角色配置](../../../desktop/desk-preview/renderer/src/pages/Settings.tsx#L432)
2. 后端仍按可保存节点确认停止。桌面端复用停止和状态查询，在后端返回 `stopped` 后提交这次操作。请求停止后失去连接时，恢复连接先查实际状态，保留草稿与素材预览。操作的角色 ID、草稿、预览和提交结果始终归属发起时的对象，切换页面或角色不会改变目标。批量操作以实际返回结果结算，失败只重试未成功项。 [角色活动接口](../../../backend/src/http/role-activity-routes.ts) · [活动写入保护](../../../backend/src/http/write-guard.ts)
3. 「暂停并保存」完成后，原处提供「继续活动」。操作前已经停止的角色继续保持停止。用户主动暂停的待办、任务进度和额度按 DL-148 保留，恢复复用已有调度。表单失败时继续展示草稿和可执行的下一步。
4. 删除角色在同一个对话框选择「保留记忆和对话」或「一并删除」，最终执行动作按活动状态显示「删除角色」或「暂停并删除角色」。保留用户原始素材、仍需回放的历史引用和最后一个角色等既有规则。素材预览的主按钮本身即为导入提交，重名和缺图在预览中反馈。 [角色删除](../../../desktop/desk-preview/renderer/src/pages/Settings.tsx#L466) · [素材预览](../../../desktop/desk-preview/renderer/src/components/appearance/AppearancePanel.tsx#L270)

提交前完成表单校验、目标确认和重复请求判定，再发起停止。已有停止请求时等待它达到边界。一次点击锁定发起角色和提交草稿，等待期间的后续编辑留作新草稿。后端状态读取失败时就地重试读取。停止已成功而保存失败时同时显示「角色已停止」及失败原因，保留原稿供重试，也保留已有的继续活动入口。取消尚未提交的保存时撤销本次待写入动作，角色活动按后端实际状态显示。

停止查询和写入是两次请求。若其他入口已在两次请求之间恢复角色，写入由后端拒绝，原页面保留草稿和实际状态，允许用户重试。进入写入后使用现有角色租约串行执行，禁止并发恢复。结果未知时先查对应记录或操作状态，确认成功的写入只更新原提交快照，保留后续编辑。已发出的停止或写入可能继续完成，取消等待和断线后以实际状态为准。 [恢复与写入租约](../../../backend/src/application/role-activity-service.ts#L144)

导入按单套显示成功、失败和重名，重试只处理失败项。角色删除区分「尚未删除」和「已从列表移除，文件清理待完成」。删除时真正已发出的调用按既有规则结算，停止后已搁置且不会再运行的续行由删除流程处理，界面无需先恢复角色来清空队列。删除当前陪伴角色后同步收起其配置、对话和播放状态，并按现有规则切换到剩余角色。 [角色删除结果](../../../backend/src/application/role-deletion-service.ts) · [删除前运行时收尾](../../../backend/src/bootstrap/app.ts#L204)

## 2. 模型维护只暂停实际依赖目标

### 2.1 后端计算影响范围

以目标 `resourceId` 为单位，复用已启用绑定、资源延续和实际模型解析逻辑。配置页展示的影响范围与提交前校验使用同一份规则。已有引用报告可扩展返回角色、用途、活动状态、任务及具体阻塞原因，桌面端按角色显示名呈现。 [引用扫描](../../../backend/src/application/resource-service.ts#L266) · [模型绑定解析](../../../backend/src/application/model-binding-resolver.ts)

| 对象 | 纳入规则 |
| --- | --- |
| 对话与记忆 | 对话绑定解析到此服务，或当前有效的记忆模型解析到此服务。未单独设置记忆模型时按现有回退解析。对话和记忆命中同一角色时只计算一次。 |
| 原任务链 | 仍保有此服务延续关系的未结束任务，以及已固定使用此服务的运行中任务。旧任务可能与角色当前绑定不同，按原任务记录识别。 |
| 正在调用的后台工作 | 使用此服务的记忆整理、句段标注和过场图提示词规划。保护检查覆盖调用领取与结果结算。保存时已发出的调用按既有规则结算或在可保存节点暂停，后续调用使用已保存配置。 |
| 其他引用 | 已关闭且无在途调用或任务续用的绑定、已结束任务、历史调用日志均不扩大暂停范围。角色已经停止时仅显示占用或依赖情况。 |

提交前重新解析实际依赖。影响预览区分要暂停的工作、要迁移的绑定、阻塞删除的任务。按服务串行化模型写入，协调相关角色的绑定保存、活动恢复、任务领取和后台模型调用。读完请求体后重新检查范围，避免预览之后新绑定或任务并发加入。等待安全边界时，已发调用可以结算，其他服务的角色和任务可以继续。提交前再次检查操作范围，扫描失败或发现新增受影响对象时，返回具体原因，在原页面更新范围和保留草稿。当前的全局守卫仍用于有全局停止要求的其他服务。 [现有守卫](../../../backend/src/http/write-guard.ts#L33) · [后台记忆模型](../../../backend/src/application/memory-runtime.ts#L359) · [标注模型](../../../backend/src/application/segment-annotation-service.ts#L90) · [过场图规划](../../../backend/src/scene/model-planner.ts#L87)

若只有旧任务依赖目标服务，而角色当前对话与记忆都使用其他服务，在该任务的领取与续行入口暂缓这项工作。调度器可继续检查其他可运行任务，写入结束后唤醒被暂缓的工作。不得用角色停止状态代替这种按任务暂缓。确需暂停角色时，显示触发暂停的实际绑定或调用。已停止角色不进入恢复名单。 [调度入口](../../../backend/src/application/conversation-service.ts#L1013)

维护窗口先限制目标服务领取新调用，再等已发调用及结果登记到达安全边界。调用从选定服务到登记占用须与维护入口互斥。正在收尾的任务可以保存节点进度。走到下一次模型调用时若服务仍在维护，先保存可恢复状态并暂缓该调用，避免任务和维护相互等待。暂缓时保留原排队项及已完成进度，在挑选待处理窗口、续行和唤醒任务时跳过暂缓项。等待期间允许结果写回和租约释放，不持数据库事务。提交前在同一保护范围内重查引用和版本，阻止相关绑定变更或恢复抢在写入前进入。绑定从 A 移到 B 时同时协调两侧服务，采用固定顺序避免相互等待。无关服务仍可启动工作。操作成功、失败或取消后都释放临时限制并唤醒可运行项，提交中的请求以实际结果结算。 [当前调度与续行领取](../../../backend/src/application/conversation-service.ts#L1013) · [现有绑定版本](../../../backend/src/application/resource-service.ts#L235)

未开始的工作在再次领取时重新解析当前配置。已经开始的原任务保留原服务与已完成步骤。后续调用按既有模型续行兼容规则读取已保存配置，模型、协议或地址变化时不能把旧服务的专有续行数据交给新连接。删除已经生效后，背景工作也不得用旧快照重新发起请求。 [模型刷新](../../../backend/src/application/model-binding-resolver.ts#L99) · [协议续行判断](../../../backend/src/model/protocols.ts#L770)

### 2.2 设置页操作

| 操作 | 交互与执行 |
| --- | --- |
| 改名称 | 在模型详情直接保存展示字段。 |
| 改协议、地址或密钥 | 在同一表单测试草稿。若有活跃依赖，显示受影响角色及用途，提供「暂停相关角色并保存」。同站点按既有规则处理密钥，换站点时在本表单填写新密钥或清除旧密钥。一次保存地址和密钥。提交后使该服务的旧候选、探测提示及在途响应失效。 |
| 启用或停用 | 单独切换开关时直接保存启用状态。停用后新任务无法选择该服务，已持有资源的原任务按 DL-71 和 DL-73 继续。若同一次操作还要修改连接参数，连接写入按实际依赖到达安全边界。 |
| 删除 | 在模型详情展示受影响的对话／记忆绑定和未结束任务。可在同一处选择替代模型或解除绑定。任务仍依赖目标服务时显示具体任务和处理入口。实际删除前重查引用，沿用现有删除和绑定清理机制。删除失败反馈实际已完成的动作与剩余阻塞项。 |

验收基线为角色甲和乙同时活动，分别使用模型 A、B。换 A 的密钥时只暂停甲。若乙当前有效的记忆绑定解析到 A，暂停范围包含乙并标明记忆用途。若乙当前对话和记忆都使用 B，仅有一条旧任务依赖 A，则只暂缓乙的该条任务。单独命中的后台调用按调用安全边界处理。无关角色的回复、后台任务和恢复入口均不被本次维护阻塞。

操作影响在提交区一次说明。模型删除前的改绑使用相应角色绑定的最新版本。按实际结果展示已改绑、仍受阻、已删除和待清理。网络失败后先查提交结果，重试仅处理未成功的步骤。旧任务的资源归属随原任务保留，修改当前绑定不会自动清除旧链引用。 [绑定版本与资源删除](../../../backend/src/application/resource-service.ts#L235)

维护结束后，在同一操作区提供「继续本次暂停的角色」，仅包括由这次操作发起停止且仍处于该次停止状态的角色。原先已停止、正在停止或后来由用户另行停止的角色不加入。多个角色恢复按实际结果分别更新，仍有任务、绑定或模型阻塞时在同处提示。

删除前按各角色的对话和记忆用途分别校验替代项。解除对话绑定后，保留已有会话与待回复消息，并显示配置入口。解除独立记忆绑定后重新按现有规则解析回退。预览显示仍引用目标的停用绑定及清理结果，这些绑定不扩大暂停范围。实际改绑成功而删除受阻时保留已经成功的改绑，原页面明确显示删除尚未发生。删除决策已提交时，读取侧立即滤掉旧资源和残留绑定，重试只继续清理。 [资源引用与决策提交](../../../backend/src/application/resource-service.ts#L266)

## 3. MCP 与 Skill 在资源详情内维护

- 资源详情展示已开启的角色、占用任务及其状态。批量关闭角色绑定只处理勾选对象，若受角色停止条件保护就在当前页面暂停并保存。修改或删除资源前仍需核对启用绑定与未结束任务，用户可在这里关闭绑定、查看任务或等待释放。用户明确选择结束某项任务时走已有任务终结语义。已发工具调用由原任务结算。 [引用报告](../../../backend/src/application/resource-service.ts#L266) · [任务终结](../../../backend/src/http/routes.ts#L404)
- 全局停用的交互采用立即阻止新任务获取资源。原任务继续使用其已持有的资源，任务结束并完成在途调用后释放。启用绑定的选择可以保留在角色页，资源状态标为「全局已停用」。修改运行配置和删除依旧依据实际占用执行。该设计涉及调整 DL-148 的全局停用条款，按本节联动前后端验收。
- 新建、编辑共用表单。MCP 的环境变量使用键值行，已保存值保持掩码。Skill 来源目录提供本机文件夹选择并保留手填。操作页只提供资源开关、影响范围和实际执行动作。

「结束任务」只结束指定任务的后续执行。先读取任务状态并显示具体名称，提交后刷新该项。现有终结接口会处理任务链引用，实施时还需把未结算调用计入资源占用，并等连接收尾再允许编辑或删除。核对暂停、等外部结果与重启场景。 [任务终结与目录清理](../../../backend/src/application/conversation-service.ts#L329)

模型、MCP 和 Skill 的快速路径只处理单独的启用状态写入。请求同时包含运行配置或密钥变动时，按较严格的写入条件整笔处理，校验失败时开关和其他字段均保持提交前的状态。设置页、直接 API 和 CLI 都应使用相同判定。扩展的启用绑定仍计入修改与删除占用。全局停用后，角色可在资源详情关闭自己的绑定，旧任务和已经发出的调用继续计入占用。 [现有资源写入分支](../../../backend/src/application/resource-service.ts#L146)

## 4. 第一次配置与对话恢复

1. 没有角色时，主页和对话的空态提供「创建角色」，直接打开已有角色创建表单。创建后在角色配置的模型区提供「选择对话模型」。若没有供应商，按钮打开设置中同一新建表单并返回来源角色及模型栏。选择和保存绑定由用户在当前角色完成。此入口复用设置表单，角色页目录无需常驻另一套供应商管理。
2. 对话绑定能解析到启用的服务与具体模型后提供「开始对话」。能在本地确认的配置问题（如凭据引用失效）就地提示。远端连通性由可选测试或实际调用反馈。角色原先处于停止状态时，按钮明确包含开始活动的意图。角色停止且模型缺失时，先引导配置模型，返回原窗口后再按角色活动状态提供开始或恢复入口。外观、语音、生图、扩展、额度按需配置，记忆按现有规则跟随对话模型。把原「完成度」中与操作有关的状态移到角色头部或对应表单。
3. 对话输入区遇到角色已停止时提供「恢复活动」，模型不可用时提供「配置对话模型」，保留当前角色、窗口和草稿。后端若已接收消息但没有安排回复，返回可区分的等待原因。前端显示已接收与等待原因，释放输入区的等待状态，按原消息标识继续调度。重试使用既有去重标识，避免已保存的消息重复发送。保留已存在的旧任务续用路径。 [消息提交](../../../backend/src/application/conversation-service.ts#L213) · [对话发送](../../../desktop/desk-preview/renderer/src/conversation/use-window-session.ts#L673)

入口携带来源页面、角色、窗口和目标分区。创建或编辑结束后优先回到发起位置，已有角色和已有供应商仍可直接选择。「开始对话」以按钮显示的目标角色打开对话。普通编辑切换继续与陪伴切换独立。供应商列表只有成功读取为空时才显示新建引导，读取失败保留已知项并就地重试。 [应用级陪伴选择](../../../desktop/desk-preview/renderer/src/App.tsx#L50) · [异步状态组件](../../../desktop/desk-preview/renderer/src/ui/async-state.tsx)

将「等待角色或模型就绪」「正常排队」「请求未确认」区分开。前两种展示已接收的消息，按消息和窗口恢复调度。只有提交结果未知时才复用原提交标识重试写入。模型绑定修复、相关服务恢复可用以及角色恢复时通知调度器重查已有待处理窗口。重连和切换窗口读回同一等待状态。以明确的排队原因判断界面状态，单独的 `decisionScheduled=false` 不能说明缺少模型。 [重复提交处理](../../../backend/src/application/conversation-service.ts#L213) · [恢复调度](../../../backend/src/application/conversation-service.ts#L1113)

核对既有提交与接收新消息分别处理。同角色、同窗口、同提交标识及相同内容的已接收消息，即使角色后来停止，也必须能查回原结果。角色停止仍拒绝新消息，同标识改内容仍返回冲突。重复查询或重试不得再次写入、打断正在生成的回复或新建任务。后端明确拒绝新消息时，输入草稿原样保留。 [当前消息路由](../../../backend/src/http/routes.ts#L251) · [去重持久化](../../../backend/src/storage/role-store.ts#L600)

维护释放、绑定生效或恢复活动后，重新检查已有待处理工作。角色仍停止时保留队列，等显式恢复。记忆整理所需的待处理触发要能在暂时无模型或维护等待时保留，恢复后根据有效的独立记忆绑定或回退模型继续，不依赖用户再发一句话。 [记忆模型解析](../../../backend/src/application/model-binding-resolver.ts#L94) · [记忆触发处理](../../../backend/src/application/memory-runtime.ts#L196)

## 5. 生图、语音及配置异常

- **生图。** 设置统一管理生图服务，角色表单允许就地打开同一服务编辑入口并返回原草稿。测试连接使用当前草稿地址、凭据及工作流，测试生图使用当前草稿服务、模型路径、工作流、生成参数、角色和所选服饰提示词。后台生成过场继续读取已保存配置。测试按角色和草稿来源处理结果，沿用超时、图片大小和格式限制。首屏保留服务、模型和样图，采样、尺寸等用现有折叠控件展开。 [生图表单](../../../desktop/desk-preview/renderer/src/components/image/ImagePanel.tsx) · [探测和样图](../../../backend/src/application/scene-image-settings.ts#L127)
- **语音。** 选参考录音、选音色、试听、保存放在当前表单。参考录音尚未写入时显示待上传。需要试听未保存的录音时，探测或试听接收临时音频，保存再写入正式引用。字段随服务能力显示，参考模式或文本只有在相关服务确实要求时出现。对话使用已保存配置。 [语音表单](../../../desktop/desk-preview/renderer/src/components/voice/VoicePanel.tsx)
- **绑定冲突。** 用已读取的基线、当前草稿和服务端最新记录做字段级合并。只修改不同字段时自动合并并重试一次。两边修改同一绑定时只在该字段提示冲突，保留其他草稿。使用版本条件写入，防止覆盖另一个分区。 [绑定保存和重读](../../../desktop/desk-preview/renderer/src/pages/Settings.tsx#L371)
- **设置导航。** 合并重复的全局对话／记忆资源目录，角色用途分配放在角色配置。语音配置留在角色页。切换编辑角色时可直接保留各角色草稿并标出未保存。状态、占用、失败及重试紧邻原操作，统一使用后端结构化原因。 [设置工作区](../../../desktop/desk-preview/renderer/src/pages/Settings.tsx)

草稿生图接口复用已保存生图的参数、工作流和凭据边界。预览时临时解析地址和凭据，复用旧密钥需按已有同源规则核对。草稿录音试听采用有限大小的临时输入，试听和失败重试不产生可被角色选择的正式资产。保存录音及配置须在一个用户动作内完成，服务端保证保存失败时原语音配置仍可用。 [生图凭据处理](../../../backend/src/application/image-service.ts#L98) · [语音预览入口](../../../backend/src/http/voice-routes.ts#L198)

已保存模型的候选和测试结果以服务及连接配置版本校验。列表、详情刷新与测试返回均按版本判断，覆盖 CLI 同站点换密钥、地址改回和旧请求晚到。版本可复用现有服务端测试指纹逻辑，接口返回不含密钥的标识。配置名称变更不清除连接结果。草稿测试结果只归当前草稿与所测模型，生图与语音预览也按原角色、服务和本次输入校验，切换对象或离开后丢弃过时的结果。 [服务端测试指纹](../../../backend/src/application/model-service.ts#L95) · [桌面探测](../../../desktop/desk-preview/renderer/src/components/model/use-model-probe.ts)

## 7. 实施顺序与验收

1. 先接角色同页暂停和恢复、直接创建入口。复用已有活动接口、草稿和状态管理。对话不可用反馈与消息接收结果查询、等待原因、恢复调度一并交付，后端先提供可读契约，桌面再接入口和状态。
2. 再交付按模型依赖的写入保护、资源详情的批量处理和任务入口。并发验收覆盖改绑与保存交错、旧任务持有不同模型、独立记忆模型、运行中后台调用、恢复与保存并发，以及批量部分失败。
3. 最后交付草稿生图、语音临时录音、自动合并绑定和导航收敛。分别验证草稿和已保存配置不同时测试取值正确、候选与结果不会跨服务或角色串入、保存失败后原草稿可继续提交。

按 [279 第 2 节](279-workflow-simplification-two-pass-review.md#2-第二轮关联修改清单) 同步处理调度、后台模型调用、缓存、类型、CLI、测试夹具与历史文档。前端按钮与对应接口成对交付，错误处理和等待状态一并验收。完成后逐项跑通 [279 第 3 节](279-workflow-simplification-two-pass-review.md#3-第三轮端到端复核) 的联调场景。

关键操作从发起页面开始验收，记录页面跳转、额外点击和错误后的下一步。常规设置用表单保存或开关，后端保护由系统执行。角色数据删除用同一个对话框完成去向选择和提交。对照第 6 节验收新增 UI。后端跑离线验收，桌面跑测试、类型检查和构建，再用临时后端做独立联调复核。
