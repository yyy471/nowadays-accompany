# 279 操作链路修复方案复核

2026-11-12。复核对象为 [278 修复文档](278-project-workflow-simplification-fix-plan.md)。三轮均基于当前前后端源码和已确认决策。发现的流程缺口已补入 278，以下记录实施时需要验证的条件。

## 1. 第一轮操作与逻辑复核

| 场景 | 按原方案实施的风险 | 修订与验收 |
| --- | --- | --- |
| 停止后保存、失败或离开页面 | 可能先停止再发现表单无效，也可能在等待时把改动提交到后来切换的角色。保存失败时只报表单错误，用户看不到角色已停止。 | 点击时先校验并固定提交目标与草稿。等待原停止请求。表单失败同时展示保存结果和实际活动状态，用户可在原处重试或继续活动。验收断线、切换角色、已在停止中以及重复点击。 |
| 模型开关、连接修改和删除 | 把三者统一成暂停会违背立即停用的约定。按任务暂停如果落成整角色停止，模型 B 的工作也会被挡住。改绑后还可能被旧任务占用，用户误以为已删除。 | 单独切换开关按 DL-71 生效。连接修改与删除区分运行依赖、绑定和任务占用。任务单独依赖时在任务入口暂缓，删除按实际结果显示已改绑、仍受阻和已删除。 |
| 扩展全局停用后立即编辑或删除 | 原有引用检查会把全局停用挡住。只改按钮会得到 409。反过来，如果任务结束后直接依据已清掉的续用记录判断，仍在结算的工具调用可能被误判为已释放。 | 实施时区分全局开关与修改、删除，按 278 第 3 节同步处理 DL-148 的设计变更。已发调用完成后才解除占用。任务处理显示具体名称和状态，用户只处理选中的任务。 |
| 首次配置、开始对话和从会话修配置 | 角色编辑与陪伴选择各有状态。直接跳到对话可能打开此前的陪伴角色。资源列表读取失败也可能误显示为没有供应商。 | 「开始对话」明确打开按钮对应角色。配置入口携带来源角色、窗口和分区，成功返回原处。区分空、加载失败和已知列表。 |
| 已收下消息但未安排回复 | 重发同一个提交 ID 只会取得原消息，现有重复提交路径不会再调度。用 `decisionScheduled=false` 也无法分辨重复提交、队列暂忙和模型缺失。 | 区分接收结果与等待原因。已有消息在模型或活动恢复时继续调度，提交结果未知时沿用去重标识。验收后端已收到但响应丢失、恢复模型、SSE 重连以及切换窗口。 |
| 导入、删除和样例测试 | 批量导入部分成功后整批重试会遇到重名。角色已删除但清理待完成可能误导用户再次删除。试听临时录音和试图复用已有密钥的草稿出图也需要明确生命周期。 | 导入按套结算，删除反馈区分记录与文件清理，预览使用草稿且只写临时输入。保存与预览分别核对数据归属。 |

页面操作仍走现有的书页、动作区和对话输入区。新增状态、按钮、错误与危险操作沿用原组件和主题变量。需要实机确认的布局、焦点和等待样式列入 [278 第 6 节](278-project-workflow-simplification-fix-plan.md#6-前端设计约束)。

## 3. 第三轮端到端复核

| 复核发现 | 已修订的设计 |
| --- | --- |
| 消息入库后丢失响应，角色随后停止。消息路由在持久化去重前检查活动状态，直接重试可能无法确认原消息是否已接收。 | 同一提交标识和内容能查回原结果，角色停止时继续拒绝未接收的新消息。消息接收、等待原因和恢复调度随桌面入口一并交付。 [消息路由](../../../backend/src/http/routes.ts#L251) · [入库去重](../../../backend/src/storage/role-store.ts#L600) |
| 调度器只挑首个待处理窗口及首个续行。若把旧任务暂缓直接写成退出调度，排在后面的其他模型工作也会卡住。记忆运行时会在模型缺失时提前退出，尚未登记的触发可能丢失。 | 等待维护的工作保留原位置，选择时跳过不可运行项。维护释放或绑定恢复后重新唤醒，并保留待处理记忆触发。角色活动继续由后端状态控制。 [窗口与续行调度](../../../backend/src/application/conversation-service.ts#L1013) · [记忆队列](../../../backend/src/application/memory-runtime.ts#L196) · [模型解析前置](../../../backend/src/application/memory-runtime.ts#L350) |
| 停止查询和保存之间可被另一个入口恢复。模型维护若只在预览和写入前扫描，仍有新调用在两者之间占用资源。 | 角色写入依靠现有租约最后校验。模型维护与新调用领取、绑定变更和恢复共同协调，允许已发请求完成结果登记，提交和取消后都释放保护。 [角色租约](../../../backend/src/application/role-activity-service.ts#L144) · [现有模型守卫](../../../backend/src/http/write-guard.ts) |
| 资源更新把停用与配置变动放在同一个入口。放宽停用分支后，混合写入可能绕过配置占用检查。当前模型刷新在服务查不到时可返回旧快照。 | 单独写开关走快速路径，混合写入整笔适用更严格的条件。删除决策生效后，旧快照无权发起新调用。改绑仅影响当前配置，旧任务沿用已有资源关系和兼容的续行上下文。 [资源更新](../../../backend/src/application/resource-service.ts#L146) · [模型刷新](../../../backend/src/application/model-binding-resolver.ts#L99) |
| 桌面候选失效依赖本地缓存代次。CLI 同站点换密钥时，角色页可能继续显示原密钥的候选或迟到的测试结果。 | 共享候选和结果核对服务端连接配置版本，复用已有测试指纹规则。各草稿预览也核对原角色及输入。 [桌面探测](../../../desktop/desk-preview/renderer/src/components/model/use-model-probe.ts) · [服务端测试](../../../backend/src/application/model-service.ts#L95) |

### 实施后必须跑通的场景

| 操作 | 通过条件 |
| --- | --- |
| 首次进入、创建角色、选模型、开始对话 | 空数据与预置停止角色都能从实际入口继续。已有供应商直接选用。测试连接可选。配置完成回到来源角色和窗口。手动切换配置对象不会改变当前陪伴角色，明确点击「开始对话」后才进入目标。 |
| 编辑角色、暂停并保存、导入或删除 | 先校验再停，原页面可见实际状态。覆盖切角色、编辑新草稿、另一个入口抢先恢复、响应丢失和同一素材部分导入成功。仅重试未成功项。两种角色删除选择均核对历史引用、播放收尾和源文件保留。 |
| 模型 A 等待维护时使用模型 B | 甲使用 A 且未单独绑定记忆，验证回退到 A。乙使用 B，且乙首个待续任务仍依赖 A。甲到达安全节点后停止，乙仅暂缓对应任务，仍可回复或处理 B 的其他任务。再测乙有独立记忆绑定到 A、A 有后台请求结算、绑定 A→B 与维护交错。取消或提交失败后临时保护解除，在原处只恢复本次暂停且仍可恢复的角色。 |
| 改绑、停用或删除资源 | 对话和记忆按各自用途校验替代项。先改绑成功、后遇到未结束任务阻塞删除时，正确显示两个结果。删除决策提交但清理失败后，重启或重试可继续清理。扩展纯开关阻止新任务，原任务可继续，旧工具结果完成后才释放占用。直接 API 和 CLI 提交混合开关与配置时，验证整笔受保护。 |
| 发送、断线、修复配置并恢复 | 测试已收下但无回复调度、正常排队、服务明确拒绝和提交响应丢失。响应丢失后暂停角色，再查回原消息。模型可用且角色恢复时，按原消息标识继续一次，待处理记忆一并被重新检查。SSE 重连和切换窗口不改变消息归属。 |
| 配置草稿探测与真实会话 | 模型地址改回、CLI 同站点换密钥、测试结果乱序时，候选和结果对应当前连接版本。生图和语音以草稿测试，以已保存配置处理会话。失败或离开页面后无过时预览覆盖当前对象，临时录音也不会变成正式资产。核对 278 第 6 节的两套主题、窗口尺寸和键盘焦点。 |

278 已补齐本轮发现的前后端交接、并发和失败恢复条件。模型维护范围按 DL-148 执行。扩展全局停用仍是 278 的待实施规则变更，当前接口继续受既有条款约束。本轮完成源码与方案核对，表中运行用例和实机视觉对照留待实施后逐项复验。
