## 3. 过场图后端契约草案

### 3.1 任务和画面归属

- 手动生成从一条已保存的角色回复进入。后端从目标轮读取正文和句段，规划返回画面描述、图层模式和目标区间。自动规划在回复正式完成后发起，额外判断是否出图。输入使用目标回复记录的 `outfitId`，如需人物参考图，引用该角色和服饰下可读的登记素材。
- 任务至少保存 `taskId`、`roleId`、`windowId`、`messageId`、触发来源、幂等标识、图层模式、起止 `segmentId`、状态、错误摘要、结果素材引用及时间。区间首尾均包含，归同一轮且顺序有效。早期流式句段用于对话展示，过场图任务以已保存的正式句段为锚点。
- `background` 只替换基础背景层，角色立绘继续按当前句段切换。`full_scene` 临时覆盖背景与立绘，退出时恢复基础背景和退出时当前句段对应的立绘。角色服饰和基础舞台状态仍由各自的状态来源管理。
- 图像结果保存到原窗口与原句段。实时演出仍处于有效区间时可自动展示。已经读过区间、查看历史或切换窗口时，用户从原句段打开。窗口切换不改变后端任务的归属。

### 3.2 接口和状态建议

| 入口 | 最小契约 |
| --- | --- |
| `POST /v1/roles/:roleId/windows/:windowId/messages/:messageId/scene-images` | 手动发起，传本次请求的幂等标识。后端返回可查询的任务。目标区间的交互在第 4 节确定。 |
| `GET /v1/roles/:roleId/windows/:windowId/scene-images/:taskId` | 读取任务状态和已保存结果。查询同时校验角色、窗口及任务归属。 |
| 窗口消息快照、按消息 ID 读取和 SSE | 快照及消息详情携带对应任务或结果引用，SSE 按任务 ID 更新。结果及事件的提交与快照游标保持一致，重连可补齐晚到状态。 |
| 受管图片读取 | 通过受管素材 ID 读取。校验访问归属、格式和可解码性，返回图像 MIME。真实路径及服务配置留在后端。 |

- 建议状态为 `queued → planning → generating → succeeded`，自动判图可以 `skipped` 收尾，异常终态为 `failed`。若适配器支持取消，按真实取消结果落状态。取消图片任务的能力独立于桌面对话回复，桌面对话省略独立的停止按钮。
- 同一个手动幂等键复用原任务。同一条已完成的助手消息只创建一个自动判图任务。显式重试记录为新的尝试，重复请求或重放 SSE 只读取原记录。外部请求有结果但本地重启时，先按上游能力查询或恢复原调用。结果不可判定且服务不支持幂等或查询时，保留可追溯的失败状态，避免自动重复发图。
- 成功状态与可读素材引用同时发布。文件写入或解码失败应留下失败状态并清理未提交文件。SQLite 迁移覆盖旧角色库与新建库。已落库消息、句段和服饰关系继续可读。
- 规划与生成分别记录实际调用及发起来源。资源开关和在途任务沿用 DL-71，既有自主调用按 DL-105、DL-110、DL-111 计量。自动出图是否跟随某类普通回复、扣点归属及供应商实际收费按第 4 节确定的触发策略和适配记录执行。重连、读图和复用已有任务不产生新调用。

## 4. 仍需确定的产品和服务规则

| 待定项 | 候选和确定时机 |
| --- | --- |
| 手动生成怎么选范围 | 建议从选中的一轮发起，由规划器推荐起止句段，并用假服务验证区间合法性。是否允许用户改起止句或确认画面方案，在手动入口和桌面交互定稿时确认。 |
| 自动何时画 | 建议借鉴 AnimaVN，在整轮完成后判断场景变化或值得纪念的情节，并按窗口冷却。自动开关默认值、频率、例外、是否覆盖角色主动分享及相关额度归属，在启用真实自动调用前确认。 |
| 首个生图服务与输入 | 真实接口地址、认证、参考图能力、支持的图像模式、尺寸、超时、错误码及幂等能力，在适配时依据选定服务固定。假服务阶段可覆盖两种图层和所有本地状态。 |
| 首版重画与历史操作 | 当前确认可从原句段打开旧图。是否提供重画、隐藏、保留多个版本及其展示优先级，在桌面过场图交互定稿时确认。 |

AnimaVN 的画面规划、起止句与回复完成后的判图可作为参考。Nowadays 按已确认的双图层和区间处理晚到结果，正式页面采用 DL-141 的逐句推进。

## 5. 后续工作

前端可先按 [225 桌面对话页开发文档](225-conversation-desktop-development-guide.md) 和 v5 原型并行开发，真实接口在对应后端契约复核后联调。

1. **桌面对话页**按 v4 的左舞台、右对话栏接入。首个可展示句段自动出现，后续点击推进，末句显示即恢复输入框。生成失败且无正文时恢复输入框，有残句时展示到末段后恢复。输入框恢复与媒体播放独立。历史浏览独立维护滚动位置和实时演出进度。
2. **媒体播放与角色配置**接入句段立绘、两种过场图图层、小喇叭点读和自动播放开关。动作段允许已开始的台词继续播。已离开句段的待合成自动播放请求失效。角色配置页提供音色绑定、参考音频和试听。
3. **完整窗口历史**为时间轴和片段卡补窗口级按日统计、关键词查询及稳定定位能力。首版覆盖完整的已保存历史，点片段定位右侧文字，旧图从原句段打开。消息分页继续用于加载定位附近的内容。
4. **真实联调和交付**分别记录真实 TTS 的克隆、预置和情绪表现，真实生图的两种图层、错误与恢复，桌面端的端到端及打包结果。桌面前端完成后，按 DL-115 恢复远程 Streamable HTTP MCP 工作包。

## 6. 本阶段验收清单

| 场景 | 通过条件 |
| --- | --- |
| 手动、自动、跳过 | 指定轮的手动生成可查询。自动只在正式终态后判图，关闭、判定跳过和命中冷却时无生成调用。 |
| 两种图层与有效区间 | 两种结果携带正确模式和同轮起止句段。用测试消费端验证区间进出、晚到、切窗口与历史读取的处理。实际舞台渲染留到桌面验收。 |
| 权限与持久化 | 跨角色和跨窗口读取失败，非法区间被拒绝，旧库迁移后保留历史。成功图片在重启后仍可从原句段读取。 |
| 幂等和恢复 | 并发重复请求、完成事件重放、断线恢复和进程中断均有证据。失败与重试可区分，不将未知上游状态当作失败后自动再发。 |
| 文字与音频回归 | 首个稳定句段提前发布、普通完成后 ID 保留、动作文字可回看且不合成。桥接验证省略情绪及显式传情绪，覆盖 SSE 快照和恢复。 |
| 交付证据 | 后端运行 `npm run accept:offline`，过场图专项使用离线模型与本机假服务。实现方自验和独立复核分开记录。真实服务、桌面渲染和打包结果分别留证。 |
