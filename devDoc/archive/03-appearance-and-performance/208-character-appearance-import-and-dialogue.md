**实施进度（2026-11-08）：** 衣柜登记、整套导入、单张差分、离线读图与主页立绘已完成首轮实现方自验，见[210](210-appearance-implementation-record.md)。对话页差分演出与第 2～3 步的交付验证尚未实施。

## 用户素材导入规范

在导入界面先选角色，再导入一套或多套服饰。程序自动登记并分配内部 ID。角色素材源目录按下节组织。下面是现有导入器识别的兼容格式，每套服饰可附一张主页立绘。

```text
千叶诗织/
  outfits/
    黑白长裙/
      home.png
      sprites/
        微笑.png
        握手.webp
        a.png
    白色针织裙/
      home.webp
      sprites/
        倾听.jpg
        微笑.png
```

- **兼容格式整套导入。** `outfits/<服饰名>/home.<扩展名>` 是主页立绘的固定位置，`sprites/` 放该服饰的差分。同一角色已有同名服饰时，提示「已存在该服饰」，用户可以进入该服饰补图。
- **单张上传。** 选中已有角色和服饰，上传一张差分图。例如上传 `握手.webp` 后，系统把「握手」加到这套服饰的可用差分里，下一次生成演出标注时 Agent 就能选它。上传 `a.png` 也一样登记为「a」。如同一套服饰有多张同名差分，内部 ID 分别标识各图。
- **检查范围。** 检查图片格式受支持且文件可解码，例如 PNG、JPEG、WebP，解码失败时提示具体文件。图片内容、文件名含义、透明背景、分辨率和差分是否齐全均由用户自己掌握。

想让切换更自然，同一套服饰可以尽量共用画布、景别、人物比例和站位。带透明通道的图片更容易融入主页背景。这些是制图建议。导入后保存可离线读取的图片副本，桌面可按画幅生成较小的运行版。

### 角色素材源目录

用户提供的素材库以角色为单位。新导入入口应直接读取角色目录，保留各类图片用途。以下结构以千叶诗织的黑白长裙为例。

```text
characters/
  千叶诗织/
    expressions/
      02_classic/
        happy.png
        listen.png
    standees/
      02_classic/
        qysz_02_classic_main.png
```

| 路径 | 图片用途 |
| --- | --- |
| `expressions/<服饰标识>/*.<图片扩展名>` | 对话动作和表情。按文件名自动登记为该服饰的差分。 |
| `standees/<服饰标识>/*.<图片扩展名>` | 主页立绘。随主页所选角色及其当前服饰切换，按登记的主页图读取。 |

素材库中并列的 `outfits/` 存放用户自行生图使用的服饰锚点，读取角色素材源目录时跳过它。旧格式的 `outfits/<服饰名>/home.*` 与 `sprites/` 继续兼容。

| 角色和服饰 | 主页立绘目录 | 对话差分目录 |
| --- | --- | --- |
| 千叶诗织 · 黑白长裙 | `02_classic/` | `02_classic/`，19 张 |
| 千叶诗织 · 白色针织裙 | `06_white_knit_barelegs/` | `06_white_knit/`，19 张 |
| 千叶诗织 · 白色针织裙配长袜 | `01_white_knit_stockings/` | 暂无差分目录 |
| 樱 · 两套服饰 | `idol_sweet_white_thighhigh/`、`initial_white_dress/` 各有一张立绘 | 两套同名目录目前仅有 `manifest.md` |

从角色目录直属的两个素材目录读取文件，优先按完全一致的服饰标识配对。两侧同一开头编号各只有一个服饰目录，且一个目录名是另一个加下划线或连字符后缀时，预览默认把差分归入立绘对应的服饰。千叶的 `06_white_knit` 与 `06_white_knit_barelegs` 即此情形。可在预览里撤销或手动归并。忽略 `manifest.md`、`表情清单.md` 等说明文件，缺少某一类素材时显示缺项并允许稍后补齐。若同一服饰有多张主页立绘候选，建议由用户指定一张作为主页图。已存在的同名服饰沿用现有提示。导入预览按所选角色隔离，服饰仍由 Agent 决定穿着。

桌面端导入时将 `standees` 映射为 `home`，将 `expressions` 映射为 `sprite`。目录识别、预览和复验见 [242](../04-role-settings-and-media/242-role-appearance-folder-import.md)。

## 开发契约

### 数据与接口

按角色将衣柜写入其业务 SQLite。服饰记录保存 `outfitId`、名称和可选用途说明。同一角色服饰名唯一，去除首尾空白后比较。图片记录保存 `assetId`、`outfitId`、用途（主页或差分）、原文件名、展示名、图片类型和受应用管理的文件引用。主页图最多一张，差分可同名。源图副本放在角色数据目录下的外观专用目录，读取时按登记的 ID 找图。

拟议路由均位于 `/v1/roles/:roleId/appearance`，桌面沿用现有 Electron 本地 API 代理。 [代理入口](../../../desktop/desk-preview/main.cjs#L173)

| 请求 | 职责 |
| --- | --- |
| `GET /outfits` | 返回该角色服饰及其主页图、差分 ID 和名称。Agent 通过同一份衣柜查询逻辑读取 |
| `POST /outfits` | 一次接收一套服饰的名称、可选主页图与差分图片。整包入口逐套提交并显示各套结果 |
| `POST /outfits/:outfitId/sprites` | 上传单张图并返回自动登记的差分 ID 和名称 |
| `GET /assets/:assetId` | 按角色和素材 ID 取图，以保存的图片类型响应 |

上传接口拟用表单文件字段传输，桌面先选择角色与目录或单张图片。后端在该角色范围内检查重名，并把解码成功的图片写入应用目录后提交索引。一个服饰导入失败时不发布残缺记录，清理本次暂存文件，其他服饰仍可独立完成。同角色并发新增同名服饰由数据库唯一约束兜底，返回 `409 OUTFIT_ALREADY_EXISTS`。不支持的格式和无法解码分别返回 `IMAGE_FORMAT_UNSUPPORTED` 和 `IMAGE_DECODE_FAILED`，附对应文件名。差分文件名按原样登记，由内部 ID 区分同名项。

现有 Electron 代理会将请求体整体读入内存。导入入口应单独处理图片传输与暂存，用千叶的原图包核对大文件路径，避免在 Electron、渲染器和后端各保留一份整包。文件先落到角色目录，再发布 SQLite 引用。异常退出留下的无引用暂存文件按导入记录回收。

### 桌面与演出

导入入口放在角色管理的外观区，显示角色、服饰和已登记差分。成功后刷新该角色衣柜。React 主页按已提交的服饰读取主页立绘，对话以同一个服饰 ID 读取差分。图未就绪时保留当前画面。目标差分缺失时，优先保留同服饰正在展示的图，其次用该服饰主页立绘，最后使用角色的默认呈现。穿搭状态的写入与跨页同步见 [209](209-agent-daily-outfit-development-guide.md)。 [主页组件](../../../desktop/desk-preview/renderer/src/components/home/HomeScene.tsx) · [对话页入口](../../../desktop/desk-preview/renderer/src/App.tsx#L61)

对话演出参考 AnimaVN。现有 SSE 提供正文，桌面按顺序呈现短段。模型从当前服饰的登记项中选择差分，把结果按句段位置作为独立标注。应用按 ID 取图，支持未知 ID 回退。播放到对应段才切图，同一表情可延续多段。新图就绪后淡入或播放配置的一次性动效。历史跳转恢复画面，快进跳过一次性动效。后续 TTS 和插图可以复用句段位置。 [现有 SSE 契约](../01-backend-prototype/174-p2-01-memory-agent-contract.md#85-sse-事件)

## 开发顺序与验收

1. **登记与读图。** 先跑通角色衣柜、整套导入、单张上传及离线读图。用千叶的两套服饰核对主页图及各 19 张差分。补验 PNG、JPEG、WebP、名称为「a」的图、同名差分、同角色重名服饰、不同角色同名服饰、坏图和另一角色的素材 ID。
2. **主页与对话接入。** 导入后刷新衣柜，先用固定句段演示「握手」能被选用，再接实际 SSE 和 [209](209-agent-daily-outfit-development-guide.md) 的服饰状态。验收缺图回退、切角色时迟到的图片、同表情不重复触发动效以及历史跳转。
3. **交付验证。** 以隔离数据目录运行 Electron，核对原素材目录移走和重启后仍可读图，保存实现方证据并另做独立复核。
4. **角色素材源目录补验。** 直接选择角色文件夹，核对千叶的同名匹配及白色针织裙在预览中的默认归并，核对樱在没有差分图片时仍能导入主页立绘。切换角色或当前服饰后，主页显示对应的 `standees`，对话动作和表情取自对应服饰的 `expressions`。复验兼容格式、已导入素材、单张补图以及跳过用户锚点目录。
