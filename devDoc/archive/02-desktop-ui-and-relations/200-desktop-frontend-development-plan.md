## 2. 视觉优化与资产生产

### 2.1 两张基准帧

以当前小院版做构图对照。先交付一个稍近的晴天下午版本，并用这个新机位渲染夜景。主拍立得的脸是第一视觉焦点，数字钟和玩偶形成第二层，窗景与书架提供环境。

| 调整 | 制作方法 | 通过条件 |
| --- | --- | --- |
| 机位与摆放 | 收一部分前景空桌面，杯子向前拉出层次，维持近正视。窗右沿、主拍立得与小照片之间保留可见间隔。 | 在完整宽窗和较窄桌面窗中，照片面部、时钟与入口都能辨认。窗台、屋檐和桌沿的透视协调。 |
| 墙面与书架 | 试用一张浅色便笺合并活动与心情。主动分享用照片旁的小纸条呈现。书脊靠布纹、压印、深浅和前后错位分辨。 | 小窗口第一眼能辨认角色和主入口。未读出现后仍有清楚的阅读顺序。 |
| 物件材质 | 玩偶细颗粒、柔高光和接缝遮蔽。杯口有釉层、杯底露素陶。相纸有细薄边缘及接触阴影。时钟仅在玻璃边缘保留窄反射。 | 在正常窗口尺寸能分辨相纸、布面、陶釉和玻璃。玩偶头发与照片暗色块保有颜色和轮廓。 |
| 角色与窗景 | 延续带手绘笔触的二楼小院。叶团、天空、屋檐以较大色块处理。保留照片与玩偶的角色配色，单独控制它们的受光。 | 暖色日光、阴雨柔光与夜间台灯下都能辨认同一角色。夜景有清楚的相纸与面部，晴天没有泛白。 |

### 2.2 分层与窗口适配

- 用 Blender 产出环境底图和分层资产。首个分层样机验证窗景遮罩、台灯受光、主照片与玩偶的可替换层，以及相应接触阴影。每层记录场景坐标、画幅、裁切范围和角色切换锚点。光照合成先对照同机位原渲染，再决定保留哪些独立光照层。色彩管理与透明边缘处理保持一致。
- 时钟、挂历日期、便笺、未读入口与按钮由界面绘制。互动热区用语义按钮，坐标跟随同一场景变换。窄窗口调整裁切和操作层布局，触发点优先保留可读名称。对话区单独布局，常规宽度以立绘占三分之一到四成试排，窄窗口改为标题区头像。输入框与正文按实际窗口像素排版。
- 在每个验收画幅检查拍立得脸部和文字清晰度。对话页用独立高分辨率立绘，过渡以照片中的面部位置为锚点。每个角色使用自有素材，缺少玩偶或立绘时由头像或角色名提供清楚的默认表现。
- 源资产与应用产物分开维护。实施时明确可获取的源工程、贴图与字体授权、导出步骤和运行资产清单。应用带可离线读取的产物，启动先加载当前画面，空闲时预解码相邻时段及对话立绘。

### 2.3 时间、季节、天气与呼吸感

| 状态 | 驱动与显示 | 验收重点 |
| --- | --- | --- |
| 本地时间 | 系统时钟驱动数字钟、日期和环境时段。晨、昼、暮、夜先用少量同机位关键光照验证，窗口重新显示、唤醒或跨日时以当前系统时间重新计算。 | 跨午夜日期更新，休眠返回直接对齐。暮色过渡保持曝光层次，窗框影子在整个过程只有一套清楚轮廓。 |
| 季节 | 首轮候选按本地日期选取四季画面，预览可指定日期。小院沿用同一机位、同一屋檐和树的位置。优先换树冠与室内花瓶，辅以自然光色温差。 | 四季对照能看出同一小院。角色主体在四季里保持稳定，季节变化和日期更新互相一致。 |
| 天气与灯 | 先验证晴、阴、雨视觉状态。天气影响窗景、入室光和窗玻璃，台灯单独决定自身亮度、桌面暖光与相纸补光。天气来源待定，离线样机由可控状态驱动。 | 白天能开灯，夜里能关灯，切换灯光时窗外时段延续。天气未知时能显示正常的中性环境。 |
| 环境动效 | 优先实现窗边缓慢叶影或雨迹，合适时段使用杯口少量蒸汽。可见时只启用少量局部动画，窗口隐藏时暂停环境帧，恢复时按当前状态绘制。 | 减少动态效果下呈现等价静态画面。动效位置稳定、亮度变化克制，照片和聊天内容持续可读。 |

先实测晴天下午到暮色、夜间灯的开关、阴雨三组关键组合，再扩展四季。对于位置差异明显的硬影，优先使用匹配光源位置的影子层或补关键帧。采用底图过渡时逐帧检查影缘与相纸亮度，发现重影就退回受控的光照层。

## 3. 界面与交互契约草案

- **进入和退出对话。** 主拍立得短促抬起，同一张脸接到对话页的角色区域，消息面板同时显出。先用 250–350 毫秒试手感。返回时沿原入口收回并还原键盘焦点。缩放窗口、快速往返或素材尚未就绪时可以结束过渡并落到正确页面。减少动态效果采用直接切换或短淡入。次级入口的翻书只用于轻量记录页，其他常用管理放在稳定的应用菜单。
- **切换角色。** 挂历下的小照片开启选择面板。选定后将姓名、主照片、玩偶和状态一起更新，机位与环境时钟连续。按 `roleId` 与 `windowId` 管理草稿、历史滚动位置、请求和事件订阅。异步素材和事件按角色／会话归属更新，快速切换时旧角色的内容留在各自会话。首次使用、角色未就绪、素材缺失与角色读取失败均有可操作的显示。
- **直接对话。** 主拍立得打开当前角色的主窗口，聊天只放与用户的直接对话，日记和工具详情从各自入口阅读。流式内容区分等待、生成、完成、中断和失败，保留已输出的中断片段。翻看历史时保持阅读位置，在最新位置才随回复滚动。初次进入显示最近一页，向上加载旧消息时以原有可见消息为锚。
- **中文输入与重连。** 按 DL-77～DL-84 处理中文输入法组词、停输 1 秒、发送新消息中断，以及离开视图时的输入态清理。草稿是客户端状态。消息和执行以服务端为准，断线续读以 SSE 游标去重，同次网络重试沿用 `submissionId`。角色切换、回到书桌与订阅断开均保留原执行归属。
- **状态与消息便笺。** 活动和心情只在真实数据可用时展示，可区分当前、最近记录及未知。主动分享入口定位原消息。持久未读实现前，原型用测试数据验证样式，真实界面可先展示有证据的最近分享。功能性文字在明暗两套界面检查对比度，场景按钮支持键盘焦点、清晰名称和退出路径。

## 4. 后端接入与桌面壳

界面原型先用可重复的离线数据源，接入时由同一 UI 状态边界消费本地 API。角色、消息与任务的业务存储仍由后端负责。

| 事项 | 现状 | 接入时处理 |
| --- | --- | --- |
| 发现角色与主窗口 | 已知角色可读，窗口可列出。UI-PREP-01 的公开角色清单缺失。 | 复用全局角色索引，区分空列表、就绪和未就绪。重开时验证仍能发现角色与主窗口。 |
| 聊天、输入和流 | 已有消息 GET/POST、输入态、SSE、已知执行详情。历史接口按 `after` 正向读。 | 先验证最新页、向前翻页及在途快照的最小接口。快照与事件游标使用可衔接的一致边界，覆盖读取和订阅之间到达的消息。 |
| 活动、日记与主动分享 | 已有角色状态、活动和日记读接口。主动分享写入主窗口。 | 「她的一天」优先接真实活动与日记。当前活动聚合、分享已读位置按 [196](../01-backend-prototype/196-backend-capability-gap-plan.md#管理与体验候选) 逐项确认。主动重试失败回复依赖 OPS-01 的另行契约。 |
| 设置和资源 | 模型与资源已有查询和配置接口，角色有能力绑定。 | 首轮桌面菜单建议只覆盖本地联调必需的角色、模型与现有资源操作。启停语义沿用 DL-71。远程 MCP、QQ 和外部平台按各自排期推进。 |
| 桌面壳 | 新主线已经能独立启动后端，历史分支有桌面壳参考。 | 工程样机优先评估 Electron 与轻量渲染器的组合，框架与版本以实测定。验证干净构建、本地后端启动失败提示、窗口缩放、托盘隐藏、恢复和明确退出。窗口关闭与退出遵循 DL-29。 |

桌面壳选型要用当前后端和独立依赖实测。记录 Node 运行方式、SQLite 运行环境、离线安装包、包体积、冷启动与空闲占用。旧工作区的缓存和构建结果只作历史参考。后端有变更的工作包按 [运行说明](../../../backend/README.md) 复跑统一离线验收，前端联调使用离线模型和本地工具样例。

测试证据按美术截图、交互录屏、自动化结果和桌面实机记录分别保存。建议从 1280×720、1600×900、窄窗口，以及 Windows 125% 和 150% 缩放开始，记录实际窗口尺寸、缩放、设备及构建版本。性能先测当前样机的冷启动、首次进聊天、资产切换掉帧、空闲与最小化占用，再据实定门槛。过渡期间输入应立即可用，最小化后的环境动画应停止。

FE-01 是本计划的第一个交付关卡。先出同机位晴天下午和夜景，和当前小院版并排核对主拍立得的第一眼辨识度、玩偶与杯子的材质差异、窗台到桌面的光影，以及夜间照片的清晰度。构图和光照评审通过后，再确定哪些物件需要做成独立的运行时素材。
