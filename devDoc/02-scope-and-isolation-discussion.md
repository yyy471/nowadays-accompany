# 范围、隔离与人格系统：阶段讨论稿

日期：2026-10-22

状态：根据用户补充整理的需求与建议。明确区分用户目标、代码事实及待确认设计；未改变运行代码。

## 用户明确的目标

- 一个桌面主程序管理 1–N 个 QQ 接入实例，可分别管理。
- 每实例选择各自插件、Skill、角色卡。
- 外部提供公用插件、Skill 等资源；考虑实例之间的管道能力。
- 人格系统采用角色卡 + 世界书 + 记忆管理，后续扩展情绪与遗忘。
- 保留个性化插件扩展，同时内置足够好的基础体验，用户配置后即可使用。
- 按阶段讨论并确认细节，第一份总体建议仅作为参考方向。

## 当前实现与建议边界

| 议题 | 当前实现 | 建议 |
| --- | --- | --- |
| 多账号 | 已有实例、账号租约、运行时复用和目录隔离；仅 attach | 在第一阶段验证 1–N 实例边界和真实接入，再实现受管 launch |
| 数据隔离 | 账号目录、会话键、插件状态命名空间 | 配置/历史/记忆/浏览身份分别隔离；Worker 不等于恶意代码沙箱 |
| 并发 | 消息队列按会话串行；默认 Worker 再按账号整体串行 | 同会话串行，跨会话有界并行，共享状态和资源用事务/锁 |
| 私聊/群聊 | 有分层配置；插件集在账号档案上，Worker 遍历全部插件 | 在宿主分发前执行作用域路由、授权与工具筛选 |
| 角色体系 | 角色卡文本与 revision | 内置角色卡、世界书、上下文、记忆的完整运行链路 |
| 公用层 | 公用制品、本地 catalog 与账号引用 | 共享定义，不默认共享运行状态、聊天记录或记忆 |
| 跨实例管道 | 未实现完整管道 | 独立授权消息路由，带来源、目标、跳数、去重及环路控制 |

## 必须拆开的概念

1. 槽位/接入实例与 QQ 账号：槽位可重绑定，长期数据属于账号；重绑定时清除瞬态状态，不继承旧账号记忆。
2. 公用制品库与跨实例通信：前者分发定义，后者传递明确授权的数据。
3. 角色卡、世界书与经历记忆：分别表达稳定人格、设定知识、实际互动形成的信息。自动记忆不能直接改写人工角色设定。
4. 插件“已安装/被账号启用/在当前会话可用/已获授权”是不同状态。
5. 提供 Skill 入口不等于已有 Skill 运行机制；当前制品种类仍只有 plugin 和 role-card。

## 建议的第一阶段范围（待讨论确认）

先定义主程序、实例/账号、公用层、私有层、会话的关系和隔离契约，形成配置样例与验收条目。再决定 launch 实现与 Agent 引擎接入顺序。

最低验收：

- 多账号分别启动、停止、重连，不影响其他账号。
- 账号 A 的历史、记忆、插件状态不能通过正常接口被账号 B 读取。
- 两账号使用同一公用插件，运行状态分别保存。
- 同会话顺序稳定，其他会话不会因普通慢请求无限等待。
- 群聊禁用的能力不会被分发、展示给模型或通过工具间接调用。
- 跨实例通信默认关闭，显式路由开启后不产生循环回复。

以上是下一阶段建议，不表示用户已经确认全部行为。
