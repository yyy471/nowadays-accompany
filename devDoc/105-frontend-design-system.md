# 前端总体设计规范 v1.3.0：夏澄的日常手账

2026-10-27。适用于正式Electron前端逐页重写。共用规格见本文件，完整夜间差异见 [110 晚风电台深色标准](110-nightwave-ui-standard.md)。文档整理与对比度修正见111；夜间坐姿人物已正式采用，见 [112](112-night-character-adoption.md)。108/109仍规定当前生产首页范围。公共组件历史证据见106。

## 1. 目的与依据

本规范把已认可的「桌面玩具 × 二次元手账」转成可执行的字体、布局、控件和交互标准。后续页面共用同一套规则，角色配对可以是名册，模型配置可以是抽屉，不强迫所有页面套同一张卡片模板。

- [DESIGN.md](../DESIGN.md)：美术方向与全局原则。
- 本文件：尺寸、组件、状态、行为和验收的规范来源。
- [110 深色标准](110-nightwave-ui-standard.md)：nightwave的完整色板、组件状态、主题传播与插画规则；两主题共用本文件的尺寸/交互，不复制组件实现。
- [117 动效规范](117-frontend-motion-standard.md)：已认可的「书签与落款」，包含动作目录、时长、精细参数、连续操作、减少动效及实施状态；后续动效实现与本文件一起执行。
- [tokens.json](design/character-studio/tokens.json)：基础数值与引用关系的机器可读来源；使用项目自有格式，不宣称是现有构建器支持的标准。
- [公共 UI 文档](../desktop/renderer/src/ui/README.md)：组件入口与行为契约；本批已核对公共UI、草稿注册、确认和主题接入源码，不能据此推断所有业务页面已经审计。
- [103 实施方案](103-home-and-shell-rewrite-plan.md)、[104 验收清单](104-home-and-shell-rewrite-acceptance.md)：第一批实施范围与业务验收。

数值冲突时以本文件和 token 文件为准，早期原型中的近似值与根 DESIGN.md 的范围表述相应收紧。若两份正式规格发生冲突，应同时修正后再实现，不能由页面自行挑一个值。任何组件 API 名称、既有能力和路径仍须在实施前通过源码核实。

## 2. 美术规则

- 奶油桌面是底，纸白是操作面，深蓝负责结构与提交，手账红强调进入工作台，樱粉承担轻量选中与装饰。
- 立绘、水墨场景、便签和书脊下沿构成识别；水墨只出现在插画边缘，不用于输入框、弹窗正文和错误消息。
- 普通业务页以排版、细线和留白组织；只有独立编辑、预览或浮层才使用完整纸面容器。不给每段文字再包一张卡片。
- 每个主要视区通常一个高强调动作；保存与测试共存时，保存用深蓝，测试为次一级入口，位置和文案区分职责。
- 上述颜色描述为白昼语义示例；深色使用相同动作语义和110映射，不把“深蓝/纸白”等字面色强加给两主题。
- 所有必要信息始终可读。手写字、英文小标签、纸纹、姓名索引均为可删除的装饰，不承担状态和操作说明。
- 内置「白昼来信」浅色与「晚风电台」深色预置，沿用同一角色、构图与组件规格；夜间场景重绘为月光与暖灯。暗底#171D29、纸面#202836、文字#EEE5D8、次文字#ABB0BE、主入口#D4AA87配深色文字；完整值由tokens.json中的nightwave覆盖定义。强制颜色模式仍需保留形状和焦点。

## 3. 字体与排版

### 3.1 字体来源

| 角色 | 字体栈 | 使用范围 |
| --- | --- | --- |
| 功能字体 | Segoe UI Variable Text → Microsoft YaHei UI → Microsoft YaHei → Segoe UI → sans-serif | 中文界面、表单、按钮、菜单和数据 |
| 展示字体 | Segoe UI Variable Display → Segoe UI → Microsoft YaHei UI → Microsoft YaHei → sans-serif | 品牌与少量展示标题；中文保留功能字体的阅读感 |
| 等宽字体 | Cascadia Mono → Consolas → Microsoft YaHei UI → monospace | ID、版本、日志、代码与密钥输入 |

按实际字符和本机字体回退，不要求用户安装字体；第一批不下载网络字体。常规字重400，强调600，标题700。实施时检查 Windows 实际渲染，缺少中间字重时允许字体回退，不增加描边模拟粗体。

### 3.2 固定排版级别

以下均为 CSS 逻辑像素。正文默认14px，浏览器根字号不人为压缩；系统缩放按 Electron 正常机制处理。

| 名称 | 字号 / 行高 | 字重 | 场景 |
| --- | --- | --- | --- |
| hero | 44 / 54 | 700 | 主页叙事标题，单页最多一处；紧凑窗口可切page级别 |
| page | 32 / 40 | 700 | 业务页标题、窄窗口主页标题 |
| section | 20 / 28 | 600 | 名册、配置分区、弹窗标题 |
| subtitle | 16 / 24 | 600 | 抽屉标题、账号名称、分组标题 |
| body | 14 / 22 | 400 | 说明、输入内容、详情与错误正文 |
| control | 13 / 20 | 600 | 按钮、菜单、字段标签；表格常规单元用400 |
| caption | 12 / 18 | 400 | 提示、更新时间、状态标签 |

必要内容不低于12px；8–10px只允许纯装饰。中文默认字距0；英文装饰标签可用0.08em字距，不能加到表单正文。正文段落默认不超过约65个汉字一行。

单行昵称可以截断，但必须有可通过点击/键盘访问的完整资料入口，不能只靠title悬停。错误、关键操作名和必需字段标签不截断。路径与ID可独立横向滚动或断行，不撑宽整页；长文本不用全局word-break破坏普通阅读。

## 4. 色彩与语义

下表为白昼来信。完整晚风值、组合与状态见110；字面色值只属于各自预置，组件以语义命名。

| 用途 | 前景 / 背景或边界 | 约束 |
| --- | --- | --- |
| 桌面、纸面 | #F5F0E8、#FFFCF7 | 大面积背景 |
| 正文、辅助文字 | #30384D、#6D6574 | 辅助色不用于需要强强调的操作 |
| 提交、导航当前项 | #394158，纸白字；hover #272F44 | 默认实色按钮 |
| 工作台入口 | #914E5A，纸白字；hover #663643 | 角色主题强调；不是危险语义 |
| 轻量选中、装饰 | #F5E9EB、#D9B2BC | 使用墨色文字；樱粉不承载细小白字 |
| 装饰分隔线 | #DDCFD0 | 只分组，不单独表示可输入边界 |
| 可操作控件边界 | #97818C | 用于字段边框、未选开关等必要边界 |
| 成功 | #497063 / #E7F0E9 | 配合“已保存”等文字 |
| 提醒 | #805620 / #F5EBD9 | 配合明确原因和下一步 |
| 错误、危险 | #A33247 / #F8E7E9 | 不与手账红入口混用；写明具体动作 |
| 禁用 | #625A68 / #EAE2E2 | 明确填色与文字，不将整个控件设低透明度 |

设计验收目标：普通文字对实际背景至少4.5:1，必要控件边界与焦点至少3:1。需检查真实叠色、透明图片、hover和禁用组合；token颜色通过不等于整页通过。状态不能仅靠红绿区分。中性“未知”不冒充失败，“已开启”不等于已连接或可回复。

## 5. 尺度、布局和层级

### 5.1 间距与外观

间距仅从4、8、12、16、20、24、32、40、48、64px选择。图文间8，标签到字段8，字段到提示4，字段组间16，面内边距24，业务分区间32。插画位置允许少量专属偏移，不能作为普通组件新增尺寸的借口。

| 项目 | 标准 |
| --- | --- |
| 页面水平内边距 | 宽窗口32；紧凑窗口20；窄布局16 |
| 主按钮 / 单行字段 | 高44，按钮左右16–20，字段左右12 |
| 紧凑操作 | 可见高36；独立图标命中区域至少40×40；常规主操作维持44 |
| 文本域 | 最小高120，允许垂直伸展；长编辑另设明确滚动区域 |
| 圆角 | 按钮9；字段/弹窗/编辑面12；Dock24；头像圆形 |
| 描边 | 常规1；焦点2，间隔2；主按钮实色下沿3 |
| 图标 | 小16，常规20，强调24；同一场景保持同一线宽体系 |
| 头像 | 标签32，资料48，主页主身份72；失败占位保持同尺寸 |
| 纸面阴影 | 0 6px 18px rgba(48,56,77,.06)，仅必要独立面使用 |
| 浮层阴影 | 0 12px 32px rgba(48,56,77,.14)，不施加到所有区域 |

### 5.2 页面骨架

- 顶部基准高80；底部Dock基准高72，紧凑模式64；底部独立预留区域104，包含Dock和上下留白。尺寸由token提供，内容不延伸到Dock背后。
- 宽度≥1200：主页左右构图，右侧信息约占46%–50%，场景留白优先；角色不可盖住按钮。
- 宽度960–1199：缩减场景占宽与外侧留白，标题使用32/40px档位，保留功能文字。
- 首页不允许上下滚动，按剩余高度分配插画与文字；宽度<600改为单栏图文分区，短窗口采用紧凑双栏。优先保证账号和主入口完整可见，长签名限行；其他业务页继续独立滚动，菜单和弹窗仍可内部滚动。
- 首页标题在窄屏使用28/36px，在同时短窄的辅助回退布局使用22/30px；只调整叙事标题档位，不整体缩放页面与操作控件。
- 业务页复用顶部、导航、页面标题/说明/动作槽和内容滚动契约；内部按实际任务使用名册、抽屉或表单。
- 1024×720为正式小窗口检查；1440×900、1280×800为主检查；125%缩放需Electron原生检查；更窄尺寸为回退检查。断点按可用CSS空间计算。

### 5.3 浮层与窗口

语义层级：内容0、装饰1、壳10、菜单20；与现有共享Modal管理器对齐，弹窗从1000开始，每层递增10，嵌套确认基准1010。通知1020、提示1030仅为预留语义，新增这些组件前仍须遵守顶层模态隔离。组件使用语义层名，业务页不能手工插入弹窗层级。装饰层不拦截鼠标；modal开启后底层菜单/提示关闭，通知不可盖住确认按钮或接管焦点。

复用既有Modal、Portal和焦点管理，不用z-index数值代替真实模态隔离。窗口拖拽区域排除按钮和输入；不擅自切换无边框窗口，不重做托盘和关闭协议。

## 6. 公共控件与组件目录

“已有”只代表公共UI文档列出，并非本轮已验证源码API。“扩展”必须在公共UI层完成，页面不能自己创建重复基础控件。保留现有React技术与UI入口，不因设计升级引入另一套组件库。

| 类别 | 实现归属 | 规格与语义 |
| --- | --- | --- |
| Button / ConfirmButton / CancelButton | 已有公共UI，扩展主题 | 默认深蓝；工作台入口手账红；次要纸白描边；文字动作无下沿；危险显式danger |
| IconButton | 已有公共UI | 必有可读label；独立命中40；不能仅用无文字图标表示危险操作 |
| ControlButton | 已有公共UI | 账号选择、导航、折叠标题等场景；不得绕过普通Button手拼提交按钮 |
| Input / SearchInput / Textarea / Select / Checkbox / Field | 已有公共UI | Field关联标签/说明/错误；SearchInput必有label；占位符不代替标签 |
| Modal / useConfirm | 已有公共UI | 统一焦点、Esc、取消和异步确认；危险确认默认焦点取消，保存不重复确认 |
| Switch | 公共UI | 轨道44×26，整行命中≥44高；可访问名称、当前值、Space切换；写入中保留焦点并阻止重复；trailing可将轨道放右侧，当前首页不放业务开关 |
| DropdownMenu / Disclosure | 本批新增公共UI | 菜单负责键盘、关闭和边缘定位；折叠只隐藏、不卸载编辑内容 |
| PageDock / ThemeSwitcher / MoreMenu | 业务组合组件 | 使用公共控件组合；页面导航、昼夜外观和菜单语义分开，顶部不承担QQ账号切换 |
| BindingLedger / CapabilityDrawer | 后续业务组合 | 名册行最小56高；抽屉标题最小48高；展开收起、选中、未保存分别表达 |
| StatusLabel / AsyncState / InlineNotice | 优先核对并复用现有能力 | loading、空、错误、过期和就绪有统一文字与动作；只按缺口扩展 |
| Tooltip / Popover / 通知 | 先核对现有能力，按实际需要补充 | 非必要不新增；提示只补充信息，不能藏必需操作和错误 |
| AccountAvatar | 复用既有账号头像管线 | 来源、缓存、失败回退及身份解析继续遵循项目契约 |

### 6.1 按钮与输入

- 按钮文案以动词开头，例如“保存配置”“进入工作台”“继续编辑”。加载预留图标槽并保留原有宽度下限；加载文案不长于原动作，不借加载状态引入新的长名称。反馈留在相关动作附近，不把整个页面按钮一起禁用。
- hover按各预置增强对比，深色允许变亮；active下移1px并收短实色下沿，不改变占位尺寸。文字按钮通过下划线或底色提供反馈，不添加整套立体外框。
- 输入内容用body14/22，标签control13/20；必填标记和错误文字明确可见，错误不清空输入。只读可选中复制，禁用不接受编辑，两者不同。
- 第一批Select优先保留已有公共封装及原生键盘行为。只有搜索长列表、富内容选择等确实需要时才扩展自定义浮层；不为外观另造所有选择器。
- 文件选择使用现有公共封装调用系统选择；密钥默认遮盖，复制/显示必须显式操作，不在提示中打印真实值。

### 6.2 导航、菜单与弹窗

- Dock使用导航语义，当前页以aria-current或等价语义识别；每项显示图标和文字。顶部昼夜预置采用有明确名称的按钮组与aria-pressed，不承担QQ账号切换或页面导航。
- 全部菜单行最小40高，含名称、当前项、必要说明；弹出后视口内定位，长列表内部滚动。Esc关闭并返回触发点，键盘完整可达；箭头键行为按最终采用的menu/listbox模式成套实现。
- Modal：确认宽约420–480，标准编辑约640，复杂内容约880；最终宽不超过视口减32。头尾和正文职责清楚，正文内部可滚动；窄窗口按钮可换行，不覆盖正文。
- 路由跳转、账号切换、设置关闭、返回历史与退出均经过原有草稿准入。任何视觉组件不得私自自动保存、丢弃或重复询问。
- 普通Modal继承React范围的主题；useConfirm在调用请求时记录调用hook所在范围的主题，队列逐项重新聚焦取消。集中确认回调由其创建位置决定主题，正式App迁移需同步安排Provider范围，不能只修改页面DOM。
- App控制器使用上下文式UiThemeProvider；data-ui-palette只提供token值，UiThemeScope提供局部控件外观。旧内容使用空主题上下文并保持在新控件DOM范围之外，禁止用全局CSS覆盖完成迁移。

### 6.3 列表、编辑区与消息

- 列表用对齐、行距与细线体现层次；行选中用selection语义底色加明确标记。行内按钮不是整行点击的附带触发，避免嵌套按钮。
- 长数据表保留表头/单元格关联，数值右对齐，ID等宽；确有必要时在表内横向滚动，不让整个应用横向滚动。
- 消息优先放在相关字段或分区旁；完成反馈可用轻量通知，错误、不可逆结果和必需步骤不能只短暂闪现。异步状态使用合适的live区域且避免重复播报。
- 独立编辑面只在需要边界时使用surface；同一面不再重复叠卡片。保存区靠近编辑对象，未保存状态可见。

## 7. 通用状态契约

| 状态 | 外观 | 行为 |
| --- | --- | --- |
| default | 语义配色和正常边界 | 有明确名称与操作对象 |
| hover | 轻量底色/边界变化 | 不能成为唯一可发现方式 |
| focus-visible | focus语义色2px外环，2px间隔 | 立即出现；不可被loading或选中样式覆盖 |
| pressed | 1px位移、下沿收短 | 不触发布局跳动 |
| selected / expanded | 当前项标记 / selection语义底面 | 二者不混用；同步aria-current/selected/expanded等适用语义 |
| disabled | 明确禁用背景与文字 | 原生禁用或正确aria-disabled及事件阻止；需要时给可达说明 |
| loading / saving | 就地进度，保持尺寸 | 只限制相关动作；保留正在操作的目标和焦点；aria-busy按范围设置 |
| invalid | 错误边界与具体错误 | 与字段关联；保留用户输入；提交后聚焦首个需要处理的位置 |
| empty | 说明确实无数据及下一步 | 只有成功查询到空结果才能显示 |
| error / stale | 原因、重试、必要的更新时间 | 缓存可保留但明确过期；失败不变为空或离线 |

focus、invalid、selected、busy可同时存在，不能用单一优先级把焦点或错误覆盖掉。请求结果必须归属发起时的账号/对象；视觉上的当前选中不等于异步动作可以改绑对象。

## 8. 动效与素材

完整动作标准见[117 前端动效规范](117-frontend-motion-standard.md)。已认可的书签端片、逐笔落款、导航书签、分层阅读和来源浮层已在独立HTML样板验证，正式公共组件待接入；日常基础反馈与昼夜天气过渡的已实现范围分别记录，不能将规范登记视作整应用迁移完成。

- 即时反馈120ms，控件变化160ms，抽屉220ms，页面进入280ms；统一缓动cubic-bezier(0.2,0,0,1)。异步等待不能为了凑动效强制延迟。
- 浮层退出160ms；书签/浮层可采用token登记的surfaceEase。主要正文推荐4px小幅入场，标题/正文/注脚分组延迟24ms、累计不超过72ms；缩短各组时长，整次仍在280ms结束。主入口书签探出、导航末端回弹、保存逐笔勾选与来源浮层的精细位移/比例见117与`component.motion.*`，两主题共用。
- 所有页面动画接在已有草稿准入之后，快速反向取最新目标、从当前绘制位置衔接。折叠保留编辑器；正常跨页导航沿用既有生命周期。焦点、Esc和模态隔离不等待装饰入场，退出期间保持顶层隔离并防重复关闭。
- 显式昼夜主题切换采用「晚风翻夜 / 晨光揭晓」：柔边换景400ms、叶片/余光总长550ms，由themeTransition组件token提供。仅一次性全屏换景，页面与控件保持原位；旧页绘制快照退开，实时新页保持可操作。减少动效/强制颜色时直接切换，快速反向选择立即收束到最新主题。实施与实际证据见[114](114-theme-weather-transition-execution.md)。
- 页面只做轻微淡入/位移，主要内容位移不超过8px；立绘/场景跟随≤4px，只作用装饰，关闭后布局不变。避免持续呼吸、粒子、闪光与循环角色位移。
- 系统减少动态效果或应用关闭动画时，取消装饰跟随和入场位移；焦点/加载/展开状态仍立即可辨。禁止transition:all。
- 插画保持原比例，透明边缘不改成矩形；预留宽高避免加载跳动。失败使用平静的纸面占位，不触发重试风暴。
- 图标优先复用现有图标入口；同一组不混emoji、彩色贴图和不同线宽。含义已由邻近文字表达的图标对辅助技术隐藏，独立操作必须命名。
- 主页主题与真实业务身份明确分离；没有资源映射时不暗示主题角色正在处理所有会话。

## 9. 系统能力与自定义外观的边界

按钮、字段、开关、导航、菜单和弹窗是渲染进程内的公共UI，可定制为本主题，但继续使用真实交互元素和公共行为。系统文件选择、操作系统窗口能力、托盘、剪贴板权限与既有桌面桥沿用现有机制。

不能为视觉相似而用div冒充输入框、手绘系统文件窗口或复制一套浏览器confirm。拖拽、复制、右键菜单等额外能力只有在任务需要且现有契约支持时加入，不为“酷炫”扩大功能范围。

## 10. Token落地与变更规则

采用primitive → semantic → component三层。token文件中@开头的字符串表示引用，例如component.button.background → semantic.color.commit → primitive.color.navy。基础数值只在primitive定义；业务CSS消费用途语义或组件变量，不引用“粉色第几号”决定动作含义。

现已由 `desktop/scripts/generate-character-theme.mjs` 从token生成 `ui/character-tokens.css`，主题外观使用语义及组件变量，并在开发样板、正式主页和菜单中生效。token可由data-ui-palette单独提供，控件外观通过UiThemeScope显式启用。生成物不可手工维护，构建及测试负责检查同步、引用和三层关系。

ThemePresetProvider管理daylight/nightwave本机外观偏好，不触发业务写入。UiThemeScope和Portal携带data-ui-preset，确认队列保存调用时的预置。夜间覆盖必须经过与基准相同的格式/引用/循环/值安全检查，禁止未知token路径。旧页面仅桥接原有调色变量，保持布局和控件尺寸。

总体规范v1.3.0、动效规范117 v1.0与token v1.2.0配套。token新增已认可动效的参数登记，原有变量与两主题颜色、字体/尺寸不变；新增变量生成不等于组件已经消费。v1.2.0文档阶段的夜间便签修正保留为历史。后续变更同时维护105、110、117、token和实际组件。

页面CSS只管理布局与插画位置，公共控件外观在公共UI维护。对未迁移旧页使用范围隔离；新主题变体不改变旧页默认样式。不得在每页复制token和控件规则。

新增token/组件必须有实际用途、状态和行为；近似尺寸先复用现有级别。新增变体同步本文件、token和组件样板；改变颜色含义、尺寸级别或交互契约需记录版本和受影响页面。

## 11. 实施前的组件样板与验收

主页编码前，先在实际React公共UI上制作一个开发专用组件样板入口，使用隔离数据，不加入正式业务导航、不复制第二套组件。展示：

1. 中英文、数字、长昵称、长路径的完整字体层级。
2. 四类按钮及default、hover、focus、pressed、disabled、loading、danger。
3. 输入、搜索、选择、文本域、勾选、开关的标签、帮助、错误、只读和禁用。
4. 账号切换、Dock、长菜单、Modal、嵌套确认、焦点返回。
5. 空、慢、失败、旧数据、成功与未保存状态。
6. 立绘与局部场景的正常、失败、紧凑布局与关闭动效。

这一小步用于验证规范能落到实际控件，而不是重新选择美术风格。样板已完成，另补齐密钥、数字、文件、单选、折叠保留与确认队列；正式主页及菜单也已组装。以真实Windows字体和Electron运行检查为依据，浏览器截图作为辅助。当前主屏150%实测与另一个进程125%渲染均通过；后者不是OS设置125%的验收。

验收包括：类型与既有UI契约不退化；必要对比度；完整键盘链路；弹窗焦点；多尺寸与原生缩放；无图片遮挡、按钮跳动和全局样式污染。当前两套主题的实际结果及边界见109，初始业务保护沿用104，首页范围按108用户修订执行。
