# 动态页 v2 迁移

## 实施范围

依照用户提供的 `nowadays-feed-v2-demo` 原型，将「动态」加入 Dock 的「更多」。页面使用书页时间线、角色／类型／时间筛选、待执行安排、长意图展开、状态详情、昼夜主题与减少动效。720×540 窗口中，待执行安排移到时间线上方。

时间线按角色读取自主安排、活动、任务、记忆批次和活动状态，关联标识按角色隔离。动态页请求活动分页时，后端通过 `sharedMessageId` 关联角色主窗口的原文并随页返回。打开对话后定位该消息；等待回复的活动打开记录的活动窗口。返回动态保留筛选与滚动位置，并恢复操作焦点。时间线和安排各自读取并提供重试，后台刷新失败时保留已有内容。

## 系统适配与边界

- 自主安排、活动及记忆批次的列表接口增加 `offset`，前端逐页读取并按标识去重。分页期间发生记录变化时不是同一数据库快照，后续刷新会重新收敛。
- 「新」使用本机上次成功进入动态页的时间，首次按最近一天计算。此标记是本机浏览状态。
- 角色停止事件来自当前活动状态的确认时间。恢复后的历史事件没有持久化来源。活动记录只保留其当前 `sharedMessageId`。
- 待执行列表包含已到期但仍处于 `pending` 的安排，以便显示停止角色保留的安排。立绘取系统实际服饰，没有立绘时显示姓名首字。
- 详情复用系统 `Modal` 的焦点隔离和恢复，桌面端置于右侧，窄窗口从底部显示。对话入口复用现有页面及历史分页定位。

## 实现方自验

- 渲染器 `npm run check` 与 `npm run build` 通过。桌面 `npx -y node@24 --test tests/*.test.cjs` 通过。
- 后端分页回归与自主安排、记忆查询相关测试通过。`apps/desktop/tests/feed-integration.test.ts` 使用离线模型和隔离后端验证真实主动分享在默认窗口的读取、时间线读取失败时安排的独立读取，以及相同消息编号的跨角色隔离。
- 本机浏览器使用测试接口数据检查 1440×840、1280×800、720×540 的昼夜布局，走查筛选、空态、读取失败与恢复、详情、Escape 焦点恢复、长意图展开、分享跳转和返回动态。原型通过源码与样式核对，本机浏览器策略阻止了直接打开其 `file:` 地址。
- 隔离后端通过离线模型产生主动分享，随后追加 205 条测试消息。浏览器经真实接口打开该分享，能够跨对话分页定位原文并返回动态。
- 隔离 Electron 与离线后端自验了「更多 → 动态」、自主分享与待执行安排读取、分享跳转对话及返回、昼夜主题切换。测试数据独立于用户实际数据。

## 2026-11-20 复核验证

本轮在当前工作树重跑测试，并用隔离 Electron 接口样例复现以下行为。复核结论为待修复。

| 优先级 | 触发方式与观察 | 修复后的验收条件 |
| --- | --- | --- |
| P1 | 两个角色分别有一条正常安排和一条分享。首次打开时令分享原文返回 404，整个时间线显示读取失败，正常安排也不可见。原文恢复后重试才显示两条。 | 原文缺失时局部提示，其他角色及事件仍可浏览。 |
| P2 | 打开待执行安排的详情，把同一安排更新为已完成并触发刷新。列表已经显示「已执行」，「接下来」已移除该项，打开的详情仍显示「待执行」。 | 详情按当前记录反映刷新后的状态。 |
| P2 | 单角色接口样例含 501 条安排、501 条活动、201 批记忆和 250 条分享。两次读取均完整跨页，每次合计发起 263 次接口请求，其中 250 次重新读取分享原文。可见页面每 15 秒刷新。 | 无变化的历史分享避免重复逐条请求，新增或更新的记录仍能出现。 |

桌面测试 161 项、相关后端与动态集成测试 22 项、前后端类型检查、样式门禁与构建通过。Electron 复验了 1440×840、1280×800 的双栏和 720×540 的上方安排条，三个尺寸均无页面横向溢出。以上故障和请求计数来自隔离样例，未测用户库的刷新耗时。

原型源码另有筛选淡出淡入、长意图高度动画和分享跳转的共享元素过渡，当前实现直接切换。原型与成品尚未逐帧比对，独立验收及用户实际数据走查仍待执行。

## 2026-11-20 修复与独立复验

两位 Terra 6.1（xhigh）分别修复数据读取和桌面交互，第三位同配置的复核者使用独立样例检查合并后的实现。

- 活动分页可随页返回主窗口的分享原文。原文缺失时保留该条活动、显示局部提示并禁用打开原文。SQLite 回归覆盖不同窗口、同编号不同角色、原文修改、删除与恢复。
- 复用上轮单角色规模（501 条安排、501 条活动、201 批记忆、250 条分享），连续两轮读取均为 13 次接口请求，原先各为 263 次。每轮仍会读取各页和其中的正文，结果未测量用户库的实际刷新耗时。
- 详情跟随最近一次成功读取的记录。隔离 Electron 中，让时间线返回 503，单独更新安排栏，打开的详情随即显示「已执行」。移除记录后详情关闭。独立复核另行验证了三种窗口尺寸与 Escape 焦点恢复。
- 隔离真实后端由离线模型生成自主分享并追加 205 条消息。Electron 从动态跳到原文，定位高亮结束后原文仍在可见区且保有键盘焦点。返回时焦点恢复到原动态的操作按钮。
- 已补齐筛选淡出淡入、长意图展开与收起的高度动画，以及分享卡与对话气泡的往返过渡。首次打开对话时，若目标消息仍在分页读取，先用分享正文绘制临时过渡目标。独立复核在首轮候选发现冷启动时缺少目标，修正后重测了冷启动和跨角色路径。最终候选 `index--RirFhm8.js` 的冷启动去程捕获到 568×119 的源卡与约 622×41 的可见目标，返回后焦点回到源按钮。减少动效模式下即时切换。

**结论**　本次列出的三项缺陷和三处动效差异通过独立离线复验。复核者分别跑了 Electron、双角色接口样例与 SQLite/HTTP 回归；主进程另跑桌面测试 161 项、相关后端及集成测试 24 项、渲染器检查和构建。正常及减少动效两种模式均通过真实接口的 205 条后续消息定位。用户实际数据库的性能及与原型的逐帧视觉对照不在本轮证据范围内。

提交前补验：安排详情打开期间，若刷新使「接下来」中的触发按钮消失，关闭详情后焦点回到动态标题。独立复核者以最终构建 `index-PaU3KO7R.js` 重跑 Electron 验证，原触发按钮仍存在时的焦点恢复及此前复验场景也通过。
