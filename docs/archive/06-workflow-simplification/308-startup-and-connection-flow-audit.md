# 从零启动、连接配置与页面体验评审指南

> **更新日期**：2026-11-16 · **适用对象**：首次从零接触本项目的评审人员  
> **目标**：提供开箱启动命令、各类外部服务连接说明与基础使用路径，便于从零试用系统并独立提出页面操作与交互优化建议。

## 一、怎么把项目跑起来（从零开箱）

环境要求：**Windows + Node.js 24+**（工作区如尚未安装依赖，需分别在 `backend`、`apps/desktop/renderer`、`desktop/desk-preview` 运行一次 `npm ci`；本机如已安装过依赖可直接按下面命令启动）。

### 方式 A：单条命令启动（推荐，桌面自动拉起内置后端）

在 PowerShell 执行：

```powershell
Set-Location D:\app\nowadays\accompany\desktop\desk-preview
# 可选：指定一个全新的空目录从零体验（不设则默认使用 apps/backend/.nowadays-desktop）
$env:NOWADAYS_APP_ROOT = "D:\app\nowadays\accompany\.nowadays-review"
npm start
```

> **提示**：窗口右上角点 `×` 只是最小化到系统托盘。如果要彻底退出或切换数据目录重启，请**右键系统托盘图标 ->「退出 Nowadays」**，否则后台进程仍在占用数据目录。

### 方式 B：前后端分两个窗口起（需要看后端日志时用）

- **窗口 1（先起后端）**：
  ```powershell
  Set-Location D:\app\nowadays\accompany\apps\backend
  npm run dev -- --app-root ..\.nowadays-review --port 3210
  ```
- **窗口 2（再起桌面端）**：
  ```powershell
  Set-Location D:\app\nowadays\accompany\desktop\desk-preview
  $env:NOWADAYS_BACKEND_URL = "http://127.0.0.1:3210"
  npm start
  ```

## 二、模型与各类外部服务怎么连接（页面填写速查）

进入界面后，点击左下角底部栏的 **「全部菜单」->「设置」**，可以看到左侧的分类。首次体验只需要至少配通「**文本对话模型**」即可聊天，语音 / 生图 / 扩展按需选配。

| 类型 | 设置入口 | 接口协议 / 常见地址与填写说明 |
| --- | --- | --- |
| **对话 / 记忆模型（必配）** | `设置 -> 模型 -> 模型` | 支持 4 种协议：<br>· **OpenAI Chat**：如 `https://api.openai.com/v1` 或兼容代理根地址（如 `http://127.0.0.1:8000`）<br>· **OpenAI Responses**：填响应接口根地址与密钥<br>· **Anthropic Messages**：如 Claude / DeepSeek 兼容接口地址与密钥<br>· **Google Gemini / Vertex AI**：选择后会自动填入 Vertex Express 默认地址；改用 AI Studio 请填 `https://generativelanguage.googleapis.com/v1beta`（Vertex Express API Key 无法自动拉模型列表，需手填模型名后点「测试连接」）<br>填完可点「读取模型列表」-> 选/填模型名 ->「测试连接」->「保存模型服务」。 |
| **语音 TTS（可选）** | `设置 -> 模型 -> 语音` | · **统一语音协议（`nowadays-tts-v1`）**：本机 WSL 桥接常用 `http://127.0.0.1:9890`（无需密钥），填地址后可点「测试连接」查看引擎与预置音色。<br>· **旧 IndexTTS 协议**：无连接测试按钮，保存后去角色语音面板通过「试听」验证。 |
| **生图 ComfyUI（可选）** | `设置 -> 模型 -> 生图` | 默认填 ComfyUI 地址如 `http://127.0.0.1:8188`（令牌选填，无反代认证可留空），点「读取模型列表」或「测试连接」检查模型与工作流节点，保存后在角色侧选用。 |
| **MCP / Skill（可选）** | `设置 -> MCP` / `设置 -> Skill` | · **MCP**：填本地 `stdio` 启动命令、参数（每行一个）和 JSON 环境变量。<br>· **Skill**：填本地技能文件夹目录（需含 `<技能名>/SKILL.md`；仓库 [apps/backend/examples/skills](../../../apps/backend/examples/skills) 下有现成样例目录）。 |

## 三、基础使用路径（从空库到对话）

按以下流程可在桌面端完成首次配置并开始使用，也可自由探索其余页面交互：

1. **创建第一个角色**：
   - 应用打开默认显示「桌面（主页）」，当没有任何角色时首页出现 **「创建角色」**。
   - 填写显示名与人设并提交后，会进入 **「角色配置 -> 设定」**。新建角色默认处于「已停止」状态。
2. **添加外部服务**：
   - 通过底栏左下角 **「全部菜单 -> 设置」**（或页面内跳转按钮），在 **「模型」** 分类下完成文本模型，以及可选的语音、生图服务保存；如需 MCP / Skill，在左侧对应分类添加。
3. **为角色绑定模型与配置**：
   - 返回 **「角色配置 -> 模型」**，在「对话」「记忆整理」「生图」「语音」各栏完成选择并保存；如需外观或扩展，可在对应分页补充配置。
4. **启用角色并进入对话**：
   - 启用角色活动后（如在「角色配置 -> 模型 -> 对话」点开始对话、在「设置 -> 角色状态」点恢复活动，或直接切到底部 **「对话」** 页按提示恢复），即可发送消息对话。
5. **变更已保存配置**：
   - 在角色启用期间，可按需回到设置或角色配置修改模型地址、密钥、服务启停或人设参数。

## 四、首次个人用户实机体验记录（2026-11-16）

### 体验范围与结果

- 使用独立空数据目录 `.nowadays-review`，从首页创建角色「千叶诗织」；姓名与人设为本次测试自拟。用指定素材文件夹导入 3 套服饰、38 张对话差分；其中 1 套没有对话差分，页面有提示。角色配置页显示了立绘。
- 使用用户提供的文本连接资料，选择 Anthropic Messages 协议、手填 `deepseek-v4-flash` 后测试通过，并绑定到角色。两轮真实对话均收到连贯回复：问候后角色说起散步和画稿；追问画什么时，她回答正在画家附近的小街景。
- 本机语音服务连接成功，识别到 CosyVoice、IndexTTS 和 4 个预置音色。选择「秧秧」后生成试听，页面反馈「已按当前表单生成试听，正在播放」，并保存了声音配置。**未能独立确认扬声器实际出声或音质**。
- 本机 ComfyUI 连接测试通过，探测到 2 个模型。选用 MOSS 模型，手写简短外貌描述并使用页面默认场景描述，成功生成并显示 1024×1024 测试样图；角色侧生图配置已保存。该样图偏写实，和填写的日系插画风以及原角色立绘有差异；仅测一张，不能据此判断整体质量。测试样图不进入过场图历史；本次未验证对话中过场图生成。
- 完成配置后角色恢复活动；对话与生成内容均为本次测试数据。未测试 MCP、Skill、多角色、重启后持久性或长时间使用。

### 实际发现的问题

1. **「新建角色」窗口反复自行弹出。** 首次创建角色后，表单清空却仍停留在新建窗口；关闭后，从角色状态返回外观、从设置返回模型、素材导入完成、保存声音、保存生图配置和恢复角色活动后，又多次出现同一个空白新建窗口。需反复关闭，遮住原页面和成功反馈，容易误以为操作没有成功或需要再创建一次。建议创建成功后明确展示结果及下一步，并检查后续操作为何重新打开窗口。
2. **对话消息在实时页面一度错序。** 第一轮完整回复显示后发送第二条消息，页面临时把第二条用户消息放在第一轮角色回复之前，看起来像连续发送了两条问题。离开对话再返回后顺序恢复正常。实际观察到的是实时显示错序，不能推断历史数据也错序。
3. **角色立绘与状态初次显示不一致。** 刚进入对话时画面先显示首页主题人物，并提示「当前未选择服饰」；之后才出现新角色立绘，再提示所选服饰没有对话表情。素材实际上已导入，初次等待期间用户难以判断是否配置失败。建议在角色素材加载中给出清楚的过渡与当前选择，而非短暂展示另一人物。
4. **逐句对话的继续方式不够醒目。** 回复先显示一个动作，之后必须反复点击对话区域或按 Enter 才能看到后续句子；提示文字小且颜色浅，输入框在演出期间不显示。首次使用时容易以为回复只有一句或正在卡住；较长回复需要多次重复操作。建议清楚提示还有后续内容，并考虑容易发现的自动播放或一次展开方式。
5. **模型列表失败后的提示不足以让普通用户继续。** 使用提供的 DeepSeek 地址和 Anthropic Messages 协议时，「读取模型列表」报 HTTP 404；手动填写 `deepseek-v4-flash` 后连接测试通过。页面虽提示可手填，却没有告诉用户从哪里找到可用名称或如何判断协议。连接成功后保存，重新进入服务详情又显示「最近测试：尚未测试」，与刚才的成功反馈容易形成疑惑。
6. **初始等待和状态反馈容易误解。** 新建后配置页短暂显示「状态未获取」，外观导入按钮不可用；去角色状态页等待后显示「已停止」，返回才可操作。状态尚未加载时页面没有清楚说明正在等待、何时可操作。首次生图与语音生成也只有「正在出图／正在合成」，缺少预计等待时间、进度或明确的可取消方式。

### 流程与页面体验建议

- **从创建到聊天缺少一条连贯的新手路线。** 实际需要新建角色、关闭窗口、进入角色模型、跳到全局设置添加服务、测试和保存、返回并关闭再次弹出的窗口、选择模型、再保存并恢复活动。虽然页面间有跳转按钮，但首次使用仍需理解「服务」和「角色使用的模型」两层选择；建议在创建成功后集中展示必要步骤及完成状态，选配外观、语音和生图可后补。
- **素材导入对普通用户偏技术化。** 页面要求理解 `standees`、`expressions`、`outfits` 文件夹以及「差分、归并、锚点」；预览虽能列出缺项和自动归并，但确认导入在较长内容下方，需要同时理解内外两层滚动。默认选中的是没有对话表情的第一套，而另外两套各有 19 张；可考虑明确推荐带表情的一套，并用通俗名称解释图片用途、缺项影响和可操作的下一步。
- **配置页内容和重复动作偏多。** 文本、语音、生图均需先建全局服务，再到角色配置选择和保存；语音还要从参考音频切换到预置音色、选择具体声音、试听、保存，保存会暂停角色并需继续活动。页面中出现「后端」「WSL」「协议」「工作流」「锚点」「CFG」等术语，首次接触缺少面向使用目的的解释。建议提供普通用户的默认路径，把高级选项收起，同时保留现有细项。
- **部分重要按钮和反馈容易落在首屏外。** 模型、语音、生图服务表单以及生图结果都需要向下滚动才能找到保存按钮或完整图片；固定底栏附近的按钮一度只露出一部分。建议让保存和下一步始终可见，并明确「测试成功」与「已保存」是两件事。
- **术语与信息展示可更友好。** 角色状态页出现 `ready`，已保存语音摘要显示音色内部编号而非选中的「秧秧」；生图服务密钥状态显示 `missing`，即使该本机连接无需令牌，也容易让人误认为出错。建议展示中文状态与可理解的名称，并明确选填项未填不影响使用。

### 启动指南补充观察

本次按指定目录运行 `npm start` 后成功打开应用。首次在受限执行环境内启动时构建遇到权限错误，在允许访问后启动成功，不能直接归因于产品本身。此前按指南尝试在 `desktop/desk-preview` 执行 `npm ci`，因该目录没有 `package-lock.json` 失败；这会阻碍真正缺依赖的首次使用者，建议核对指南中的依赖安装步骤。指南提供了本机服务地址，但没有说明服务未启动时普通用户如何启动它们或如何判断准备完成。
